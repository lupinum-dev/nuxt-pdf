# Product

## Register

product

## Users

Nuxt developers evaluating or adopting Nuxt PDF. They need to understand the authoring model quickly, inspect realistic documents, and verify development preview and production delivery without learning repository internals.

## Product Purpose

Prove the complete Nuxt PDF workflow through a small gallery of production-real document genres: Vue SFC authoring, typed data, local resources, pagination, development preview, and a production Nitro response. Success means a developer can map any showcased technique directly to a fresh application and render their first document within ten minutes.

## Brand Personality

Precise, calm, and trustworthy. The playground should feel like a production developer tool with editorial restraint, not a marketing microsite or a component showcase.

## Anti-references

Avoid the untouched Nuxt starter, generic dashboard cards, decorative gradients, novelty motion, oversized marketing headlines, and controls whose styling competes with the document itself.

## Design Principles

- Use only consumer-supported authoring paths in every example.
- Let one anchor document prove both preview and Nitro delivery paths.
- Explain each technique through concrete source and data, not feature claims.
- Keep controls familiar and make every action's result explicit.
- Use one quiet visual language so the generated PDF remains the focal artifact.
- Show only capabilities that ship in the current external alpha.

## Accessibility & Inclusion

Meet WCAG 2.2 AA for the playground interface. Preserve keyboard focus, semantic landmarks, sufficient contrast, readable text at browser zoom, structural mobile behavior, and reduced-motion preferences.
