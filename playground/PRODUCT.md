# Product

## Register

product

## Users

Nuxt developers evaluating or adopting Nuxt PDF. They need to understand the authoring model quickly, inspect a realistic invoice, and verify both development preview and production download paths without learning the implementation.

## Product Purpose

Prove the complete Nuxt PDF workflow in one credible example: Vue SFC authoring, typed data, local resources, pagination, development preview, and a production Nitro response. Success means a developer can map the playground directly to a fresh application and render their first document within ten minutes.

## Brand Personality

Precise, calm, and trustworthy. The playground should feel like a production developer tool with editorial restraint, not a marketing microsite or a component showcase.

## Anti-references

Avoid the untouched Nuxt starter, generic dashboard cards, decorative gradients, novelty motion, oversized marketing headlines, and controls whose styling competes with the document itself.

## Design Principles

- Put the working document and its two real delivery paths first.
- Explain the system through concrete invoice data, not feature claims.
- Keep controls familiar and make every action's result explicit.
- Use one quiet visual language so the generated PDF remains the focal artifact.
- Show only capabilities that ship in `0.2.0`.

## Accessibility & Inclusion

Meet WCAG 2.2 AA for the playground interface. Preserve keyboard focus, semantic landmarks, sufficient contrast, readable text at browser zoom, structural mobile behavior, and reduced-motion preferences.
