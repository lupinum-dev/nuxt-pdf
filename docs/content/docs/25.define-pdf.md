Each `pdfs/*.vue` template calls `definePdf` exactly once. It is a compile-time
macro (like `defineProps`); it declares render metadata and development-only
preview data and returns nothing.

```ts
definePdf<Props>({
  title: props => `Report ${props.id}`,
  filename: props => `report-${props.id}.pdf`,
  language: 'en-GB',
  maxPasses: 5,
  sampleData: { id: 'sample' },
  scenarios: {
    long: { id: 'long-report' },
  },
})
```

## Options

| Option | Type | Default | Description |
| ------ | ---- | ------- | ----------- |
| `title` | `string \| (props) => string` | None | Document title. A static string or a function of props. |
| `filename` | `string \| (props) => string` | None | Download filename, sanitized before use in `content-disposition`. |
| `language` | `string` | None | Document language tag (for example `"en-US"`), written as the `/Lang` entry of the document catalog. It also picks the hyphenation patterns that the style key `hyphens: 'auto'` uses. |
| `maxPasses` | `number` | `5` | Maximum layout passes before the render fails with `PDF_LIMIT_EXCEEDED` ("Page numbers did not stabilize"). A positive integer. |
| `sampleData` | `Props` | None | Props used for the default development preview. A template that declares no props previews without it. |
| `scenarios` | `Record<string, Props>` | None | Named prop sets. Each set becomes a preview tab and a `?scenario=` query. |

The `Props` type parameter ties `title`, `filename`, `sampleData`, and each
`scenario` to the SFC's own props, so a mismatch is a type error.

::info{icon="lucide:info"}
A document renders in one layout pass unless it uses `PdfPageRef`, which
normally settles in two passes. See [Primitives]($docs.primitives).
::

## Metadata resolution

`title` and `filename` functions receive the render props and must return a
string synchronously. They are resolved at render time.

Set `title` and `language` in one place: in `definePdf` or on `PdfDocument`. A
template that sets one of them in both places fails with `PDF_TREE_INVALID`:

```text
The document title is set twice: in definePdf({ title }) and as "title" on <PdfDocument>. Set it in one place.
```

Prefer `definePdf`: server code can then read the value before the render with
`resolveMetadata(props)`, such as for an email subject. Set it on
`PdfDocument` when only the template has the data it needs.

`resolveMetadata(props)` on the generated template handle returns the
`definePdf` values only, without mounting the component: the evaluated `title`
and `filename` and the `language`. A title or language set on `PdfDocument`
is not in it; `result.metadata` of a render has it. Whenever `definePdf` sets a
value, `resolveMetadata` and `result.metadata` give the same value. `filename`
controls the default response filename; it is not a `PdfDocument` prop.

## Preview data is development-only

`sampleData` and `scenarios` are used only by the development preview. They are
never exposed by the public `PdfTemplate` handle.

Production compilation keeps only `title`, `filename`, `language`, and
`maxPasses`. Preview expressions and routes are absent from the Nitro server
output. Keep preview data representative and disposable. Do not use it as
production runtime state or a place for secrets.

`definePdf()` is module-scoped, like Vue's other hoisted compiler macros. Its
values may be inline or imported from another module, but they cannot reference
a variable declared locally in `<script setup>`; that fails compilation instead
of producing a development-only `ReferenceError`. Keep imported preview-data
modules free of side effects. Production removes an unused import only when
evaluating that module has no required behavior.

## Scenarios in the preview

```ts
definePdf<Props>({
  sampleData: { id: 'sample' },
  scenarios: {
    long: { id: 'long-report' },
    empty: { id: 'no-sections' },
  },
})
```

The `long` scenario is available at `/_pdf/report?scenario=long`. An unknown
scenario name returns a 404 listing the available names.
