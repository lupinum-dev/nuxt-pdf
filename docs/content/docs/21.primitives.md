Every primitive is an auto-registered global component. The tables below are
drawn from the shipped prop types. `style` values use Nuxt PDF's framework-owned
`PdfStyle` contract, not the wider upstream stylesheet types (see
[Styling and layout]($docs.styling-and-layout)). A primitive with a `style` prop
also takes `class` and `:class` with the classes of the file's `<style>` block
(see [Styles]($docs.styles)).

The same surface is enforced after Vue mounts the tree. Each primitive has a
closed runtime prop allowlist; unknown props, DOM/event attributes, and props
used on the wrong primitive fail with `PDF_TREE_INVALID` rather than passing
through or silently doing nothing.

Leaf primitives hold no content: `PdfImage`, the SVG shapes (`PdfPath`,
`PdfRect`, `PdfCircle`, `PdfEllipse`, `PdfLine`, `PdfPolyline`, `PdfPolygon`),
`PdfStop`, the page tokens (`PdfPageNumber`, `PdfPageCount`, `PdfPageRef`),
`PdfAttachment`, and `PdfFacturX`. Text or an element inside one of them fails
with `PDF_TREE_INVALID`, for example `<PdfImage> cannot contain text.` Remove
the content, or put it next to the element. Whitespace and comments are not
content.

## Shared base props

`PdfPage`, `PdfView`, page-flow `PdfText`, `PdfImage`, `PdfLink`, and `PdfNote`
share these:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `id` | `string` | None | Makes the node a named destination for `#id` links and `PdfPageRef`. |
| `fixed` | `boolean` | `false` | Repeats the node on every page of its parent. See [Fixed content and pages](#fixed-content-and-pages). |
| `break` | `boolean` | `false` | Forces a page break before the node. Ignored when only `fixed` content comes before the node on its page, so it never adds an empty page. |
| `minPresenceAhead` | `number` | `0` | Minimum space in points that must follow, or the node moves to the next page. |
| `debug` | `boolean` | `false` | Draws the node's layout box for debugging. |
| `style` | `PdfStyleValue` | None | A style object or nested array. `false`, `null`, and `undefined` entries are ignored. |
| `decorative` | `boolean` | `false` | In a tagged document (`'PDF/UA-1'` or `'PDF/A-3a'`): the node and everything inside it are an artifact that assistive technology skips. No effect otherwise. See [Accessible PDF]($docs.accessible-pdf). |

`PdfPage`, `PdfView`, `PdfText`, and `PdfImage` additionally accept `bookmark`
(`string`, or `{ title, expanded? }`) to build the outline.

## Fixed content and pages

A `fixed` node repeats on every page of its parent. The parent is the
`PdfPage` for a node directly on the page (every page that page breaks into),
and the view that holds the node for a nested node (every page that view
reaches). A table header is a `fixed` row of its table.

`PdfView` and page-flow `PdfText` also accept `pages`, which limits the pages
of the parent on which a `fixed` node appears:

| `pages` | Appears on |
| ------- | ---------- |
| `'all'` (default) | Every page of its parent. |
| `'first'` | The first page of its parent only. |
| `'continuation'` | Every page of its parent except the first. |

```vue
<PdfText fixed pages="continuation">
  {{ document.title }} · <PdfPageNumber />
</PdfText>
```

Where the node does not appear, it takes no space on the painted page:

- `'first'`: the later pages of the parent are laid out without the node, so
  they hold as much content as a page without it. This costs one extra layout
  pass.
- `'continuation'`: the first page of the parent breaks as if the node were
  there, so its content can end up to one node height earlier. The engine
  measures the rest of the document in one step and cannot leave the node out
  of only the first page.

Fixed content must leave room for the content after it. When the `fixed`
nodes above some content are together as high as the page content area or
higher, the render fails at once with `PDF_LAYOUT_ERROR`. The message names
the node, its source position, its height, the room on the page, and the pages
that are full: every page, the first page, or every page after the first. The
first page counts the `'continuation'` nodes too, because it breaks as if they
were there. Make the fixed content lower, give it `position: 'absolute'`, or
remove `fixed` so it can break across pages.

An SVG, image or canvas never breaks across pages. When the room that fixed
content leaves is lower than such a block, every page repeats the one before.
The render then runs until `timeoutMs` and fails with `PDF_LIMIT_EXCEEDED`,
and the message names the in-flow fixed content as a possible cause. A `fixed`
node in a row repeats beside the row's content on every page the row reaches,
and the row ends with its content.

For a running head, the recommended pattern is an absolute `fixed` node in the
page padding. It takes no space in the flow, so no page loses content and no
extra pass runs:

```vue
<PdfPage size="A4" :style="{ paddingTop: 64, paddingHorizontal: 48, paddingBottom: 48 }">
  <PdfText
    fixed
    pages="continuation"
    :style="{ position: 'absolute', top: 28, left: 48, right: 48, fontSize: 8 }"
  >
    {{ document.title }} · <PdfPageNumber />
  </PdfText>
  <PdfText>{{ document.body }}</PdfText>
</PdfPage>
```

`pages` counts the pages of one parent. A running head that must continue on
a second `PdfPage` uses `pages="all"` on that page.

Rules, each enforced with `PDF_TREE_INVALID`:

- `pages` requires `fixed`.
- A node with `'first'` or `'continuation'` contains only `PdfView`, `PdfText`,
  text, and page tokens. It cannot contain a `bookmark` or another `pages` node.
- `pages` is not supported on a `PdfText` nested inside another `PdfText`.

A view with `fixed` children and other children does not end a page with only
its `fixed` children. When a page would end with a repeated header alone, the
view starts on the next page instead. This costs one extra layout pass.

## PdfDocument

The root. Carries document metadata; takes no base props. Its children are
`PdfPage`, `PdfAttachment`, and `PdfFacturX`.

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `title`, `author`, `subject`, `keywords` | `string` | None | Info-dictionary metadata. `'PDF/UA-1'` requires `title`. |
| `creator`, `producer` | `string` | `'nuxt-pdf'` | Info-dictionary producer metadata. |
| `language` | `string` | None | Document language tag, such as `'en'` or `'de-CH'`. `'PDF/UA-1'` and `'PDF/A-3a'` require it. |
| `creationDate` | `Date` | Current render date | Info-dictionary creation date. The same document with the same `creationDate` gives the same bytes on every render in one environment, so a hash can detect a changed document. |
| `pdfVersion` | `'1.3'` through `'1.7'` or `'1.7ext3'` | `'1.3'` | PDF version written to the catalog. With `conformance`, only `'1.7'` is accepted. |
| `conformance` | `PdfConformance \| readonly PdfConformance[]` | None | The standard the PDF claims and meets: `'PDF/A-3b'`, `'PDF/A-3a'`, or `'PDF/UA-1'`, or a list of them with at most one PDF/A level. See [PDF/A and Factur-X]($docs.pdf-a-and-factur-x) and [Accessible PDF]($docs.accessible-pdf). |
| `protection` | `PdfProtection` | None | Encrypts the PDF with AES-256: `openPassword`, `ownerPassword` (at least one), and `allow` with the permissions. Conflicts with PDF/A and `PdfFacturX`. See [Password protection]($docs.protection). |
| `pageLayout` | `'singlePage' \| 'oneColumn' \| 'twoColumnLeft' \| 'twoColumnRight' \| 'twoPageLeft' \| 'twoPageRight'` | None | Reader page layout. |

Reader page mode is not a public prop. The engine's own encryption options
(`userPassword`, `permissions`) are not accepted: they would write a weaker
cipher. Use `protection`.

`modificationDate` is also absent. The pinned engine writes its
upstream prop under a non-standard custom key rather than the PDF `ModDate`
entry, so exposing it would promise metadata that common readers do not see.

When `definePdf` supplies `title` or `language`, that value is authoritative and
overrides the corresponding `PdfDocument` prop. Without a definition value, the
root prop is preserved as the rendered fallback. The checks of `'PDF/UA-1'` and
`'PDF/A-3a'` see the definition values.

## PdfPage

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `size` | `PdfPageSizeName \| [w, h] \| { width, height }` | `'A4'` | Uppercase named size or explicit dimensions. See [Page sizes]($docs.page-sizes). |
| `orientation` | `'portrait' \| 'landscape'` | `'portrait'` | Page orientation. |
| `dpi` | `number` | `72` | DPI used for `px` dimensions. |
| `wrap` | `boolean` | `true` | Paginates content. `false` grows the page to fit. |

Plus the base and bookmark props.

## PdfView

The flexbox container. Base and bookmark props, plus:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `wrap` | `boolean` | `true` | Allows the view to split across a page boundary. |
| `pages` | `PdfFixedPages` | `'all'` | With `fixed`: the pages of its parent on which the view appears. |
| `tag` | `PdfViewTag` | None | In a tagged document: `'section'`, `'list'`, `'list-item'`, `'quote'`, `'caption'`, or `'figure'`. Without `tag` the view is a plain group. No effect without a tagged level. See [Group content]($docs.accessible-pdf#group-content). |
| `alt` | `string` | None | With `tag="figure"`: what the figure shows, for assistive technology. A tagged document requires `alt` or `decorative` on a figure view. Fails on a view without `tag="figure"`. See [Figures with a caption]($docs.accessible-pdf#figures-with-a-caption). |

## PdfText

The only container for text has two context-specific prop branches.

In normal page flow it accepts the base and bookmark props, plus:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `wrap` | `boolean` | `true` | Allows text to split across pages. |
| `widows` | `number` | `2` | Minimum lines kept together at a page top. |
| `orphans` | `number` | `2` | Minimum lines kept together at a page bottom. |
| `hyphenate` | `boolean` | `true` | `false` keeps every word whole: a long word moves to the next line instead of being split with a hyphen. |
| `pages` | `PdfFixedPages` | `'all'` | With `fixed`: the pages of its parent on which the text appears. |
| `tag` | `PdfTextTag` | `'p'` | In a tagged document: `'h1'` through `'h6'` for a heading, `'p'` for a paragraph. Not allowed on a nested `PdfText`. No effect without a tagged level. See [Headings]($docs.accessible-pdf#headings). |

Inside `PdfSvg`, it instead accepts:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `x`, `y` | `PdfSvgLength` | Required | SVG text coordinates. |
| `fill` | `string` | None | Direct SVG text paint color. |
| `style` | `PdfStyleValue` | None | Text metrics such as font family and size. `color` is not SVG paint. |

SVG text rejects page-flow-only props such as `id`, `bookmark`, `fixed`,
`break`, `wrap`, `widows`, `orphans`, `hyphenate`, `pages`, `tag`, and
`decorative`.

A `PdfText` holds text, nested `PdfText`, `PdfImage`, `PdfLink`, `PdfTspan`,
and the page tokens below.

## Page tokens

`PdfPageNumber`, `PdfPageCount`, and `PdfPageRef` print page numbers inside a
page-flow `PdfText`. The numbers are resolved after layout.

| Component | Props | Prints |
| --------- | ----- | ------ |
| `PdfPageNumber` | None | The number of the page the surrounding text is painted on. |
| `PdfPageCount` | None | The total number of pages in the document. |
| `PdfPageRef` | `to` (`string`, required) | The number of the first page that shows the element with the id `to`. |

```vue
<PdfText fixed>
  Page <PdfPageNumber /> of <PdfPageCount />
</PdfText>
```

Put `PdfPageNumber` and `PdfPageCount` in a `fixed` text to print them on every
page. A `PdfText` inside a `fixed` `PdfView`, such as a footer row, also
repeats; it needs no `fixed` of its own:

```vue
<PdfView fixed :style="{ flexDirection: 'row', justifyContent: 'space-between' }">
  <PdfText>{{ company.name }}</PdfText>
  <PdfText>Page <PdfPageNumber /> of <PdfPageCount /></PdfText>
</PdfView>
```

A page token is a component, not a value, so it cannot go into a computed
string. Keep the computed part in a template expression and put the token
after it:

```vue
<PdfText fixed>{{ parts.join(' · ') }} · Page <PdfPageNumber /></PdfText>
```

A `PdfText` that holds a page token can contain only text and page tokens,
and it cannot be nested inside another `PdfText`. Its text does not inherit a
`lineHeight` multiplier. A page token in a `PdfLink` goes into a `PdfText`
inside the link, and that link stays outside any other `PdfText`:
`<PdfLink><PdfText>Page <PdfPageNumber /></PdfText></PdfLink>`.

```vue
<PdfLink :href="`#${section.id}`">
  <PdfText>{{ section.title }} <PdfPageRef :to="section.id" /></PdfText>
</PdfLink>
```

`PdfPageRef` resolves to the page where the destination starts, also when the
section spans several pages. The `to` id must match an `id` in the document, or
the render fails with `PDF_TREE_INVALID`. A document with `PdfPageRef` uses at
least two layout passes; `maxPasses` in [definePdf]($docs.define-pdf) bounds
them. See [Contents, links & bookmarks]($docs.contents-links-bookmarks).

## PdfImage

Base and bookmark props, plus:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `src` | `PdfImageSource` | Required | Image source. |
| `alt` | `string` | None | What the image shows, for assistive technology. A tagged document requires `alt` or `decorative`, except for an image inside a `PdfSvg` or a `figure` view. |

`PdfImageSource` is a `pdfs/assets`-relative path, a `Uint8Array`/`ArrayBuffer`,
`{ data, format: 'png' \| 'jpg' }`, or `{ uri, format? }`.

## PdfLink

Base props (no bookmark), plus:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `href` | `string` | Required | External `https:` or `mailto:` URL, or a `#id` internal destination. |
| `wrap` | `boolean` | `true` | Allows the link to split across pages. |
| `hitSlop` | `{ top?, right?, bottom?, left? }` | None | Expands the clickable area. |

## PdfNote

A sticky-note annotation. Base props only; its text comes from its content.
A document that claims PDF/A or a tagged level rejects `PdfNote`; print the
note as `PdfText` instead.

## PdfTextField, PdfCheckbox, PdfSelect

Form fields: a text field, a checkbox and a drop-down list that a reader fills
in. Each is a leaf with a fixed box; its style must set `width` and `height`.
They take `name` (required, unique), `label`, `readOnly`, `required` and
`style`, and no base props.

| Primitive | Props |
| --------- | ----- |
| `PdfTextField` | `value?: string`, `multiline?: boolean`, `maxLength?: number` |
| `PdfCheckbox` | `checked?: boolean`, `exportValue?: string` (default `'Yes'`) |
| `PdfSelect` | `options: readonly string[]`, `value?: string`, `editable?: boolean` |

Nuxt PDF draws each field in Helvetica: the style sets `fontSize` (default
`10pt`), `color`, `textAlign`, `padding` (default `2pt`), the border and the
background. Field values and options use WinAnsi characters only. A document
with a PDF/A or tagged level rejects form fields. See
[Fillable forms]($docs.forms).

## PdfAttachment

Embeds a file in the PDF. It is a direct child of `PdfDocument`, next to the
pages. It paints nothing and has no children.

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `name` | `string` | Required | File name that PDF viewers show. At most 255 characters, no `/`, `\`, or control characters, unique within the document. |
| `data` | `string \| Uint8Array` | Required | File content. A string is embedded as UTF-8. It is the content, never a path or URL. |
| `type` | `string` | None | MIME type such as `text/xml`. |
| `description` | `string` | None | Description that PDF viewers show. |
| `relationship` | `PdfAttachmentRelationship` | `'Unspecified'` | `'Alternative'`, `'Data'`, `'Source'`, `'Supplement'`, or `'Unspecified'`. Written as the PDF `AFRelationship` key. |

```vue
<PdfDocument>
  <PdfAttachment name="invoice.xml" :data="invoiceXml" type="text/xml" relationship="Data" />
  <PdfPage size="A4">
    <PdfText>Invoice {{ invoice.number }}</PdfText>
  </PdfPage>
</PdfDocument>
```

An invalid prop, a duplicate `name`, or a child fails with `PDF_TREE_INVALID`.
The bytes of all attachments of one render count against
[`pdf.limits.maxTotalAttachmentBytes`]($docs.errors-and-limits). The
attachment date is the document's creation date, so a fixed `creationDate`
gives the same bytes on every render. An attachment does not make the PDF
conform to PDF/A-3 or an e-invoice profile; use `conformance` and `PdfFacturX`
for that. An attachment cannot use the name `factur-x.xml`, which belongs to
`PdfFacturX`.

## PdfFacturX

Embeds the XML invoice of a Factur-X (ZUGFeRD 2) hybrid invoice. It is a direct
child of `PdfDocument`, at most once per document. It paints nothing, has no
children, and makes the document PDF/A-3b.

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `invoice` | `EInvoice` | None | The invoice data. The render writes the CII XML for `profile` from it. Give `invoice` or `xml`, not both. See [E-invoices]($docs.e-invoices). |
| `xml` | `string \| Uint8Array` | None | The finished CII XML content. A string is embedded as UTF-8. It is the content, never a path or URL. Give `invoice` or `xml`, not both. |
| `profile` | `PdfFacturXProfile` | Required | `'MINIMUM'`, `'BASIC WL'`, `'BASIC'`, `'EN 16931'`, `'EXTENDED'`, or `'XRECHNUNG'`. With `xml`, it must match the profile that the XML names. With `invoice`, `'EXTENDED'` is not available. |
| `relationship` | `PdfFacturXRelationship` | `'Data'` for `MINIMUM` and `BASIC WL`, else `'Alternative'` | `'Data'`, `'Alternative'`, or `'Source'`. Written as the PDF `AFRelationship` key. |

```vue
<PdfDocument title="Invoice 2026-014" language="en">
  <PdfFacturX :invoice="invoice" profile="EN 16931" />
  <PdfPage size="A4" :style="{ fontFamily: 'Invoice Sans' }">
    <PdfText>Invoice 2026-014</PdfText>
  </PdfPage>
</PdfDocument>
```

The XML is embedded as `factur-x.xml` (`xrechnung.xml` for `XRECHNUNG`), with
the MIME type `text/xml`. Its bytes count against
[`pdf.limits.maxTotalAttachmentBytes`]($docs.errors-and-limits). The
[PDF/A and Factur-X guide]($docs.pdf-a-and-factur-x) explains the font
requirement and every failure.

## Table components

`PdfTable`, `PdfTableHeader`, `PdfTableRow`, and `PdfTableCell` are global
components built from `PdfView` and `PdfText`. They are not primitives: the
mounted tree contains only views and texts. In a tagged document they become a
table with header cells, data cells, and column spans, without extra props. See
[Accessible PDF]($docs.accessible-pdf#what-is-tagged-without-props).

```vue
<PdfTable :columns="['28pt', 1, '78pt']" class="lines">
  <PdfTableHeader class="head">
    <PdfTableCell>#</PdfTableCell>
    <PdfTableCell>Description</PdfTableCell>
    <PdfTableCell align="right">Amount</PdfTableCell>
  </PdfTableHeader>
  <PdfTableRow v-for="(line, index) in invoice.lines" :key="line.id" class="row">
    <PdfTableCell>{{ index + 1 }}</PdfTableCell>
    <PdfTableCell>{{ line.title }}</PdfTableCell>
    <PdfTableCell align="right">{{ money(line.total) }}</PdfTableCell>
  </PdfTableRow>
</PdfTable>
```

| Component | Renders | Props |
| --------- | ------- | ----- |
| `PdfTable` | `PdfView` | `columns` (required, `readonly PdfTableColumn[]`): one entry per column, in cell order. Other `PdfView` props, `class`, and `style` pass to the view. |
| `PdfTableHeader` | `fixed` `PdfView` in row direction | `PdfView` props pass to the view: `:fixed="false"` prints the header once, `pages` limits it. |
| `PdfTableRow` | `PdfView` with `wrap: false` in row direction | `PdfView` props pass to the view: `:wrap="true"` lets a tall row split across pages. |
| `PdfTableCell` | `PdfText` when its content is only text, else `PdfView` | `align`: `'left'` (default), `'center'`, or `'right'`; `colspan`: a whole number from 1 (default `1`); `header` (`boolean`, default `false`): in a tagged document, a cell in a `PdfTableRow` is the header of its row; `class` and `style`. |

A column entry is a share or a width:

- A number is a share of the free width, like `flex-grow`. `[2, 1]` gives the
  first column two thirds of the width.
- A string is a fixed width: a length with a unit or a percentage, such as
  `'80pt'` or `'30%'`.

The header repeats at the top of every page that the table reaches. A row does
not split across pages unless it sets `wrap`. A row that splits keeps every
cell in its column on both pages, and a row with nothing to show above the page
end moves to the next page whole. The orphan rule in
[Fixed content and pages](#fixed-content-and-pages) applies: the table does
not end a page with only its header.

A cell gets its width from its column, also when a local component renders
the cell, and whatever its padding. A cell with only text renders one
`PdfText`. A cell with other content renders a `PdfView`, which passes text
styles on to the texts inside it; put text in that cell inside `PdfText`. A
cell can hold page tokens with text, such as `Page <PdfPageNumber />`. A row
can have fewer cells than columns; the columns after its last cell stay empty
at their width. A local component can render several cells; each takes its
own column.

### Spanning columns

`colspan` lets a cell cover several columns, also in `PdfTableHeader`:

```vue
<PdfTable :columns="['28pt', 1, '78pt']">
  <PdfTableRow v-for="line in invoice.lines" :key="line.id">
    <PdfTableCell>{{ line.position }}</PdfTableCell>
    <PdfTableCell>{{ line.title }}</PdfTableCell>
    <PdfTableCell align="right">{{ money(line.total) }}</PdfTableCell>
  </PdfTableRow>
  <PdfTableRow>
    <PdfTableCell :colspan="2" align="right">Total</PdfTableCell>
    <PdfTableCell align="right">{{ money(invoice.total) }}</PdfTableCell>
  </PdfTableRow>
</PdfTable>
```

A spanning cell is as wide as the columns it covers together: the shares add
up, and the fixed widths add up. Lengths add up only in the same unit or
between `pt`, `in`, `mm`, and `cm`. A span over `px`, `rem`, `vw`, or `vh`
columns and columns of another unit fails. A row counts each cell as the
number of columns it covers. A cell that spans percentage and length columns
together cannot take a right margin (`margin`, `marginHorizontal`, or
`marginRight`); use `paddingRight` for space inside it.

Tables have no `rowspan`: the rows are rendered by the template, so a table
cannot move the rows that a tall cell covers into one group. Tables also have
no automatic borders between cells and no selector for the last cell. Style
each cell with a class. For a nested table, put a `PdfTable` inside the cell.

Each of these fails with `PDF_TREE_INVALID`:

| Cause | Message |
| ----- | ------- |
| `columns` missing, empty, or with an entry that is not a positive number, a length with a unit, or a percentage | `<PdfTable> requires "columns": a non-empty list of shares (numbers) or widths ('30%', '80pt').` |
| More columns than the table declares, counting `colspan` | `<PdfTableRow> needs 4 columns (counting colspan), but its <PdfTable> declares 3.` |
| `colspan` that is not a whole number from 1 | `<PdfTableCell> requires "colspan" to be a whole number from 1.` |
| A static `colspan="2"`, which passes text and not a number | `<PdfTableCell> colspan="2" passes the text "2", not a number. Bind it: :colspan="2".` |
| A right margin on a span over percentage and length columns | `<PdfTableCell> spans percentage and length columns, so it cannot take a right margin (margin, marginHorizontal or marginRight). Use paddingRight for space inside the cell, or give the spanned columns one kind of width.` |
| `header` that is not `true` or `false` | `<PdfTableCell> requires "header" to be true or false.` |
| A span over widths in units that do not add up | `<PdfTableCell> spans columns in "px" and "pt"; their widths cannot be added. Use one unit for the columns it spans.` |
| Text or a primitive directly in a row or header | `<PdfTableRow> holds <PdfTableCell> elements only.` |
| A row or header outside a table, or directly in a cell | `<PdfTableRow> must be inside <PdfTable>.` |
| A cell outside a row or header, or directly in a cell | `<PdfTableCell> must be inside <PdfTableRow> or <PdfTableHeader>.` |

## SVG primitives

SVG primitives render inside a `PdfSvg`. Paint, geometry, clipping, and
transforms are direct props. `PdfG` and the shape primitives have no generic
`style` prop, so there is no style-precedence path; kebab-case Vue attributes
are normalized to the equivalent camelCase key. See
[SVG graphics]($docs.svg-graphics).

`PdfSvgNumber` is a finite number or numeric string. `PdfSvgLength` additionally
accepts a numeric percentage string where the individual prop permits it.
`strokeWidth` is never a percentage. Non-negative geometry and unit-interval
opacity/stop ranges are checked at runtime.

### Shared SVG presentation props

Available on `PdfG`, `PdfPath`, `PdfRect`, `PdfCircle`, `PdfEllipse`, `PdfLine`,
`PdfPolyline`, and `PdfPolygon`:

| Prop | Type |
| ---- | ---- |
| `fill`, `stroke` | `string` |
| `fillOpacity`, `strokeOpacity` | `PdfSvgLength` (0 to 1 or 0% to 100%) |
| `strokeWidth` | `PdfSvgNumber` (non-negative) |
| `strokeLinecap` | `'butt' \| 'round' \| 'square'` |
| `strokeLinejoin` | `'miter' \| 'round' \| 'bevel'` |
| `transform` | `PdfSvgTransform`. One to three unitless `translate(...)` or `rotate(...)` operations. |
| `clipPath` | `string` with the value `url(#id)` |

### Geometry props

| Component | Own props |
| --------- | --------- |
| `PdfSvg` | `viewBox`, `width`, `height`, plus page-flow `style` (not SVG presentation), and `alt` and `decorative` as on `PdfImage` |
| `PdfG` | *(presentation props only)* |
| `PdfPath` | `d` **(required)** |
| `PdfRect` | `x`, `y`, `width` **(required)**, `height` **(required)**, `rx`, `ry` |
| `PdfCircle` | `cx`, `cy`, `r` **(required)** |
| `PdfEllipse` | `cx`, `cy`, `rx` **(required)**, `ry` **(required)** |
| `PdfLine` | `x1`, `y1`, `x2`, `y2` **(all required)** |
| `PdfPolyline` / `PdfPolygon` | `points` **(required)** |
| `PdfDefs` | None. It holds definitions that other elements can reference. |
| `PdfClipPath` | `id` **(required)** |
| `PdfLinearGradient` | `id` **(required)**, `x1`, `y1`, `x2`, `y2` |
| `PdfRadialGradient` | `id` **(required)**, `cx`, `cy`, `r`, `fx`, `fy` |
| `PdfStop` | `offset` **(required)**, `stopColor` **(required)**, `stopOpacity` |
| `PdfTspan` | `x`, `y`, `fill` only |

Alternate gradient coordinate systems, transforms, inheritance, and SVG
`preserveAspectRatio` modes are not public props. See
[Supported behavior and limitations]($docs.supported-behavior).

Each `PdfSvg` accepts at most one direct `PdfDefs` child. Definition ids are
safe, unique, and scoped to that one SVG. `fill="url(#id)"` must resolve to a
linear or radial gradient; `clipPath="url(#id)"` must resolve to a
`PdfClipPath`. Missing, malformed, or incompatible references fail with
`PDF_TREE_INVALID`.

Explicit zero has SVG semantics: zero fill opacity is transparent, zero stroke
width removes the stroke instead of requesting a PDF hairline, and supported
gradient coordinates remain zero. The engine repairs upstream truthiness
fallbacks after layout and before serialization.
