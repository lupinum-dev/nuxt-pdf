First identify whether the failure happens during module setup or during
`render()`.

- Setup validates configuration, template definitions, local images, and
  fonts. Invalid setup can throw `TypeError` before a template render exists.
- Render failures use `NuxtPdfError` with a machine-readable `code` and
  `templateKey`. Development also includes the relative `templateFile`.

The [errors and limits reference]($docs.errors-and-limits) defines
every code and default budget.

## Inspect a render error

```ts [server/api/report.get.ts]
import { NuxtPdfError, pdf } from '#pdf'

export default defineEventHandler(async () => {
  const props = { id: 'report-1' }
  try {
    const result = await pdf.report.render(props)
    return result.response()
  }
  catch (error) {
    if (error instanceof NuxtPdfError) {
      console.error(error.code, error.templateKey, error.templateFile)
    }
    throw error
  }
})
```

Log identifiers and diagnostics through the application's normal error system.
Do not log render props or document text unless the application has a separate
data-handling policy for them.

## Use the development preview

Open `/_pdf/<template-key>`. The preview renders through the same public
template method as server code and shows duration, byte length, page count,
layout passes, layout warnings, and registered font faces.

When a render fails, the preview shows the code, the template, and a short
message. For `PDF_TREE_INVALID` and `PDF_TEMPLATE_INVALID` it shows the reason, for example
`<PdfTableRow> needs 3 columns (counting colspan), but its <PdfTable> declares 2.` Other codes
show a generic sentence, so document content stays out of the error panel. If
the previous render succeeded and **Layout boxes** is off, the old PDF stays
visible with a stale marker.

An error or layout warning about one template element shows its source
position, such as `pdfs/invoice.vue:42:7`. Click the position to open that line
in your editor. The preview calls the Vite open-in-editor endpoint of the
development server and stays on the page. The position also exists on the
error object; see [source positions]($docs.errors-and-limits).

Add or remove a `.vue` template or component under `pdfs/` while `nuxt dev`
runs, and the preview lists it after the server rebuilds; Nuxt does not
restart. Adding, removing or editing a font restarts Nuxt, and so does adding
or removing an image or any other file that is not a `.vue` file, or the whole
`pdfs/` folder, because the module reads fonts and images when Nuxt starts.
Editing a template, a component or an image does not restart Nuxt.

Select **Layout boxes** in the preview header to draw the layout box and size
of every page-flow node. Use it to find the node that takes unexpected space or
moves to the next page. The setting is kept in the URL (`?debug=1`), so a
refresh and the raw PDF link keep it. Select it again to turn it off. It
exists only in the preview; a render from server code never draws the boxes.

## Fix a template that does not compile

In development, a template or a component under `pdfs/` that fails to compile
does not stop `nuxt dev`. Other templates, pages, and API routes keep working.

- The terminal prints the compiler message with the file, line, and column.
  It prints the message once; a rebuild does not print it again while the
  file stays broken.
- `/_pdf` marks the template card with **Compile error**.
- `/_pdf/<template-key>` shows "This template failed to compile", the code
  `PDF_TEMPLATE_INVALID`, the compiler message, and the source position. Click
  the position to open the line in your editor.
- Server code that renders the template gets a `NuxtPdfError` with the code
  `PDF_TEMPLATE_INVALID` and `source` set.
- A component that fails to compile fails every template that uses it, with
  the position in the component file.

Correct the file and save it. The server rebuilds, and the preview renders the
template again. A production build (`nuxt build`) still fails on the same
error, so a broken template cannot reach production.

Three more failures show the same way, with the position of the import, the
module, or `definePdf()`: a template or component that imports a module that
nothing resolves, a local module in its imports that fails to compile or
imports a missing module (the position is in that module), and a
`definePdf()` value that fails validation. A production build fails on each,
with the same message and position.

A template that throws while it renders, or uses a component that Vue cannot
resolve, shows the error in `/_pdf/<template-key>`. The terminal prints the
message and the stack once, until the template renders again.

## Match the message to a fix

| Message or code | Inspect or change |
| --- | --- |
| `Cannot find module '#pdf'` or an untyped import | Run `pnpm nuxt prepare` or restart the development server. |
| `/_pdf` returns 404 | Use the preview only in development. It is absent from production output. |
| `PDF_TEMPLATE_NOT_FOUND` | Check the relative filename and registry key. Nested keys retain `/`. |
| `PDF_TEMPLATE_INVALID` in development, "This template failed to compile" | Open the source position and correct the template or component. |
| `PDF_TREE_INVALID` | Read the named primitive and prop or nesting rule, and open the source position. Remove DOM attributes and put text inside `PdfText`. |
| `<PdfImage> cannot contain text.` or `Invalid PDF nesting: <PdfRect> cannot contain …` | Remove the content from the leaf primitive, or put it next to the element. See [primitives]($docs.primitives). |
| `PDF/A-3b requires embedded fonts` | Register a font and set `fontFamily` on every page. See [PDF/A and Factur-X]($docs.pdf-a-and-factur-x). |
| `claims PDF/UA-1, which requires …`, `needs "alt"`, `skips a heading level` | Add the document title or language, an `alt` text or `decorative`, or the heading level that the message names. See [Accessible PDF]($docs.accessible-pdf#failures). |
| `"protection.openPassword" must …`, `claims PDF/A-3b, which must not be encrypted`, `<PdfFacturX> writes a PDF/A-3 file` | Correct the named password field, or remove `protection` or the PDF/A claim. The message never shows the password. See [Password protection]($docs.protection). |
| `is the name of another form field too`, `needs a "width" in its style`, `which a form field cannot draw: field text uses WinAnsi` | Rename the field, give it a `width` and `height`, or replace the character with a WinAnsi one. See [Fillable forms]($docs.forms#rules). |
| `PDF/A-3b requires embedded fonts, but <PdfTextField> … draws its value in the standard font Helvetica`, `… which its font "…" does not have` (also with `PDF/UA-1`) | Register a TrueType font and set `fontFamily` on the page or the field, or remove the character. See [Embed the field font]($docs.forms#embed-the-field-font). |
| `<PdfTextField> "…" needs a "label" in a PDF/UA-1 document` | Give the field a `label`; give each radio option its own. See [Accessible forms]($docs.forms#accessible-forms). |
| `is also the name of a <PdfCheckbox>`, `has the value "…" twice`, `has more than one checked option`, `sets "required" on some options only` | Give the radio group a name no other field has, a `value` of its own to each option, `checked` to one option at most, and `readOnly` and `required` to every option or none. See [Make a radio group]($docs.forms#make-a-radio-group). |
| `but a field border is square`, `but a field border is solid`, `which a field cannot draw` | Remove `borderRadius` or the `borderStyle` from the field style, or use `textAlign` left, center or right. See [Style a field]($docs.forms#style-a-field). |
| `Unknown component <PdfTxt>.` from the build | Correct the tag name, or import or register the component. The message names the nearest Pdf component. |
| `[nuxt-pdf] <file>:<line>:<column> …` from the build | Correct the `<style>` declaration, selector, or class at that position. See [Styles]($docs.styles). |
| `Font family not registered: <family>` | Register the requested family, weight, and style in `pdf.fonts` in `nuxt.config.ts`. |
| `<PdfView> at <file>:<line>:<column> asks for <family> in fontStyle italic, …, but <family> has no italic face (registered: …)` | Register a file in that style for the family in `pdf.fonts`, or use another family on that node. The message lists the faces the family has. |
| `… asks for <family> in fontStyle normal, fontWeight 600, but <family> has no normal face of weight 600 (registered: …)` | Register the face of that weight in `pdf.fonts`, or use a weight the message lists. A variable face lists its axis, such as `normal 100 to 900`. |
| `Unsupported prop "render" on <PdfText>.`, `Unsupported prop "hyphenate"` or `Unsupported prop "hyphenation-callback"` from the build | Replace the removed prop. See the [upgrade guide]($docs.upgrade-guide). |
| A font throws `TypeError` during setup | Check its relative path, extension, signature, size, and location under `pdfs/fonts`. |
| `PDF_ASSET_BLOCKED` | Check the image source type, HTTPS allowlist, redirects, and timeout. A message that starts with `<PdfRichText> image content[…]` names an image in rich text. |
| `diagnostics.imageWarnings` is not empty | A rich text image with `brokenImages="placeholder"` printed its alt text in a box because its source was refused. Remove `brokenImages="placeholder"` to read the error. See [Broken images]($docs.rich-text#broken-images). |
| `PDF_ASSET_INVALID` | Replace the admitted bytes with a valid PNG or JPEG of the declared format. |
| `PDF_LIMIT_EXCEEDED` | Read the named limit and cap. Reduce the input or raise only that limit for a known document. |
| `PDF_RICH_TEXT_INVALID` | Read `error.issues`. Each `path` names a node of the rich text, such as `content[2].children[0].href` or `comark.nodes[1][0]`, and the message names the wrong value or the limit. Check CMS input with `validateRichText` before the render. See [Rich text]($docs.rich-text#limits). |
| `parseRichTextMarkdown needs the optional peer dependency "comark"` | Install it with `pnpm add comark`. See [Print Markdown]($docs.rich-text#print-markdown). |
| `parseRichTextMarkdown exceeded its …ms time budget` | The Markdown took longer than `pdf.limits.markdownTimeoutMs`. Check the input; raise the limit only for Markdown that needs this long. |
| `PDF_INVOICE_INVALID` | Read `error.issues`. Correct each field that a `path` names, such as `invoice.buyerReference`. Check form input with `validateEInvoice` before the render. See [E-invoices]($docs.e-invoices#invalid-invoice-data). |
| `Pagination cannot end: pages … take no content from the flow` | Some content never fits the room that fixed content leaves on a page: below a table header, beside a fixed node in a row, or in the columns under a fixed view. Make that content or the fixed content lower, or remove `fixed` so it can break across pages. |
| `PDF_LAYOUT_ERROR` | Check geometry, fixed content that fills the page, a `fixed` node on a page between flow content, and the registered font family, weight, and style. |
| `PDF_RENDER_ERROR` | Read the attached message for an engine failure without its own code. If it says the build has no render worker, parse Markdown with a Node server preset. See [Deployment]($docs.deployment). |

For "Page numbers did not stabilize" (`maxPasses`), fix layout that changes when page numbers appear.
Raising the cap does not make unstable geometry converge. See the
[table-of-contents guide]($docs.contents-links-bookmarks).

## Monitor successful renders

Every completed result includes immutable metadata and diagnostics. Record
duration, output bytes, page count, layout passes, layout warnings, and
registered font faces.

The development preview lists each layout warning. For example, an
unbreakable `PdfView` that is taller than the page renders with overflow, or
the engine shrinks its content to fit the page. Both cases give the warning
`PDF_UNBREAKABLE_NODE_OVERFLOW`; for a shrunk block, the node height is the
height the block needs, not the height it got. The rows that a table cell
with `rowspan` holds together give the same warning when they are cut, with
their height together and the room the page had for them. The preview names the page,
node type, node height, usable page height, and the source position of the
node. Allow the node to wrap or make it smaller.
This is a warning rather than a render failure because the output is still a
valid PDF and some authors intentionally use oversized pages.

A text keeps only the lines that fit the height of its box: its own `height`
or `maxHeight`, or that of a view around it. The other lines are not drawn,
and the render gives the warning `PDF_CONTENT_HIDDEN`, once per text, with the
number of lines that are not drawn. An absolute node that reaches below the
page end gives the same warning, with its lines and boxes below the page. The
preview names the page, the node type, what is hidden and the source position
of the node. Give the box more height, shorten the content, or move the
absolute node up. A block that cannot split and is cut at the page end gives
only `PDF_UNBREAKABLE_NODE_OVERFLOW`, not this warning for the lines inside it.

A `PdfTable` with `'auto'` columns that is narrower than its longest words
gives the warning `PDF_TABLE_COLUMNS_TOO_NARROW`, once per table. The preview
names the page where the table starts, the table width and the width its
columns need. Give the table more room or shorten the longest words.

When the notes of a page cannot all fit on it with their marks, the notes that
do not fit print at the top of the note area on the next page, and the render
gives the warning `PDF_FOOTNOTES_MOVED`, once per page. The preview names the
page and the numbers of the notes that moved. Let the block with the marks
wrap, or shorten the notes.

A character that the font of its text does not contain shows as the font's
empty box, or not at all in a standard font, and gives the warning `PDF_GLYPH_MISSING`, once per character. The
preview names the page where the character first appears, its code point and
the font family. Register a font that contains it and use it in `fontFamily`,
or replace the character.

A document whose `language` has no hyphenation patterns gives the warning
`PDF_HYPHENATION_UNAVAILABLE` when a text has `hyphens: 'auto'`, once per
render, and its words split only at soft hyphens. The preview names the language. Set a supported tag, such as `de` or
`en-GB`, or put soft hyphens (`&shy;`) in long words.

A failed render shows up in a customer's invoice, not in a test run. Alert on trends
before time or output budgets become routine failures.
