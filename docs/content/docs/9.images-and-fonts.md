Keep local images under `pdfs/assets` and fonts under `pdfs/fonts`. Nuxt PDF
validates and embeds them in the Nitro server output.

In development, each render reads and validates local image files again.
Image edits take effect without restarting the server.

## Add a local image

Put a PNG or JPEG in `pdfs/assets`. Set `PdfImage.src` to the path relative to
that directory:

```vue
<PdfImage
  src="brand/logo.png"
  :style="{ height: 40, objectFit: 'contain', width: 120 }"
/>
```

Public rendering accepts local paths, admitted PNG or JPEG byte sources, and
allowlisted HTTPS URLs. It blocks (`PDF_ASSET_BLOCKED`) `data:` URL strings, absolute filesystem
paths, parent traversal, and symlink escapes. A file that is not a PNG or JPEG,
such as an SVG file, fails with `PDF_ASSET_INVALID`.

A JPEG with an EXIF orientation prints turned or mirrored as that orientation
says, as a browser shows it. For orientations 5 to 8 the image turns a quarter,
so its width and height swap for the layout too.

Use [`PdfSvg`]($docs.svg-graphics) for vector graphics authored in the
document tree.

## Register a local font

Put a TTF, OTF, or WOFF2 file in `pdfs/fonts`, then register one entry for each weight
and style used by the document:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lupinum/nuxt-pdf'],
  pdf: {
    fonts: [
      {
        family: 'Invoice Sans',
        src: 'InvoiceSans-Regular.ttf',
        fontStyle: 'normal',
        fontWeight: 400,
      },
      {
        family: 'Invoice Sans',
        src: 'InvoiceSans-Bold.ttf',
        fontStyle: 'normal',
        fontWeight: 700,
      },
    ],
  },
})
```

Set the family on a parent so text descendants inherit it:

```vue
<PdfPage :style="{ fontFamily: 'Invoice Sans' }">
  <PdfText>Invoice</PdfText>
</PdfPage>
```

If the requested family is not registered, or the family has no face of the
requested style and weight, rendering fails with `PDF_LAYOUT_ERROR`. No weight
falls back to another: `fontWeight: 'bold'` needs a face registered at 700,
also for rich text `strong` and headings, which ask for 700. If the configured
file is invalid, module setup throws a `TypeError` before a template render
starts.

### Variable fonts

A variable font file serves every weight on its `wght` axis: register it
once, and each weight inside the axis paints with the axis set to that weight.
A weight outside the axis fails with `PDF_LAYOUT_ERROR`, so 100 on a font from
200 to 900 fails, also when it is registered. Other axes, such as width or
slant, stay at the font's defaults.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lupinum/nuxt-pdf'],
  pdf: {
    fonts: [
      { family: 'Code', src: 'SourceCodeVF-Upright.ttf' },
    ],
  },
})
```

Use the TrueType variable file (`.ttf`, or a WOFF2 made from it). A variable
font with CFF2 outlines, the usual `.otf` variable file, fails at build time
with a `TypeError`; use the `.ttf` file or one static `.otf` file per weight.

## Where lines break

A line breaks where the Unicode line breaking rules
([UAX #14](https://www.unicode.org/reports/tr14/)) allow:

- after spaces;
- between two Chinese or Japanese characters, so text without spaces wraps;
- after a hyphen, a slash or an en dash, as in `e-mail` or `and/or`, with no
  added hyphen. A break after a hyphen costs a little, so the layout takes it
  only when it gives more even lines than a break at a space;
- at a zero-width space (`&#8203;`, U+200B). Use it to mark more break points
  in a long URL; a URL already breaks after most slashes, but not before a digit.

A line never breaks at a no-break space (`&nbsp;`, U+00A0) or before closing
punctuation, such as `!`, `?` or `)` after a space in French text. A line
separator (U+2028) or a paragraph separator (U+2029) ends the line, as a line
break (`\n`) does.

To keep a hyphenated word whole, put a word joiner (`&#8288;`, U+2060) after
its hyphen: `e-&#8288;mail`. The same keeps a page range on one line:
`201–&#8288;216`. It holds in every font, also one without a glyph for it,
and it takes no room.

## Hyphenate by document language

Set the style key `hyphens: 'auto'` to hyphenate long words by the rules of
the document `language`. A word that does not fit on a line then splits at a
hyphenation point and gets a hyphen. `hyphens` is inherited, so set it once on
the page. The default, `hyphens: 'manual'`, splits a word only at its soft
hyphens (`&shy;`, U+00AD).

```vue
<PdfDocument language="de-AT">
  <PdfPage :style="{ hyphens: 'auto' }">
    <PdfText>Donaudampfschifffahrtsgesellschaft</PdfText>
  </PdfPage>
</PdfDocument>
```

`language` only picks the patterns. Set it on `PdfDocument`, or in
`definePdf`. A tag uses the pattern file of its longest known part, in any
case and with `_` read as `-`:

| `language` | Pattern file |
| --- | --- |
| `de`, `de-AT`, `de-CH` | `de-1996`, German in the 1996 spelling |
| `de-1901`, `de-CH-1901` | `de-1901`, `de-ch-1901`: traditional and Swiss traditional German |
| `en`, `en-US` | `en-us` |
| `en-GB` | `en-gb` |
| `el` | `el-monoton`, monotonic Greek (`el-polyton` for polytonic) |
| `mn` | `mn-cyrl` |
| `sr` | `sr-cyrl`, Serbian in Cyrillic script |
| `sr-Latn`, `sh` | `sh-latn`, Serbian in Latin script |
| `pt-BR` | `pt` |
| `fr-CA`, `es-MX` and other regional tags | the file of the language: `fr`, `es` |

`de-CH` gets the German 1996 patterns. For the Swiss patterns, write the full
name: `language="de-CH-1901"`. The other files are `af`, `as`, `be`, `bg`,
`bn`, `ca`, `cop`, `cs`, `cy`, `da`, `es`, `et`, `eu`, `fi`, `fi-x-school`,
`fr`, `fur`, `ga`, `gl`, `grc`, `gu`, `hi`, `hr`, `hsb`, `hu`, `hy`, `ia`,
`id`, `is`, `it`, `ka`, `kmr`, `kn`, `la`, `la-x-classic`, `la-x-liturgic`,
`lt`, `lv`, `mk`, `ml`, `mn-cyrl-x-lmc`, `mr`, `mul-ethi`, `nb`, `nl`, `nn`,
`no`, `oc`, `or`, `pa`, `pi`, `pl`, `pms`, `rm`, `ro`, `ru`, `sa`, `sh-cyrl`,
`sk`, `sl`, `sq`, `sv`, `ta`, `te`, `th`, `tk`, `tr`, `uk` and
`zh-latn-pinyin`; each is its own tag.

- Without `language`, `hyphens: 'auto'` has no patterns: a word splits only
  at its soft hyphens.
- A soft hyphen always gives a split point, with either value. A soft hyphen
  in a word sets its only split points: the patterns do not split that word.
- Left, right and centered text splits a word only when that avoids a much
  shorter line. Justified text splits words more often, to keep its spaces
  even.
- An e-mail address or a URL (text between spaces that holds `@` or `://`)
  never gets a hyphen. It splits only at its soft hyphens, and a URL also
  breaks after most slashes.
- `hyphens: 'manual'` on a `PdfText` keeps its words whole on a page with
  `hyphens: 'auto'`. Use it for labels in narrow columns and for display type.
- Text in `'auto'` table columns is measured with whole words, and a rich text
  code block always has `hyphens: 'manual'`.
- For a language without patterns, a word splits only at its soft hyphens.
  When a text has `hyphens: 'auto'`, the render gives the layout warning
  `PDF_HYPHENATION_UNAVAILABLE` with the language. Languages whose writing does not hyphenate (Arabic, Persian,
  Hebrew, Yiddish, Urdu, Chinese, Japanese and Korean) give no warning.

The patterns come from the [`hyphen`](https://github.com/ytiurin/hyphen)
package, 80 languages. Old Church Slavonic (`cu`) is not available. The server loads the patterns
of a language at its first render and keeps them for the process.

## Check language coverage

A font must contain the glyphs used by the document. Latin Extended, Greek, and
Cyrillic are tested with supplied fonts. Chinese, Japanese, Arabic,
right-to-left text, and combining marks are tested with subset fonts and are
experimental. Variable TrueType fonts are tested for the `wght` axis. For other
scripts, add semantic and raster tests in your application.

An emoji needs a registered font that contains it, such as Noto Emoji, set in
`fontFamily` of its text. Only glyph outlines are painted, so a color emoji
shows in one color. For a color emoji graphic, use an admitted image.

Only the font that `fontFamily` names paints a text; no other font fills in.
A character that the font does not contain shows as the font's empty box, the
`.notdef` glyph, and copies as U+FFFD (�). The render still succeeds and gives
the layout warning `PDF_GLYPH_MISSING` once per character, with the page, the
code point and the font family (see [Errors and debugging]($docs.errors-and-debugging#monitor-successful-renders)).
A document with a PDF/A or PDF/UA claim fails instead, because both standards
forbid the empty box. A tab, a bidi control character (such as U+202E) or
another character that draws nothing is never shown as a box, and takes no
room. Neither is a space that the font lacks: it paints nothing, takes
0.278 em (Helvetica's space width) and gives no warning. A letter with a combining accent that the font lacks, such as
"A" followed by U+030A (combining ring), shows the precomposed letter "Å" when
the font has it, and copies as that letter.

Some Arabic fonts, such as Noto Sans Arabic, draw the dots of a letter as
separate glyphs. In viewers built on pdf.js, such as Firefox, copy and search
of Arabic text in such a font can give control characters and a changed word
order. The page looks right, and Poppler-based tools read the text right.

## Resource validation

The module checks four things:

- **Structure:** images must decode as PNG or JPEG; fonts need a valid TTF, OTF,
  or WOFF2 structure and matching extension. Nuxt PDF decodes a WOFF2 file to
  TTF or OTF itself before it embeds the font. A WOFF 1 file, a WOFF2 font
  collection, and a WOFF2 file that decodes to more than 20 MiB are refused.
- **Size:** a local image must fit `pdf.limits.maxTotalImageBytes` and
  `maxTotalImagePixels`, the budgets for all images of one render. A font is
  limited to 5 MiB.
- **Location:** the resolved path must remain inside its declared root.
- **Embedding:** validated bytes travel in the Nitro server output, so
  production rendering does not read these files from disk.

The
[module-options reference]($docs.module-options) lists the exact font
fields. Use the [remote-image guide]($docs.remote-images) for HTTPS
sources.
