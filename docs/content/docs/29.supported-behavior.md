Nuxt PDF supports the behavior listed in its public guides and reference pages
against exact pinned layout, font, and serialization packages. It does not claim
the complete React PDF API or test suite.

## Supported areas

The repository tests these user-facing areas:

- document trees, pagination, flex layout, styles, text, and raster images;
- `<style>` blocks with class, compound, and descendant selectors, file-local
  variables, `v-bind()`, and `@import` of local `.css` files, compiled at build
  time;
- tables with a header that repeats on every page and cells that span columns,
  and `fixed` content limited to the first or the continuation pages of its
  parent;
- local fonts and admitted local or allowlisted remote image sources;
- metadata, links, notes, bookmarks, file attachments, and page numbers
  (`PdfPageNumber`, `PdfPageCount`, `PdfPageRef`);
- PDF/A-3b output and Factur-X hybrid invoices (`PdfFacturX`), validated with
  veraPDF;
- EN 16931 e-invoice XML (CII) from invoice data, for the Factur-X profiles
  `MINIMUM` to `EN 16931` and for XRechnung, validated with Mustang and the
  KoSIT validator;
- tagged PDF for PDF/UA-1 and PDF/A-3a: headings, paragraphs, lists, sections,
  quotations, captions, tables, links, and alternative text for images,
  validated with veraPDF;
- SVG shapes, gradients, clip paths, transforms, and SVG text;
- semantic PDF inspection and raster snapshot helpers;
- production removal of preview routes, preview data, and source positions;
- layout in a worker thread with a hard render deadline;
- bounded render time, tree node count, image and attachment bytes, remote
  requests, and page count.

The detailed support status for scripts and fonts is in
[Add images and fonts]($docs.images-and-fonts). Exact primitive and style
support belongs to the [reference section]($docs.primitives).

## Differences from React PDF

Three behaviors differ where matching the pinned lower engine would produce a
wrong or unstable public result:

- A table-of-contents destination resolves to the section's first page.
- A text with `PdfPageNumber` or `PdfPageCount` does not inherit a
  `lineHeight` multiplier. Apply line height to static `PdfText` instead.
- Explicit zero values keep SVG meaning for fill opacity, stroke width, and
  supported gradient coordinates.

These differences have geometry or raster regression coverage.

## Outside the current boundary

Nuxt PDF does not claim:

- full React PDF API, hook, browser-helper, or runtime compatibility;
- Nuxt 3, Node 20, browser rendering, or edge rendering;
- HTML printing, browser CSS beyond the `<style>` subset, charts, forms,
  signing, editing, or PDF merging as built-in features;
- PDF/A levels and parts other than PDF/A-3b and PDF/A-3a, or PDF/UA-2;
- that a screen reader reads tagged output as intended, or the human checks of
  PDF/UA-1 (alt texts, link texts, reading order): veraPDF checks only the
  machine rules;
- `PdfNote` or links in running content in a tagged document;
- the content of Factur-X XML that the application passes with `xml`: Nuxt
  PDF checks only the profile it names;
- UBL e-invoices and writing the `EXTENDED` profile;
- `rowspan` in tables;
- custom hyphenation rules beyond `hyphenate`;
- byte-identical output across operating systems and viewers;
- authenticated remote requests, custom headers, remote fonts, or SSRF
  protection beyond the exact-prefix allowlist;
- SVG image files, SVG markers, or the complete browser SVG model;
- multi-pass resolution of values other than page numbers, page-conditional
  `fixed` content, and the orphan rule for
  repeated headers.
