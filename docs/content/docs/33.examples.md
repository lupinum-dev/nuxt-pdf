The playground under `playground/pdfs/` ships ten complete templates. Each is an
ordinary `.vue` single-file component discovered by the module and rendered
through the same registry in development and production. Every template keeps
its styles in a `<style>` block with classes and a few `:root` variables;
`:style` remains for values that come from data, such as chart geometry, and
for `PdfLeader` colors. Run `pnpm dev` and open `/_pdf` to
browse them, or read each source alongside the excerpts below.

![An invoice, an annual report with charts, an e-book and a certificate rendered by Nuxt PDF](/showcase/showcase.webp)

Open the rendered files: [invoice](/showcase/invoice.pdf), [annual report](/showcase/annual-report.pdf),
[e-book](/showcase/ebook.pdf) and [certificate](/showcase/certificate.pdf).

For a page image and the full source of six of them, see the
[template gallery]($docs.gallery).

## Invoice with a repeated table header

The invoice lists its lines in a `PdfTable`. The columns are set once on the
table; the description column takes the free width. `PdfTableHeader` repeats at
the top of every page that the table reaches, and each `InvoiceLine` component
renders one `PdfTableRow`:

```vue [pdfs/invoice.vue (excerpt)]
<template>
  <PdfTable :columns="['26pt', 1, '44pt', '74pt', '80pt']">
    <PdfTableHeader class="line-header">
      <PdfTableCell>#</PdfTableCell>
      <PdfTableCell>Description</PdfTableCell>
      <PdfTableCell align="right">Qty</PdfTableCell>
      <PdfTableCell align="right">Rate</PdfTableCell>
      <PdfTableCell align="right">Amount</PdfTableCell>
    </PdfTableHeader>
    <InvoiceLine
      v-for="(line, index) in invoice.lines"
      :key="line.id"
      :currency="invoice.currency"
      :index="index"
      :line="line"
    />
  </PdfTable>
</template>
```

Both pages use `InvoicePage`, a local component that holds the page chrome
and a `<slot />` for the content: a running head, a footer link and the
counter `Page <PdfPageNumber /> / <PdfPageCount />`. On the first page the
running head has `pages="continuation"`, so it starts on page 2. `pages`
counts the pages of one `PdfPage`, so the second page with the project brief
uses `pages="all"` to keep the head going. The `compact` scenario leaves that
page out.

The invoice is a Factur-X hybrid invoice. `toEInvoice` in
`pdfs/components/invoice/e-invoice.ts` turns the invoice into `EInvoice` data.
`PdfFacturX` writes the `EN 16931` XML from that data, and the pages print the
totals of `computeEInvoice`, so both show the same amounts. The
document claims `conformance="PDF/A-3b"`, so every text uses a registered font:
`Inter`, set once through the page class. See [E-invoices]($docs.e-invoices).

## E-book with chapter-aware running matter

*The Reed Line* is a digest novella, set in Literata with Cormorant for the
display lines. Its Contents page prints the start page of each chapter with
`PdfPageRef`, resolved after layout:

```vue [pdfs/ebook.vue (excerpt)]
<template>
  <PdfLink
    v-for="chapter in ebook.chapters"
    :key="chapter.id"
    :href="`#${chapter.id}`"
    class="toc-link"
  >
    <PdfView class="toc-row">
      <PdfText class="toc-title">{{ chapter.title }}</PdfText>
      <PdfText class="toc-page"><PdfPageRef :to="chapter.id" /></PdfText>
    </PdfView>
  </PdfLink>
</template>
```

Each chapter is a view with the chapter `id`. The running foot is a `fixed`
text inside that view, so it repeats on every page that the chapter spans and
names the **current** chapter:

```vue [pdfs/ebook.vue (excerpt)]
<template>
  <PdfView
    v-for="chapter in chapters"
    :id="chapter.id"
    :key="chapter.id"
    :break="!chapter.first"
    :bookmark="chapter.title"
    class="chapter"
  >
    <PdfText fixed class="running-foot">
      {{ chapter.title }}   ·   <PdfPageNumber />
    </PdfText>
    <PdfText v-for="(paragraph, index) in chapter.body" :key="index" class="paragraph">
      {{ paragraph }}
    </PdfText>
  </PdfView>
</template>
```

The [running foot recipe]($docs.recipes#running-foot-that-names-the-section)
shows the matching styles.

## Annual report with SVG charts and a ledger table

The Fieldnote Studio annual report draws a grouped bar chart with rounded bar
tops, a line chart with a gradient area tint, and a donut, each in a rounded
card. It uses the [SVG primitives]($docs.svg-graphics),
with every figure computed from one canonical `YearFigures` source. The donut
segments come from a pure geometry model and render as a `v-for` of paths:

```vue [pdfs/annual-report.vue (excerpt)]
<PdfView tag="figure" :alt="donut.alt">
  <PdfSvg :viewBox="`0 0 ${donut.size} ${donut.size}`" :style="{ height: donut.size, width: donut.size }">
    <PdfPath
      v-for="segment in donut.segments"
      :key="segment.id"
      :d="segment.d"
      :fill="segment.fill"
      :transform="segment.transform"
    />
  </PdfSvg>
</PdfView>
```

The donut size comes from the geometry model, so it stays in `:style`. The
statement of operations is a `PdfTable`. Each row carries a `kind`, and one
class per kind sets the padding and the weight of the figures. Each number cell uses `align="right"`, and the model
writes outflows in parentheses. The quarter and sector breakdowns sum to the
yearly totals.

The report is an accessible PDF that claims `['PDF/A-3a', 'PDF/UA-1']`. The
section titles and chart titles are headings, each section is a
`tag="section"` view, and the KPI tiles are a list. The donut legend belongs to the donut figure,
whose `alt` text gives every share. Each
chart has an `alt` text that the geometry model writes from the same data, so
the bar chart's text holds every plotted value. The axis and value labels
around the charts repeat that text, so they are `decorative`, and so are the
KPI triangles, whose delta text carries the sign. The ledger table needs no props for its header and data cells. The label
cells set `header` so each row has a row header. See [Accessible PDF]($docs.accessible-pdf).

## Certificate with an SVG layer

The certificate is a single A4 landscape page on ivory paper, inside one thin
frame. The recipient's name is set in Cormorant, the rest in Literata. At the
top sits a seal drawn with SVG: two rings with a band of fine ticks between
them. The monogram is ordinary text on top of the drawing:

```vue [pdfs/components/certificate/CertificateSeal.vue]
<script setup lang="ts">
defineProps<{ monogram: string }>()

const ticks = Array.from({ length: 72 }, (_, index) => {
  const angle = (index / 72) * Math.PI * 2
  const [cos, sin] = [Math.cos(angle), Math.sin(angle)]
  return { x1: 32 + cos * 26.2, y1: 32 + sin * 26.2, x2: 32 + cos * 29.2, y2: 32 + sin * 29.2 }
})
</script>

<template>
  <PdfView class="seal">
    <PdfSvg class="seal-rings" view-box="0 0 64 64">
      <PdfCircle cx="32" cy="32" r="31.4" fill="none" stroke="#23395B" stroke-width="0.6" />
      <PdfLine
        v-for="(tick, index) in ticks"
        :key="index"
        v-bind="tick"
        stroke="#23395B"
        stroke-width="0.35"
      />
      <PdfCircle cx="32" cy="32" r="24.4" fill="none" stroke="#23395B" stroke-width="0.6" />
    </PdfSvg>
    <PdfText class="seal-letter">
      {{ monogram }}
    </PdfText>
  </PdfView>
</template>

<style>
.seal {
  align-items: center;
  justify-content: center;
  width: 64pt;
  height: 64pt;
}

.seal-rings {
  position: absolute;
  top: 0;
  left: 0;
  width: 64pt;
  height: 64pt;
}

.seal-letter {
  font-family: "Cormorant";
  font-size: 27pt;
  font-style: italic;
  font-weight: 500;
  color: #23395B;
}
</style>
```

The frame has a fixed height, so a long recipient name wraps at spaces to two
lines and the page can never spill to a second sheet.

## Menu with typography and diacritics

The Gasthaus Alpenrose card is two A5 pages of typography on warm paper: dish
names in Cormorant, descriptions in Literata italic, fine hairlines and no
boxes. German dish names carry their umlauts through rendering and extraction.
Each price sits in a fixed column at the right edge, with tabular figures so
the digits line up:

```vue [pdfs/menu.vue (excerpt)]
<template>
  <PdfView class="dish" :wrap="false">
    <PdfView class="dish-row">
      <PdfText class="dish-name">
        {{ dish.name }}
      </PdfText>
      <PdfText class="price">
        {{ formatMenuPrice(dish.price) }}
      </PdfText>
    </PdfView>
    <PdfText class="dish-description">
      {{ dish.description }}
    </PdfText>
  </PdfView>
</template>

<style>
.dish {
  margin-bottom: 8pt;
}
.dish-row {
  flex-direction: row;
  align-items: baseline;
}
.dish-name {
  flex: 1;
  padding-right: 12pt;
  font-family: "Cormorant";
  font-size: 13pt;
  font-weight: 600;
}
.price {
  width: 40pt;
  font-family: "Literata";
  font-size: 9.5pt;
  font-variant-numeric: tabular-nums;
  text-align: right;
}
.dish-description {
  margin-top: 2pt;
  font-family: "Literata";
  font-size: 8.5pt;
  font-style: italic;
  color: #6E6559;
}
</style>
```

`:wrap="false"` keeps a dish and its description on one page.

Prices use a comma as the decimal separator. For example, `9.5` becomes `9,50`. The whole card
is data-driven, so the `winter` scenario swaps every dish and pour without
touching the template.

## Registration form with fillable fields

The Fieldnote Studio workshop registration is a one-page A5 form. The
participant fills it in a PDF reader and sends it back. Each field gets its
size from a class; a `PdfText` above it is the visible label, and `label` is
the accessible name. A field's own border has square corners, so each field
has no border and sits in a view with a rounded border. See
[Fillable forms]($docs.forms):

```vue [pdfs/registration.vue (excerpt)]
<template>
  <PdfText class="field-label">Full name</PdfText>
  <PdfView class="input">
    <PdfTextField
      name="fullName"
      label="Full name"
      :value="registration.participant"
      :max-length="60"
      required
      class="field"
    />
  </PdfView>
  <PdfView class="input">
    <PdfSelect
      name="session"
      label="Session"
      :options="registration.sessions"
      :value="registration.sessions[0]"
      class="field"
    />
  </PdfView>
</template>

<style>
.field-label {
  margin-top: 11pt;
  margin-bottom: 4pt;
  font-weight: 500;
}
.input {
  border: 1pt solid #D4D4D8;
  border-radius: 6pt;
}
.field {
  width: 100%;
  height: 20pt;
  padding: 4pt 7pt;
}
</style>
```

## Journal article from editor HTML

The Fieldnote Studio journal article is HTML that a rich text editor saved in a
CMS. `PdfRichText` prints its headings, lists, quote, code block and link over
two A5 pages. The `body` class sets the text size, and with it the heading
sizes and spacing; `styles` sets the heading font, the pull quote and the
colours of code and links. See [Rich text]($docs.rich-text):

```vue [pdfs/article.vue (excerpt)]
<template>
  <PdfRichText
    class="body"
    :html="article.body"
    :styles="{
      h2: { fontFamily: 'Cormorant', fontWeight: 600 },
      strong: { fontWeight: 600 },
      quote: { fontFamily: 'Cormorant', fontStyle: 'italic', fontWeight: 500, fontSize: 13, borderLeftWidth: 1.5, borderLeftColor: '#1F5A5C' },
      codeBlock: { backgroundColor: '#F3EFE7', borderRadius: 3, padding: 8 },
      link: { color: '#1F5A5C' },
    }"
    bookmarks
  />
</template>

<style>
.body {
  font-family: "Literata";
  font-size: 9.5pt;
  line-height: 1.6;
}
</style>
```

Literata is registered up to weight 600, so `strong` asks for 600: the
default bold (700) would fail with a missing font face error.

A second post is written in Markdown with a `::callout{tone="tip"}`
and a `::callout{tone="warning"}`. The route `server/api/article.get.ts` awaits
`parseRichTextMarkdown` and passes the model as `content`; the template maps
`callout` to a small Vue component with a label and an accent rule:

```vue [pdfs/article.vue (excerpt)]
<script setup lang="ts">
import ArticleCallout from './components/article/ArticleCallout.vue'

const components = { callout: ArticleCallout }
</script>

<template>
  <PdfRichText class="body" :content="article.content" :components="components" />
</template>
```

## Research paper in two columns

The research paper is three A4 pages. The masthead, the title, the authors and
the abstract span the page; the body below them sits in two balanced columns,
set with one class. Each section is a bookmark, and a heading keeps at least 40 pt of its
section below it, so it never ends a column alone:

```vue [pdfs/paper.vue (excerpt)]
<template>
  <PdfView class="body">
    <PdfView
      v-for="section in paper.sections"
      :id="section.id"
      :key="section.id"
      :bookmark="section.title"
      tag="section"
    >
      <PdfText tag="h2" class="heading" :min-presence-ahead="40">
        {{ section.title }}
      </PdfText>
    </PdfView>
  </PdfView>
</template>

<style>
.body {
  columns: 2;
  column-gap: 18pt;
}
.heading {
  font-family: "Inter";
  font-weight: 600;
}
</style>
```

The first page carries the journal masthead, so the running head starts on
page 2. It is an absolute `fixed` view in the page padding with
`pages="continuation"`:

```vue [pdfs/paper.vue (excerpt)]
<template>
  <PdfView fixed pages="continuation" class="running-head">
    <PdfText>{{ paper.shortTitle }}</PdfText>
    <PdfText>{{ paper.journal }} · <PdfPageNumber /></PdfText>
  </PdfView>
</template>

<style>
.running-head {
  position: absolute;
  top: 28pt;
  right: 54pt;
  left: 54pt;
  flex-direction: row;
  justify-content: space-between;
}
</style>
```

A paragraph is built from runs: plain text, italics for species names and
statistical symbols, sub- and superscripts such as R² and CO₂, citations that
link to the reference list, and figure and table labels that link to their
captions. Each figure and table follows the paragraph that first cites it and
floats to the top or the bottom of its column with `float`, so the text fills
the columns around it. The figures are `PdfView tag="figure"` views with
an SVG drawing, a numbered caption and an `alt` text that holds every plotted
value. The template claims PDF/A-3a and PDF/UA-1.
