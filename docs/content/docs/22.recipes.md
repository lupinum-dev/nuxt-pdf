## Repeating header, footer, and page numbers

A `fixed` node repeats on every page of its parent when content wraps onto
more output pages. Keep the page padding large enough that flowing content
never overlaps it.

```vue
<template>
  <PdfPage size="A4" class="page">
    <PdfText fixed class="header">
      Quarterly statement
    </PdfText>
    <PdfText fixed class="footer">
      Page <PdfPageNumber /> / <PdfPageCount />
    </PdfText>
    <slot />
  </PdfPage>
</template>

<style>
:root {
  --page-margin: 40pt;
}
.page {
  padding: 64pt var(--page-margin) 52pt;
}
.header {
  position: absolute;
  top: 24pt;
  left: var(--page-margin);
}
.footer {
  position: absolute;
  right: var(--page-margin);
  bottom: 24pt;
  font-size: 7pt;
}
</style>
```

## Running head from page 2

Add `pages="continuation"` to a `fixed` node to show it on every page of its
parent except the first. Use `pages="first"` for the opposite case. Place the
head absolutely in the page padding: it then takes no space in the flow, so
every page holds the same content and no extra layout pass runs.

```vue
<template>
  <PdfPage size="A4" class="page">
    <PdfText fixed pages="continuation" class="running-head">
      Invoice {{ invoice.number }} · Page <PdfPageNumber />
    </PdfText>
    <slot />
  </PdfPage>
</template>

<style>
.page {
  padding: 64pt 48pt 52pt;
}
.running-head {
  position: absolute;
  top: 28pt;
  right: 48pt;
  font-size: 7pt;
  color: #758078;
}
</style>
```

A node with `pages` can contain views, texts, and page tokens. It cannot hold a
bookmark or another `pages` node.

## Running foot that names the section

Put the `fixed` text inside the section view. It then repeats on every page
that the section spans and can print the section title:

```vue
<template>
  <PdfPage size="A5" class="page">
    <PdfView
      v-for="chapter in chapters"
      :id="chapter.id"
      :key="chapter.id"
      :break="!chapter.first"
      class="chapter"
    >
      <PdfText fixed class="running-foot">
        {{ chapter.title }} · <PdfPageNumber />
      </PdfText>
      <PdfText v-for="(paragraph, index) in chapter.body" :key="index">
        {{ paragraph }}
      </PdfText>
    </PdfView>
  </PdfPage>
</template>

<style>
.page {
  padding: 48pt 40pt 62pt;
}
.chapter {
  flex-grow: 1;
}
.running-foot {
  position: absolute;
  right: 0;
  bottom: -24pt;
  left: 0;
  font-size: 7pt;
  text-align: center;
}
</style>
```

The foot is positioned relative to the section box. `flex-grow: 1` lets the
section fill its last page, so the foot stays at the same height on every page.
For a head at page level that names the chapter of each page, use
[running headers]($docs.document-tree#running-headers).

## Invoice table with a repeated header

Use `PdfTable` for line items. `columns` sets the widths once: a number is a
share of the free width, a string is a fixed width. `PdfTableHeader` repeats at
the top of every page that the table reaches. A `PdfTableRow` does not split
across pages.

```vue [pdfs/components/invoice/InvoiceLines.vue]
<script setup lang="ts">
import type { Invoice } from '../../../shared/invoice'

const props = defineProps<{ invoice: Invoice }>()
const money = (value: number) => `${props.invoice.currency} ${value.toFixed(2)}`
const total = props.invoice.lines.reduce((sum, line) => sum + line.quantity * line.unitPrice, 0)

// #, description (takes the free width), quantity, amount.
const columns = ['28pt', 1, '52pt', '86pt'] as const
</script>

<template>
  <PdfTable :columns="columns">
    <PdfTableHeader class="line-header">
      <PdfTableCell>#</PdfTableCell>
      <PdfTableCell>Description</PdfTableCell>
      <PdfTableCell align="right">Qty</PdfTableCell>
      <PdfTableCell align="right">Amount</PdfTableCell>
    </PdfTableHeader>
    <PdfTableRow
      v-for="(line, index) in invoice.lines"
      :key="line.id"
      class="line"
    >
      <PdfTableCell>{{ index + 1 }}</PdfTableCell>
      <PdfTableCell>{{ line.description }}</PdfTableCell>
      <PdfTableCell align="right">{{ line.quantity }}</PdfTableCell>
      <PdfTableCell align="right">{{ money(line.quantity * line.unitPrice) }}</PdfTableCell>
    </PdfTableRow>
  </PdfTable>
  <PdfView class="totals" :wrap="false">
    <PdfText class="grand-total">Total {{ money(total) }}</PdfText>
  </PdfView>
</template>

<style>
:root {
  --rule: #DDE3DE;
  --muted: #758078;
}
.line-header {
  padding-bottom: 8pt;
  border-bottom-width: 1pt;
  border-bottom-color: #9EA8A1;
  font-size: 7pt;
  color: var(--muted);
}
.line {
  padding-vertical: 10pt;
  border-bottom-width: 1pt;
  border-bottom-color: var(--rule);
}
.totals {
  align-items: flex-end;
  margin-top: 16pt;
}
.grand-total {
  font-weight: 700;
}
</style>
```

A row can live in a local component that renders `PdfTableRow`; it takes its
columns from the enclosing table. A cell with text only renders as text; a cell
with other primitives, such as two `PdfText` lines, renders as a view. When the
header would stand alone at the bottom of a page, the table starts on the next
page.

## Carried subtotals

A long ledger can show the sum so far at the end of each page and again at
the top of the next page. Compute the running sum and format it in the
component, then let each row set it as a running value. The page picks
which value it shows.

```vue [pdfs/components/LedgerTable.vue]
<script setup lang="ts">
const props = defineProps<{ lines: { id: string, label: string, netCents: number }[] }>()

const money = new Intl.NumberFormat('de-DE', { style: 'currency', currency: 'EUR' })
let sum = 0
const rows = props.lines.map(line => ({ ...line, carried: money.format((sum += line.netCents) / 100) }))
</script>

<template>
  <PdfTable :columns="[3, 1]">
    <PdfTableHeader>
      <PdfTableCell>Item</PdfTableCell>
      <PdfTableCell align="right">Net</PdfTableCell>
    </PdfTableHeader>
    <PdfTableRow fixed pages="continuation">
      <PdfTableCell>Carried forward</PdfTableCell>
      <PdfTableCell align="right"><PdfRunningText name="net" at="before" /></PdfTableCell>
    </PdfTableRow>
    <PdfTableRow v-for="row in rows" :key="row.id" :running="{ name: 'net', text: row.carried }">
      <PdfTableCell>{{ row.label }}</PdfTableCell>
      <PdfTableCell align="right">{{ money.format(row.netCents / 100) }}</PdfTableCell>
    </PdfTableRow>
    <PdfTableRow fixed pages="not-last">
      <PdfTableCell>Carried to next page</PdfTableCell>
      <PdfTableCell align="right"><PdfRunningText name="net" at="end" /></PdfTableCell>
    </PdfTableRow>
  </PdfTable>
</template>
```

- The row under the header shows the value before the page (`at="before"`)
  on every page of the table but the first (`pages="continuation"`).
- The last row shows the last value set on the page (`at="end"`) on every
  page but the last (`pages="not-last"`). A table that fits one page shows
  neither row.
- Sum whole minor units, such as cents, and format only the result: sums of
  decimal numbers drift (`0.1 + 0.2`).
- A row that splits across pages counts on the page where it starts.
- For a second sum, such as VAT, give a text in a cell its own name:
  `<PdfText :running="{ name: 'vat', text: row.vatCarried }">`.

Limits: the page where a carry row is hidden keeps its room free at the
bottom, the first page for `'continuation'` and the last page for
`'not-last'`. While the
value at the end of a page is not known yet, the row keeps the room of the
value of its name that needs the most room. In a column of a column
container, `at="before"` and `at="end"` fail with `PDF_TREE_INVALID`.

## Dot leaders for contents and price lists

Put the label, a [`PdfLeader`]($docs.primitives#pdfleader) and the number in
one `PdfText`. The leader runs on the baseline from the end of the label to
the number, and the number ends at the right edge. A label that wraps keeps
the number on its last line:

```vue
<template>
  <PdfText
    v-for="dish in dishes"
    :key="dish.name"
    class="dish"
  >
    <PdfText class="dish-name">{{ dish.name }}</PdfText>
    <PdfLeader :style="{ borderBottomColor: '#CDD5CF', marginLeft: 7, marginRight: 7 }" />
    <PdfText>{{ dish.price }}</PdfText>
  </PdfText>
</template>

<style>
.dish {
  font-size: 10pt;
}
.dish-name {
  font-weight: bold;
}
</style>
```

Set the font on the outer `PdfText` too. The leader takes the font size of
the text around it for its line height and its em gaps. For a contents, put
a `PdfPageRef` in place of the price, or use
[`PdfContents`]($docs.contents-links-bookmarks), which writes these entries
for you.

## Payment details and QR

Generate the payment payload in setup code, turn consecutive dark QR modules
into one SVG path, and keep the payment panel together with `wrap="false"`.

```vue
<template>
  <PdfView class="payment" :wrap="false">
    <PdfView class="payment-details">
      <PdfText>IBAN {{ payment.iban }}</PdfText>
      <PdfText>BIC {{ payment.bic }}</PdfText>
      <PdfText>Reference {{ invoice.number }}</PdfText>
    </PdfView>
    <PdfSvg :viewBox="`0 0 ${qrSize} ${qrSize}`" class="qr">
      <PdfPath :d="qrPath" fill="#000000" />
    </PdfSvg>
  </PdfView>
</template>

<style>
.payment {
  flex-direction: row;
  margin-top: 20pt;
}
.payment-details {
  flex: 1;
}
.qr {
  width: 72pt;
  height: 72pt;
}
</style>
```

## Keep a heading with what follows

`keepWithNext` moves the heading to the next page when the first lines of the
text after it do not fit. Use `wrap="false"` only when the whole section is
small enough to fit on a page.

```vue
<template>
  <PdfView class="terms">
    <PdfText keep-with-next class="terms-heading">
      Payment terms
    </PdfText>
    <PdfText>{{ terms }}</PdfText>
  </PdfView>
</template>

<style>
.terms {
  margin-top: 24pt;
}
.terms-heading {
  margin-bottom: 10pt;
  font-size: 15pt;
}
</style>
```

## Report sections and a table of contents

Give each section a `bookmark` and put `PdfContents` where the table of
contents goes. It lists the bookmarks with their page numbers, and Nuxt PDF
lays the document out again until every number is stable:

```vue
<template>
  <PdfDocument language="en">
    <PdfPage>
      <PdfText class="section-title" :bookmark="{ title: 'Contents', contents: false }">Contents</PdfText>
      <PdfContents />
      <PdfView v-for="section in sections" :key="section.title" :bookmark="section.title" break>
        <PdfText class="section-title">{{ section.title }}</PdfText>
        <PdfText>{{ section.body }}</PdfText>
      </PdfView>
    </PdfPage>
  </PdfDocument>
</template>

<style>
.section-title {
  font-size: 22pt;
}
</style>
```

The [links and table-of-contents guide]($docs.contents-links-bookmarks)
explains the options, convergence, and a list of your own with `PdfPageRef`.

## Attach a file

Put a `PdfAttachment` inside `PdfDocument` to embed a file in the PDF. It
paints nothing. Pass the content as a string, which Nuxt PDF embeds as UTF-8,
or as bytes:

```vue [pdfs/order.vue]
<script setup lang="ts">
interface Props {
  order: { number: string, total: string }
}

definePdf<Props>({
  filename: props => `order-${props.order.number}.pdf`,
})

const props = defineProps<Props>()

const orderXml = `<?xml version="1.0" encoding="UTF-8"?>
<order number="${props.order.number}">
  <total currency="EUR">${props.order.total}</total>
</order>`
</script>

<template>
  <PdfDocument language="en">
    <PdfAttachment
      name="order.xml"
      type="text/xml"
      relationship="Data"
      description="Order data"
      :data="orderXml"
    />
    <PdfPage>
      <PdfText>Order {{ order.number }}</PdfText>
    </PdfPage>
  </PdfDocument>
</template>
```

- `name` is the file name that PDF viewers show. It must be unique in the
  document and cannot contain a path separator.
- `data` is never read as a path or URL.
- Escape data values before you put them into XML.
- `pdf.limits.maxTotalAttachmentBytes` caps the total size of all attachments in one
  render.

For a Factur-X or ZUGFeRD invoice, use `PdfFacturX` instead of
`PdfAttachment`. See [PDF/A and Factur-X]($docs.pdf-a-and-factur-x).

Use the [testing guide]($docs.testing) to protect document text, links, page
counts, and reviewed raster output.
