Configuration and asset setup can fail before rendering starts. Public render
failures use `NuxtPdfError` and one code from `PDF_ERROR_CODES`.

## Error classes and codes

| Failure | Stage | Inspect or change |
| --- | --- | --- |
| `TypeError` | Module setup | Read the message and correct the module option, template definition, local asset, or configured font. No render or template error code exists yet. |
| `PDF_TEMPLATE_NOT_FOUND` | Render dispatch | Check the template's relative filename and generated registry key. |
| `PDF_TEMPLATE_INVALID` | Template execution | Move `definePdf()` to its supported template scope. In development, a template or component that fails to compile also renders with this code and `source`; correct the file at that position. |
| `PDF_TREE_INVALID` | Vue mount or tree validation | Correct the named root, nesting rule, primitive prop, table structure, page token, attachment, SVG reference, content in a leaf primitive, text placement, PDF/A requirement such as a standard font, tagged PDF rule such as a missing `alt` text or a skipped heading level, `protection` rule such as a missing password or protection with PDF/A, or form field rule such as a duplicate field name, a missing `width` or `height`, a non-WinAnsi value, a rounded or dashed field border, or a field in a PDF/A or tagged document. Messages name a password field, never its value. |
| `PDF_INVOICE_INVALID` | `PdfFacturX` with `invoice`, `renderEInvoiceXml`, `computeEInvoice` | Read `error.issues`: each issue names a rule, the field path, and what to give. Correct those fields. See [E-invoices]($docs.e-invoices#invalid-invoice-data). |
| `PDF_LAYOUT_ERROR` | Layout | Check geometry, fixed content that fills the page, and registered font family, weight, and style. |
| `PDF_LIMIT_EXCEEDED` | Any bounded render stage | Read the named limit and cap. Reduce the input or change that one configured budget. For "Page numbers did not stabilize", see `maxPasses` below. |
| `PDF_ASSET_INVALID` | Image admission | Replace invalid admitted PNG or JPEG bytes, dimensions, or declared format. |
| `PDF_ASSET_BLOCKED` | Image source or request policy | Check the source form, HTTPS allowlist, redirects, and per-hop timeout. |
| `PDF_RENDER_ERROR` | Render | Inspect the attached message and template identity for an uncategorized engine failure. |

`NuxtPdfError` exposes `code`, `templateKey`, and, in development,
`templateFile`. With `PDF_INVOICE_INVALID`, `issues` lists every
`PdfInvoiceIssue` (`rule`, `path`, `message`). Its message names the template. Production leaves out the
relative source path.

## Source positions

In development, an error about one template element and a layout warning
about one node carry `source`, a `PdfSourcePosition`:

| Field | Type | Meaning |
| --- | --- | --- |
| `file` | `string` | Path of the `.vue` file relative to the project root, with forward slashes. |
| `line` | `number` | 1-based line of the element's opening tag. |
| `column` | `number` | 1-based column of the element's opening tag. |

A `PDF_TREE_INVALID` message names the element, such as `<PdfText>`, and its
`id` when it has one, such as `<PdfText id="intro">`. It also names the prop or
style key and the wrong value, so you can find the element in production,
where `source` is absent. A string value longer than 40 characters is cut. The
message never shows a password or the text of a node. Two elements with one
`id` are both named. Find the element by its name and id, and correct the
named prop or key.

`NuxtPdfError.source` is set on `PDF_TREE_INVALID` errors about one node, such
as an invalid prop or a table row with too many cells. Each entry of
`diagnostics.layoutWarnings` is a `PdfLayoutWarning`; its `source` names the
template element of the node that overflows. Production builds and
the `/build` and `/test` entries record no positions, so `source` is absent
there. The [development preview]($docs.errors-and-debugging) shows the
position as a link that opens the editor.

`PDF_LIMIT_EXCEEDED` covers every configured time and resource budget. An
oversized local or remote image uses this code. Allowlist and unsupported-source
policy failures use `PDF_ASSET_BLOCKED`. Invalid bytes that passed the source
policy use `PDF_ASSET_INVALID`.

## Render limits

Every field is an optional positive safe integer. Omitting the `limits` object
or one field keeps the default below. An invalid value or an unknown key throws
`TypeError` during module setup. A key that an earlier version accepted
fails with a message that says what to set instead.

| Field | Default | Bounded work |
| --- | --- | --- |
| `timeoutMs` | `30_000` | The whole render in milliseconds, including the wait for a render worker. |
| `maxPages` | `2_000` | Laid-out page count. |
| `maxNodes` | `50_000` | Mounted document-tree nodes. |
| `maxTotalImageBytes` | `33_554_432` | Encoded image bytes, total per render. |
| `maxTotalImagePixels` | `100_000_000` | Decoded image pixels, total per render. |
| `maxRemoteRequests` | `32` | Remote requests per render, including redirect hops. |
| `maxTotalAttachmentBytes` | `33_554_432` | Bytes of all `PdfAttachment` files and the `PdfFacturX` XML, total per render. |

"Total per render" means the sum over all images or attachments of one render.
An image source that the document uses several times counts once. A single
image is also checked against the whole budget while it loads, so one large
image fails before it is decoded completely. At most four remote requests run
at the same time; this is not configurable.

Configure overrides in `nuxt.config.ts`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  pdf: {
    limits: {
      maxPages: 500,
      timeoutMs: 20_000,
    },
  },
})
```

The timeout is one deadline for the complete render. Layout and serialization
run in a worker thread. At the deadline the worker stops, also in the middle of
a layout step, and the render fails with `PDF_LIMIT_EXCEEDED`. The next render
gets a fresh worker. A production preset that bundles the server into one file
renders in the server process instead (see [Deployment]($docs.deployment)).
There the deadline is checked between engine stages, so one stage can finish
after the deadline before the error is reported.

The timeout covers layout and writing the PDF. Vue runs the template in the
server process. Synchronous code in a template, such as an endless loop in
`setup`, blocks the server process like in any server-rendered component, and
no timeout can stop it.

`maxNodes` is checked after Vue mounts the tree. Image and attachment budgets
apply before the tree goes to the layout engine. `maxPages` is checked after layout.

`maxPasses` is a per-template `definePdf()` option, not a module limit. Its
default is `5`. A document with `PdfPageRef`, an in-flow `pages="first"` node,
or a view that the orphan rule moves normally settles in two passes. Geometry that keeps changing
with the page numbers fails with `PDF_LIMIT_EXCEEDED` and the message "Page
numbers did not stabilize".
