Nuxt PDF renders a closed tree of PDF primitives. It does not render HTML or DOM
components.

## Root and page structure

Each template has one `PdfDocument` root and at least one `PdfPage`:

```vue
<PdfDocument language="en">
  <PdfPage>
    <PdfView>
      <PdfText>Quarterly report</PdfText>
    </PdfView>
  </PdfPage>
</PdfDocument>
```

The main primitives are:

| Primitive | Role |
| --- | --- |
| `PdfDocument` | Document root and metadata |
| `PdfPage` | One fixed or wrapping page |
| `PdfView` | Flex layout container |
| `PdfText` | Text content and inline text runs |
| `PdfImage` | PNG or JPEG image |
| `PdfLink` | External or internal link |
| `PdfNote` | PDF note annotation |
| `PdfTable` | Table with shared column widths and an optional repeated header |
| `PdfPageNumber`, `PdfPageCount`, `PdfPageRef` | Page numbers inside `PdfText` |
| `PdfAttachment` | File embedded in the PDF |
| `PdfTextField`, `PdfCheckbox`, `PdfRadio`, `PdfSelect` | Fillable form fields |
| `PdfRichText` | Rich text from editor HTML, Markdown or a model |

The [primitive reference]($docs.primitives) lists the closed prop and
nesting surface. The [SVG guide]($docs.svg-graphics) covers vector
graphics.

::warning{icon="lucide:triangle-alert"}
Put all visible text inside `PdfText`. Text placed directly under `PdfPage` or
`PdfView` fails with `PDF_TREE_INVALID`; it is not discarded.
::

## Vue composition

Use local Vue components, typed props, slots, `v-if`, and keyed `v-for`. Keep
components owned by one document under a document-specific directory:

```vue [pdfs/components/invoice/InvoiceLine.vue]
<script setup lang="ts">
defineProps<{ label: string; amount: string }>()
</script>

<template>
  <PdfView class="line">
    <PdfText>{{ label }}</PdfText>
    <PdfText>{{ amount }}</PdfText>
  </PdfView>
</template>

<style>
.line {
  flex-direction: row;
  justify-content: space-between;
}
</style>
```

Import the component from the template. Nuxt app plugins, global components,
directives, and app-level provides do not enter the PDF tree.

## Dynamic page text

Put `PdfPageNumber` and `PdfPageCount` inside a `PdfText`. Nuxt PDF prints the
numbers after layout:

```vue
<PdfText fixed>
  Page <PdfPageNumber /> of <PdfPageCount />
</PdfText>
```

`fixed` repeats the node on each page of its parent. A `PdfText` inside a
`fixed` `PdfView` repeats with it and needs no `fixed` of its own. A page token
cannot go into a computed string; put it after the template expression (see
[page tokens]($docs.page-breaking#page-tokens)). Add `pages="first"` or
`pages="continuation"` to a `fixed` node to show it only on the first page or
on every page after the first. Place a running head absolutely in the page padding, so it takes no
space in the flow (see [fixed content and pages]($docs.page-breaking#fixed-content-and-pages)).
For a table of contents, use
[`PdfContents`]($docs.primitives#pdfcontents). The
[contents guide]($docs.contents-links-bookmarks) shows how.

## Running headers

A running header names the chapter or section of the page. Give the
heading `running` with a name, and print the value with `PdfRunningText` in a
`fixed` text:

```vue
<PdfPage size="A4">
  <PdfText fixed class="running-head">
    <PdfRunningText name="chapter" /> · Page <PdfPageNumber />
  </PdfText>
  <PdfView v-for="chapter in chapters" :key="chapter.title" break>
    <PdfText tag="h1" running="chapter">{{ chapter.title }}</PdfText>
    <PdfText v-for="(paragraph, index) in chapter.body" :key="index">{{ paragraph }}</PdfText>
  </PdfView>
</PdfPage>
```

A page shows the value set by the node at its very top, found down through
its containers. Otherwise it shows the last value set before the page. So a
chapter that starts in the middle of a page names the next page, not this
one. Before the first heading with the name, `PdfRunningText` prints nothing.
A value carries over to the next `PdfPage`. A page can show several names,
such as `chapter` and `section`.

`PdfRunningText` works only in a `fixed` node, such as a header or a footer.
A `PdfRunningText` whose name no text in the document sets fails with
`PDF_TREE_INVALID`. When the headings that set it are optional, put the same
`v-if` on the `PdfRunningText`.

The value is the plain text of the heading. For a shorter value, give
`running` an object: `:running="{ name: 'chapter', text: 'Methods' }"`. A long
value wraps like any text. A header in the flow takes the height of its value
on each page, so the content of that page starts lower. A header placed
absolutely in the page padding takes no room, so a value that wraps there can
reach the content. To keep the header on one line, set `maxLines: 1` and
`textOverflow: 'ellipsis'` on the text that prints it.

`at` on `PdfRunningText` picks another value of the page. `at="end"` prints
the last value set on the page, the CSS paged media rule `last`, as a
dictionary head shows its last entry. `at="before"` prints the value the
page starts with, before any setter on it. CSS paged media also has `first`,
the first value set on the page; Nuxt PDF does not offer it.

A `PdfTableRow` sets a value with `:running="{ name, text }"`. With `at`,
that gives a ledger its carried subtotals: see
[Carried subtotals]($docs.recipes#carried-subtotals).

See [page tokens]($docs.page-breaking#page-tokens) for the props and the
failures.

Invalid nesting, unknown primitive props, DOM attributes, `Teleport`, and
`v-show` fail instead of producing incomplete PDF content.
