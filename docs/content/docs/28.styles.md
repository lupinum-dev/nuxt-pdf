`PdfStyle` is Nuxt PDF's framework-owned authoring contract. It
contains the behavior this package tests and supports. You write it in two forms:

- a plain `<style>` block with class selectors, compiled at build time. It
  accepts the kebab-case CSS name of every `PdfStyle` key, a set of
  shorthands, file-local variables, `v-bind()`, and `@import` of local `.css`
  files. It has no cascade, no inheritance rules beyond the ones in the tables
  below, and no selectors other than classes (see
  [The style block](#the-style-block));
- a style object or array on the `style` prop, for values that come from data.

```ts
import type { PdfStyle } from '@lupinum/nuxt-pdf'

const pageStyle = {
  color: '#18251d',
  fontFamily: 'Invoice Sans',
  fontSize: 10,
  paddingHorizontal: 48,
  paddingVertical: 40,
} satisfies PdfStyle
```

Use `satisfies`, not a type assertion. It preserves the object's useful
inferred type while making `vue-tsc` reject unknown keys, invalid enums, and
unsupported units.

`PdfStyle` belongs to page-flow layout and text metrics. SVG paint and geometry
use direct props: `PdfG` and shapes do not accept `style`, `PdfSvg.style` places
the SVG root in page flow, and SVG `PdfText.style` controls text metrics while
its direct `fill` prop controls paint.

## The style block

A PDF template or a local component under `pdfs/` can have plain `<style>`
blocks. Each rule has class selectors and kebab-case declarations. The
compiler turns every rule into a `PdfStyle` object at build time, so an
invalid declaration fails the build, not the render.

```vue [pdfs/invoice.vue]
<script setup lang="ts">
type Props = { invoice: { number: string, overdue: boolean, total: string } }

defineProps<Props>()

definePdf<Props>({
  title: ({ invoice }) => `Invoice ${invoice.number}`,
})
</script>

<template>
  <PdfDocument language="en">
    <PdfPage size="A4" class="page">
      <PdfText class="title">Invoice {{ invoice.number }}</PdfText>
      <PdfText :class="['amount', { overdue: invoice.overdue }]">{{ invoice.total }}</PdfText>
    </PdfPage>
  </PdfDocument>
</template>

<style>
:root {
  --ink: #18251D;
  --accent: #47734F;
  --page-margin: 48pt;
}
.page {
  padding: 44pt var(--page-margin) 54pt;
  font-size: 9pt;
  color: var(--ink);
}
.title, .amount {
  font-size: 18pt;
  font-weight: bold;
}
.overdue {
  color: var(--accent);
  border-bottom: 1pt solid var(--accent);
}
</style>
```

### Accepted CSS

- Selectors: a class (`.title`), a compound of classes (`.row.total`), or
  classes separated by spaces (`.total .cell`). A selector list such as
  `.title, .amount` is accepted. The Selectors section below gives the matching
  rules and the selectors that fail.
- Properties: the kebab-case name of a `PdfStyle` key (`font-size` for
  `fontSize`), plus the shorthands below. Each value follows the rules of its
  key in the tables on this page.
- At-rules: only `@import` (see Imported files below).
- Not accepted: other at-rules such as `@media` and `@font-face` (register
  fonts with `pdf.fonts`), nested rules, declarations outside a rule,
  `!important`, and the attributes `scoped`, `module`, `lang`, and `src` on the
  block.

| Shorthand | Values | Expands to |
| --------- | ------ | ---------- |
| `margin`, `padding` | One to four values in CSS order (top, right, bottom, left): lengths, percentages or `em` lengths, and `auto` for `margin` | The four side keys |
| `border-width`, `border-color`, `border-style` | One to four values, in CSS order | The four side keys |
| `border-radius` | One to four lengths or percentages (top left, top right, bottom right, bottom left) | The four corner keys |
| `border`, `border-top`, `border-right`, `border-bottom`, `border-left` | A width, a color, and optionally a style, in any order, such as `1pt solid #CCCCCC` | Width, style, and color of each side |
| `gap` | One or two lengths: the row gap, then the column gap. One value sets both. | `gap`, such as `gap: 4pt 8pt` |
| `columns` | A column count, a column width, or both, in either order, such as `2 120pt` | `column-count` and `column-width` |
| `column-rule` | A width, a color, and optionally a style, in any order, such as `0.5pt dotted #999999` | `column-rule-width`, `column-rule-style`, and `column-rule-color` |
| `flex` | A number `n` | `flex-grow: n`, `flex-shrink: 1`, `flex-basis: 0` |
| `flex` | `auto` or `none` | `1 1 auto` or `0 0 auto` |
| `flex` | Three values: grow, shrink, basis | The three flex keys |

`margin-horizontal`, `margin-vertical`, `padding-horizontal`, and
`padding-vertical` take one value, as the `PdfStyle` keys do. The `border`
shorthands and `column-rule` need a width and a color. Without a style they write `solid`, which
is the style the PDF engine paints. A browser paints no border for
`border: 1pt #CCCCCC`; a PDF template paints a solid one. Because the
shorthand writes the style, it replaces a style that an earlier rule set, as a
CSS shorthand does.

Units are the same as for `PdfLength`: a plain number is a PDF point, and
`pt`, `px`, `in`, `mm`, `cm`, `rem`, `vh`, and `vw` are kept as written.
Percentages are accepted where the key accepts them, and `em` where the key
takes a `PdfEmLength` (see [Values and units](#values-and-units)). `ex`,
`ch`, `vmin`, and `vmax`, and `em` on other keys, fail the build with a message
that names the unit. Colors take
the forms in [Colors](#colors); another form fails the build. A font family is
one family name, with or without quotes. A rotation or skew angle in
`transform` needs `deg` or `rad`.

A `class` on `<template>` or `<slot>` fails the build, because neither renders
an element; put the class on the component inside it.

### Selectors

A selector is made of class names only:

| Selector | Matches |
| -------- | ------- |
| `.total` | An element with the class `total`. |
| `.row.total` | An element with both classes `row` and `total`. |
| `.total .cell` | An element with the class `cell` inside an element with the class `total`. |
| `.ledger .row.total .cell` | Any mix of the two forms. |

```vue [pdfs/components/Ledger.vue]
<script setup lang="ts">
defineProps<{ rows: { id: string, kind: string, label: string }[] }>()
</script>

<template>
  <PdfView class="ledger">
    <PdfView v-for="row in rows" :key="row.id" :class="['row', row.kind]">
      <PdfText class="cell">{{ row.label }}</PdfText>
    </PdfView>
  </PdfView>
</template>

<style>
.cell { padding: 2pt 0 }
.row.total { font-weight: bold }
.total .cell { border-top: 1pt solid #18251D }
.ledger .total .cell { padding-top: 6pt }
</style>
```

A descendant selector matches lexically: it tests the elements that enclose
the element in the template of the same file. The enclosing element can carry
a static `class` or a dynamic `:class`, and elements without a class between
them do not matter. The selector does not see elements of another component:
a class on the parent component's element does not match a descendant step
inside a local component, and the reverse.

Every other selector fails the build at the rule. The message names the
selector and ends with `Use class selectors: .a, .a.b or .a .b.`:

| Selector | Example |
| -------- | ------- |
| Type selector | `PdfText`, `p`, `.row PdfText` |
| Child or sibling combinator | `.a > .b`, `.a + .b`, `.a ~ .b` |
| Pseudo-class or pseudo-element | `.cell:first-child`, `.cell::before` |
| Attribute, id, universal, or nesting selector | `[data-x]`, `#total`, `*`, `&` |

### Class order and precedence

- A rule whose selector has more classes wins over a rule with fewer classes
  for the same key, as CSS specificity does. `.total .cell` and `.row.total`
  count two classes, `.cell` counts one.
- Between rules with the same number of classes, the order of the `<style>`
  block decides, not the order of the names in `class`. A later rule wins.
- For a rule with a selector list, the matching selector with the most classes
  counts.
- `style` and `:style` apply after all classes, so a style object wins over
  every class.
- `class` and `:class` take the forms Vue accepts: a string, an array, or an
  object. Static names and the literal names in `:class` are checked at build
  time. A dynamic name that no rule defines fails the render with
  `PDF_TREE_INVALID`: `Unknown PDF class "x" in <Invoice>. Define .x in the <style> block of that file.`

### Classes in components

Classes are local to the file that uses them. A class in a template must be
defined in the `<style>` block of that same file.

- A local component uses the classes of its own file.
- A class that a parent sets on a local component uses the parent's rules
  and applies to the root element of that component, as Vue passes any
  fallthrough attribute. A component with several root elements fails with
  `A class on <Name> needs a single root element in that component, or
  v-bind="$attrs" on one element.` A component with `inheritAttrs: false`
  drops the class unless it binds `$attrs`.
- `PdfTable`, `PdfTableHeader`, `PdfTableRow`, and `PdfTableCell` take `class`
  like a primitive.
- Primitives without a `style` prop, such as the SVG shapes, cannot take a
  class.

### Variables

Declare variables in a `:root` rule and read them with `var()`:

```vue
<template>
  <PdfText class="label">Total</PdfText>
</template>

<style>
:root {
  --muted: #758078;
  --label: var(--muted);
}
.label {
  color: var(--label);
}
</style>
```

Variables are substituted as text at build time, and the result is checked
like a written value. They are local to the file and the files it imports;
all `<style>` blocks of one file share them, and a later declaration of a name
wins. `var()` takes one name and no fallback. To read a script value, use
`v-bind()`. `var()` inside a quoted string stays as written. A value can be at
most 10,000 characters long after its variables are substituted.

### Values from the script

`v-bind()` reads a value from the template's script, as in Vue single-file
components. Use it to keep one source for a value that the style block and the
script both need, such as a color that a chart also draws.

The recommended pattern is a TypeScript module with the shared tokens. The
template imports it, and a `:root` variable binds each token once:

```ts [pdfs/components/theme.ts]
export const ink = {
  strong: '#1A2620',
  muted: '#8A938C',
} as const

export const accent = '#315D3B'
```

```vue [pdfs/report.vue]
<script setup lang="ts">
import { accent, ink } from './components/theme'

definePdf({ title: 'Report' })
</script>

<template>
  <PdfDocument language="en">
    <PdfPage class="page">
      <PdfText class="title">Annual report</PdfText>
      <PdfSvg :width="120" :height="4" view-box="0 0 120 4">
        <PdfRect :width="120" :height="4" :fill="accent" />
      </PdfSvg>
    </PdfPage>
  </PdfDocument>
</template>

<style>
:root {
  --ink: v-bind('ink.strong');
  --muted: v-bind('ink.muted');
  --accent: v-bind(accent);
}
.page { color: var(--ink); padding: 40pt }
.title { color: var(--accent); border-bottom: 1pt solid var(--muted) }
</style>
```

- Write `v-bind(name)`, `v-bind('expression')`, or `v-bind("expression")`. The
  expression is one JavaScript expression. It can read a `<script setup>`
  binding, an import, or a prop (`v-bind('props.size')`).
- `v-bind()` is a whole value: a number is a PDF point, and a string reaches
  the engine as written. The render accepts a string that the engine reads
  correctly, which includes every value of the `<style>` block grammar (see
  [Style object values](#style-object-values)). Write keywords in lower case
  and a font family without quotes. `v-bind(gap)pt` fails; put the unit into
  the bound value, such as `'12pt'`.
- The render checks every bound value. An invalid value fails with
  `PDF_TREE_INVALID`, and the message names the expression, the property, the
  value, and the expected form:
  `v-bind(props.size) for "font-size" gave "banana": expected a number of points, a length such as 12pt, or a percentage.`
- A bound value of `null` or `undefined` leaves the key out. Any other value
  that is not a string or a number, such as `false`, fails.
- In a box shorthand (`margin`, `padding`, `border-width`, `border-color`,
  `border-style`, `border-radius`), each bound part sets its sides:
  `padding: 4pt v-bind(gutter)` binds the right and left padding.
- In a `border` shorthand, write the other two parts:
  `border-bottom: 1pt solid v-bind(color)` binds the color. Use the longhands
  to bind more than one part.
- `flex` with `v-bind()` needs all three parts, such as `v-bind(grow) 1 0`.
- `gap` with `v-bind()` takes one bound value for the whole gap. To bind both
  gaps, bind one string such as `'4pt 8pt'`.
- A `v-for` alias or slot prop with the name that a `v-bind()` reads fails the
  build on the element where it hides the script value. Rename the alias.
- `v-bind()` in an imported `.css` file fails, because that file has no
  script. Declare the variable in `:root` of the template that imports it.

### Imported files

`@import` reads the rules and `:root` variables of a local `.css` file. Use it
to share one set of variables between templates:

```css [pdfs/theme.css]
:root {
  --ink: #18251D;
  --accent: #47734F;
}
.label { color: var(--accent) }
```

```vue [pdfs/letter.vue]
<script setup lang="ts">
definePdf({ title: 'Letter' })
</script>

<template>
  <PdfDocument language="en">
    <PdfPage>
      <PdfText class="label">Reference</PdfText>
      <PdfText class="body">Text</PdfText>
    </PdfPage>
  </PdfDocument>
</template>

<style>
@import './theme.css';
.body { color: var(--ink) }
</style>
```

- Write the path in quotes. It is relative to the importing file, or starts
  with a Nuxt alias. `pdfs/` is in the project root, so use `~~`:
  `@import '~~/pdfs/theme.css'`. A standalone build and `renderPdfSfc` from
  `@lupinum/nuxt-pdf/test` accept relative paths only, so write
  `@import './theme.css'` in a template that you test with `renderPdfSfc`.
- The file must end in `.css` and lie inside the project directory. A symbolic
  link that points outside the project fails.
- Put every `@import` before the first rule of the block. Media queries,
  layers, `url()`, and remote URLs fail.
- An imported file can import other files. A file that imports itself fails
  and the message shows the chain.
- Imported rules come before the rules of the importing file, so the importing
  file wins between rules with the same number of classes. The same is true
  for variables.
- A file that the block reaches twice counts at its last place, as in a
  browser. If `b.css` imports `c.css` and the block then imports `c.css`
  again, the rules of `c.css` win over those of `b.css`.
- `nuxt dev` compiles the template again when an imported file changes, and
  when a missing imported file is created.
- An error in an imported file names that file, its line, and its column.

### Build errors

Every rejected declaration, selector, or class fails the build with the file,
line, and column of the cause:

```text
[nuxt-pdf] /app/pdfs/invoice.vue:24:10 Invalid value "bleu" for "color": expected a hex color (#rgb, #rgba, #rrggbb or #rrggbbaa), rgb(), hsl(), hwb(), a color name or transparent.
```

| Message | Inspect or change |
| ------- | ----------------- |
| `Type selector "PdfText" is not supported in PDF styles; found "PdfText". Use class selectors: .a, .a.b or .a .b.` | Replace the selector with a class and set that class on the element. |
| `@media is not supported in PDF styles.` | Remove the at-rule. Register fonts with `pdf.fonts`. |
| `@import must come before every rule of the style block.` | Move the `@import` to the top of the block. |
| `@import cannot find "./theme.css" (resolved to pdfs/theme.css).` | Correct the path. It is relative to the file that imports it. |
| `@import takes a path relative to this file or one that starts with an alias, such as ./theme.css or ~~/pdfs/theme.css; found "theme.css".` | Write `./theme.css` or `~~/pdfs/theme.css`. A standalone build and `renderPdfSfc` know no alias: write the relative path there. |
| `@import "../../shared.css" leaves the project directory.` | Move the file into the project. |
| `v-bind() must be a whole value.` | Put the unit into the bound value. |
| `v-bind() is not allowed in an imported file` | Bind the value in `:root` of the importing template. |
| `Nested rules are not supported in PDF styles` | Write each rule at the top level. |
| `Declarations must be inside a class rule in PDF styles` | Move the declaration into a class rule. |
| `!important is not supported in PDF styles` | Remove `!important`. Use `style` to win over classes. |
| `Unsupported PDF style property "fontSize". Use kebab-case "font-size".` | Write the property in kebab-case. |
| `Unsupported PDF style property "background". Use background-color.` | Use a property from the tables on this page. |
| `Invalid value … expected …` | Write a value of the expected form. |
| `Unknown variable "--x"` | Declare the variable in `:root` of the same file. |
| `var() takes one variable name` | Remove the fallback value. |
| `Variable "--a" refers to itself.` | Remove the cycle between the variables. |
| `Declare variables in a :root rule.` or `:root holds variables only` | Keep variables in `:root` and properties in class rules. |
| `Class "x" is not defined in the <style> block of this file.` | Define the class in the file that uses it. |
| `<PdfRect> has no style, so it cannot take a class.` | Set SVG paint with direct props. |
| `<style scoped> is not supported in PDF components.` | Remove the attribute. |

## Values and units

| Type | Accepted values | Notes |
| ---- | --------------- | ----- |
| `PdfLength` | A number, or `pt`, `px`, `in`, `mm`, `cm`, `rem`, `vh`, or `vw` (for example `12`, `'12pt'`, `'4mm'`) | A unitless number is a PDF point. `px` is `n × 72 / dpi` points at the page DPI (default 72), not rounded. |
| `PdfPercentage` | A numeric percentage string such as `'50%'` | Accepted only by properties whose type includes percentages. |
| `PdfEmLength` | A number with `em`, such as `'1.5em'` | A share of the node's own font size, as in CSS: `'1.5em'` in a text of 10 pt is 15 pt. Accepted by `width`, the margins, the paddings, `gap`, `rowGap`, and `columnGap`, and their shorthands. Other keys reject it: heights are read before font sizes are known, border widths do not grow with the text, and a percentage `fontSize` and a unitless `lineHeight` already scale. |
| Color | A color string such as `'#18251d'`, `'rgb(24, 37, 29)'`, or `'red'` | The forms are in [Colors](#colors). There is no global cascade. Variables exist only in the `<style>` block. |
| Enum | One of the literals listed below | Browser-only values are rejected even when a similarly named CSS property exists. |

`rem` is the page's font size, as CSS takes the root element's: `'2rem'` on a
`PdfPage` with `fontSize: 10` is 20 pt. A page without a `fontSize` gives the
default, 18 pt. `vw` and `vh` resolve against the PDF
page container, not a browser window. Percentages resolve against the relevant
parent dimension.

`ch`, `ex`, `calc()`, container queries, and arbitrary CSS strings are not
part of the contract. `var()` works only in the `<style>` block.

## Colors

Every color takes the same forms: in a style object, a `v-bind()` value, the
`<style>` block, and the SVG paint props.

| Form | Examples | Alpha |
| ---- | -------- | ----- |
| Hex | `#1a2`, `#18251d`, `#1a28`, `#18251d80` | The fourth digit, or the last two |
| `rgb()`, `rgba()` | `rgb(24, 37, 29)`, `rgb(24 37 29 / 50%)`, `rgb(10%, 20%, 30%)` | After a comma or a slash, a number or a percentage |
| `hsl()`, `hsla()` | `hsl(140, 20%, 12%)`, `hsl(140deg 20% 12% / 0.5)` | After a comma or a slash, a number |
| `hwb()` | `hwb(140 10% 80%)`, `hwb(140 10% 80% 0.5)` | A fourth number |
| A color name, in any case | `red`, `Navy`, `rebeccapurple` | None |
| `transparent` | `transparent` | 0 |

These keys and props take a color: `backgroundColor`, `color`,
`textDecorationColor`, `columnRuleColor`, every border color, and the SVG `fill`, `stroke`, and
`stopColor`. A color's alpha multiplies the opacity that applies to it, as in
CSS: `backgroundColor: 'rgba(0, 0, 0, 0.5)'` with `opacity: 0.5` paints at
25 %. In SVG, the alpha multiplies `fillOpacity`, `strokeOpacity`, or
`stopOpacity`.

A form field takes opaque colors only, because a field draws its colors
without alpha; a color with alpha fails with `PDF_TREE_INVALID`. Any other
form, such as `currentColor`, `hsl(120, 50, 50)` without `%`, `hwb()` without a
hue, or a misspelled name, fails with `PDF_TREE_INVALID`, and at build time in the `<style>` block.

## Style object values

A `:style` value and a `v-bind()` value go to the engine as written. The
render checks each one and rejects only a value that the engine cannot read
correctly. So these values pass in a style object, although the `<style>`
block grammar is narrower and rejects them:

- `'auto'` for `width`, `height`, the minimum and maximum sizes, and `top`,
  `right`, `bottom`, and `left`.
- One to four values for `margin` and `padding`, such as `margin: '4pt 8pt'`,
  and one or two values for `marginHorizontal`, `marginVertical`,
  `paddingHorizontal`, and `paddingVertical`. With two values, `…Vertical`
  sets the top, then the bottom, and `…Horizontal` the right, then the left.
  `auto` works in margins only.
- The `flex` shorthand: `'auto'`, `'none'`, `'initial'`, or grow, shrink, and
  basis, such as `'1 0 30%'`. Write the shrink factor before the basis:
  `flex: '1 30pt'` fails, because the engine reads `30pt` as the shrink factor.
- In `transform`: a `px` or `pt` unit in a translation, an angle without a
  unit (degrees), and any number of operations.
- A font weight name in any case, such as `'Bold'`.

A value that the engine would misread fails with `PDF_TREE_INVALID`, for
example `fontSize: '1.2em'`, `color: 'currentColor'`, `lineHeight: 'normal'`,
`textAlign: 'Center'`, `translate(10mm, 0)`, `matrix()`, or `false`. The
message names the key, the value, and the expected form, which describes the
`<style>` block grammar.

## Negative values

Sizes, spacing inside a box, and opacity have a range. A value outside it fails
with `PDF_TREE_INVALID` in a style object, a `v-bind()` value, and the
`<style>` block, which fails at build time:

- These keys must be 0 or more: `width`, `height`, `minWidth`, `minHeight`,
  `maxWidth`, `maxHeight`, `flexBasis`, `flexGrow`, `flexShrink`, `gap`,
  `rowGap`, `columnWidth`, `columnGap`, every `padding` key, every border width and
  radius.
  Each part of a shorthand counts, so `padding: '4pt -2pt'` fails.
- `fontSize` and `lineHeight` must be above 0, so `fontSize: 0` fails. To
  hide a text, leave it out of the template with `v-if`.
- Each number in the `flex` shorthand must be 0 or more, so `flex: -1` and
  `flex: '1 -1 0'` fail. `'auto'`, `'none'`, and `'initial'` stay valid.
- `maxLines` and `columnCount` must be a whole number of 1 or more, and so
  must the count in `columns`.
- `opacity` must be from 0 to 1.
- These keys can be negative: every `margin` key, `top`, `right`, `bottom`,
  `left`, `letterSpacing`, and `transform`. Use a negative margin to pull an
  element over its neighbor.

The message names the element,
the key, and the value, for example
`<PdfText> :style value -4 for "fontSize" is invalid: expected a value above 0.`

## Dimensions and positioning

These keys are valid on page-flow primitives (`PdfPage`, `PdfView`, `PdfText`,
`PdfImage`, `PdfLink`, and `PdfNote`). `width` and `height` also size `PdfSvg`
inside page flow.

| Property | Accepted value | Inherited | Behavior |
| -------- | -------------- | --------- | --------------------- |
| `width`, `height` | `PdfLength \| PdfPercentage`, and `PdfEmLength` for `width` | No | Sets the resolved box size. |
| `minWidth`, `minHeight`, `maxWidth`, `maxHeight` | `PdfLength \| PdfPercentage` | No | Constrains the resolved box size. |
| `position` | `'relative' \| 'absolute' \| 'static'` | No | `'static'` keeps the node in the flow and ignores `top`, `right`, `bottom` and `left`. Use the component `fixed` prop to repeat content across pages; browser `fixed` is not accepted. |
| `top`, `right`, `bottom`, `left` | `PdfLength \| PdfPercentage` | No | Offsets a positioned node. |

A percentage `height`, `minHeight` or `maxHeight` is a share of the parent's
height inside its paddings and borders. The layout turns it into points
before it breaks the pages, so every part of a node that breaks keeps the
same height. The parent must have a height that is known before layout: a
height in points, a percentage of a parent with one, or the `PdfPage`, whose
share is its height inside its paddings. Otherwise the render fails with
`PDF_TREE_INVALID`. Give the parent a height, or give the node its height in
points. An absolute node takes its percentage from its parent's box, as in
CSS, and needs no such parent.

An absolute node takes no room in the flow and never breaks across pages. It
prints on one page:

- A node placed by `top`, or without `top` and `bottom`, prints on the first
  page of its parent. With `justifyContent` `center`, `space-around` or
  `space-evenly`, it is centered on that page.
- A node placed by `bottom` alone prints on the last page of its parent. So
  does a node without `top` and `bottom` in a column with
  `justifyContent: 'flex-end'`, or in a row that aligns it to the end.
- An absolute node with the `fixed` prop on a `PdfPage` prints on every page.

The parent is the view or row around the node, or the `PdfPage` for a node at
page level. When the parent breaks across pages, its parts count as one tall
parent: a node that `top` places below the part on a page prints on the part
where its offset lands. A percentage inset is a share of the whole parent's
height inside its borders, before it breaks. An absolute node that still
reaches below the page end is cut there and gives the `PDF_CONTENT_HIDDEN`
warning. Move it up, or give it `bottom` in place of `top`.

A relative `top` or `bottom` moves the node and does not move the content
around it. The page end applies to the moved node: a node that `top` moves
below the page end goes to the next page. When the node breaks across pages,
every part keeps the offset. A percentage is a share of the whole parent's
height inside its paddings.

## Flex layout

Flex properties primarily belong on `PdfPage` and `PdfView`. Text, links,
images, notes, and SVGs can be flex items. The engine defaults to a `column`
direction.

| Property | Accepted value | Inherited | Behavior |
| -------- | -------------- | --------- | --------------------- |
| `flexDirection` | `'row' \| 'row-reverse' \| 'column' \| 'column-reverse'` | No | Controls the main axis. The default is `column`. |
| `flex`, `flexGrow`, `flexShrink` | `number` | No | Controls available-space growth and shrinkage. |
| `flexBasis` | `PdfLength \| PdfPercentage \| 'auto'` | No | Sets the initial main-axis size. |
| `flexWrap` | `'nowrap' \| 'wrap' \| 'wrap-reverse'` | No | Controls flex-line wrapping. A column without a `height` has one line, also when it breaks across pages. On a column `PdfPage` that breaks, it fails with `PDF_TREE_INVALID`: use `columnCount` for text in columns. A view with a `height` or `maxHeight` that wraps moves whole to the next page; higher than a page, it fails with `PDF_LAYOUT_ERROR`. A row that wraps breaks between its lines; see [Fixed content and pages]($docs.page-breaking#fixed-content-and-pages). |
| `alignItems` | `'flex-start' \| 'flex-end' \| 'center' \| 'stretch' \| 'baseline'` | No | Aligns children on the cross axis. |
| `alignSelf` | `'auto' \| 'flex-start' \| 'flex-end' \| 'center' \| 'stretch' \| 'baseline'` | No | Aligns this node on its parent's cross axis. `'auto'`, the default, takes the parent's `alignItems`. |
| `justifyContent` | `'flex-start' \| 'flex-end' \| 'center' \| 'space-between' \| 'space-around' \| 'space-evenly'` | No | Distributes children on the main axis. |
| `alignContent` | `'flex-start' \| 'flex-end' \| 'center' \| 'stretch' \| 'space-between' \| 'space-around' \| 'space-evenly'` | No | Places the lines of a wrapping container on the cross axis. `'baseline'` fails with `PDF_TREE_INVALID`: the layout would place it as `'flex-start'`. |
| `gap` | `PdfLength \| PdfEmLength`, or two such lengths such as `'4pt 8pt'` | No | Adds space between flex children. Two values are the row gap, then the column gap; one value sets both. |
| `rowGap` | `PdfLength \| PdfEmLength` | No | The space between the rows: between the children of a column, or between the lines of a wrapping row. A percentage is not accepted. |

There is no grid, browser block layout, side floats (CSS `float: left` and
`right`) or CSS cascade. `float` places a node at the top or the bottom of its
area instead; see [Floats](#floats).

In a column that breaks across pages, `flexGrow`, `justifyContent` and a
vertical `margin` of `'auto'` use the room each page leaves:

- On a page, the room below the content goes to the children with `flexGrow`,
  by their factors. A child with a `maxHeight` stops at it, and the others
  share the rest. On a full page, this is only the room below the last line
  that fits.
- When no child grows, `justifyContent` spaces the content of each page in
  that room. Fixed headers and footers move with the content.
- When no child grows, a `marginTop` or `marginBottom` of `'auto'` takes
  that room, and several auto margins share it equally. `justifyContent` then
  does nothing. On a full page, this is only the room below the last line
  that fits. In a row, an auto margin on a cell only moves the cell up or
  down in its row.
- In a view, the room that its `minHeight` or the height of its row leaves is
  shared. A part of a view that ends at a page end shares the room below its
  last line. Elsewhere a view is as high as its content and has no room to
  share.
- A container with `flexDirection: 'column-reverse'` draws its last child at
  the top, so it breaks in that order: the first page holds its last
  children. A `row-reverse` row breaks as a row.
- A view or a text with a `minHeight` in points that breaks across pages
  fills the room to the page end, up to its `minHeight`. The next part is at
  least as high as the rest of the `minHeight`. A text breaks by its lines.
- A view that breaks across pages first places its children in its whole
  height, with that spacing, and breaks where those places cross the page end.
  Each part then spaces its own children in its own height. A view with
  `justifyContent: 'flex-end'` and a `minHeight` whose content starts below
  the page end moves whole to the next page.
- A row does not leave a cell behind. When a cell that starts before the
  page or column end moves after it by its own rules, such as a text whose
  orphans do not fit, the whole row moves.
- In a row that breaks across pages, a cell that does not stretch
  (`alignSelf` or the row's `alignItems` set to `flex-start`, `center`,
  `flex-end` or `baseline`) breaks where its place in the whole row puts its
  lines. Each part of the row then aligns the cell again. A part of the row
  ends at the page end, so a cell aligned to the center or the end of a part
  sits by the room below the last line lower than its lines alone would put
  it.

## Columns

A `PdfView` or a `PdfPage` with `columnCount` or `columnWidth` lays its
children out in columns. On the page where the container's content ends, the
columns are balanced, as in CSS: they get about the same height, and the
content after the container follows below the highest column. On the pages
before, a column ends at the page end, and the content goes on at the top of
the next column, then in the first column of the next page.

| Property | Accepted value | Inherited | Behavior |
| -------- | -------------- | --------- | --------------------- |
| `columnCount` | A whole `number` of 1 or more | No | The number of columns. |
| `columnWidth` | `PdfLength` | No | The least column width: as many columns as fit, at most `columnCount`. |
| `columns` | `number`, a length with a unit, or both, such as `'2 120pt'` | No | Sets `columnCount`, `columnWidth`, or both. A number is the count; a width needs a unit. The one it does not set is reset, as in CSS. |
| `columnGap` | `PdfLength \| PdfEmLength \| 'normal'` | No | The space between the columns. Without it, or with `'normal'`, the gap is 1em of the container's font size. |
| `columnFill` | `'auto' \| 'balance'` | No | `'balance'` (the default) balances the columns on the page where the content ends. `'auto'` fills them in order to the page end there too. |
| `columnSpan` | `'none' \| 'all'` | No | `'all'` on a direct child of the container places it across all columns. Without a column container above it, it has no effect, as in CSS. |
| `columnRuleWidth` | `PdfLength` | No | The width of the rule between the columns. Without a width above 0 there is no rule. |
| `columnRuleStyle` | `'solid' \| 'dashed' \| 'dotted'` | No | The style of the rule, as for borders. The default is `'solid'`. |
| `columnRuleColor` | color string | No | The color of the rule. The default is black. |

The container's `gap` or `rowGap` spaces its children in each column.

A column rule is a line in the middle of each gap between two columns that
hold content. It runs from the top of the columns to the bottom of the
highest one. On a container with a `height`, it runs to the bottom of the
container's content box. A child with `columnSpan: 'all'` interrupts it, and
on a page with columns it stops above the footnotes. In a tagged document the
rule is an artifact, not content. In a `<style>` block, the `column-rule`
shorthand takes the same parts as `border`:

```vue
<template>
  <PdfView class="article">
    <PdfText v-for="paragraph in paragraphs" :key="paragraph">{{ paragraph }}</PdfText>
  </PdfView>
</template>

<style>
.article {
  columns: 2;
  column-gap: 18pt;
  column-rule: 0.5pt dotted #999999;
}
</style>
```

On a `PdfView` or `PdfPage` without columns, the rule has no effect, as in
CSS, so a template can switch its columns off and keep the rule.

For running text, balanced columns differ by at most a line. A block that
cannot split stays whole in one column, so blocks, table rows and keep rules
can make one column higher. A container with a `height` or `maxHeight` fills its
columns to that height: balanced, or in order with `columnFill: 'auto'`. Like
any view with a height, such a container moves whole to the next page when it
fits the page and crosses the page end. A container higher than the page
splits at the page ends: its parts share its height, and only the last part
is balanced.

`break="column"` on a node in a column starts the next column. In the last
column, and in a container with `columnCount: 1`, it starts the next page.
See [Page breaks]($docs.page-breaking#page-breaks).

On a `PdfPage`, the column properties go to the columns, and so do `gap` and
`alignItems`, which space and place the children in each column. So the flow
of a page with columns lays out as the children of a `PdfView` with the same
style. The page keeps its padding and other styles, and its `fixed` and
absolute children: a fixed header or footer stays as wide as the page, and an
absolute child keeps its offsets against the page.

Each of these fails with `PDF_TREE_INVALID`, because the layout would ignore
it or change it:

- `columnCount`, `columnWidth` or `columns` on a primitive other than
  `PdfView` and `PdfPage`, such as `PdfText`. Put the content into a
  `PdfView` with the columns.
- A column container that is `fixed` or absolute, or inside such a node. Move
  the view into the page flow.
- A column container with a `flexDirection` other than `'column'`: each
  column fills from top to bottom.
- `break="column"` outside a column: not inside a column container, or inside
  a child with `columnSpan: 'all'`. Use `break` for a new page.
- `columnSpan: 'all'` on a node in a column that is not a direct child of
  its column container, or on a `fixed` child of a `PdfPage` with columns,
  which is full width already.
- A percentage `height`, `minHeight` or `maxHeight` on a direct child of a
  column container, in a column or with `columnSpan: 'all'`: it would be a
  share of the room the columns get on a page, not of the container, so the
  child and the content after the columns would be placed wrong. Give the
  child a height in points, or remove it. An absolute child, a fixed child of
  a `PdfPage` with columns, and a child further down take their percentage
  as elsewhere.
- `columnFill: 'balance-all'`.
- `columnRuleWidth`, `columnRuleStyle` or `columnRuleColor` on a primitive
  other than `PdfView` and `PdfPage`. Put the rule on the column container,
  or use a border.

These fail with `PDF_LAYOUT_ERROR`:

- A column container in a column of another. Give the inner view
  `columnSpan: 'all'` to place it across the outer columns, or remove its
  columns.
- A column container with a `height` or `maxHeight` whose content needs more
  columns than it has at that height. Remove the height, or make the content
  lower.

## Floats

A node with `float` leaves the flow and moves to the top or the bottom of its
area: the column it stands in, the part of its column container on the page
when it has `columnSpan: 'all'`, or the page content area without columns. It
works like `[t]` and `[b]` for a figure in LaTeX. Use it for figures and
tables that can move away from the text that refers to them.

| Property | Accepted value | Inherited | Behavior |
| -------- | -------------- | --------- | --------------------- |
| `float` | `'none' \| 'top' \| 'bottom'` | No | `'top'` places the node at the top of its area, below fixed content there. `'bottom'` places it at the bottom, above the footnotes and a fixed footer. `'none'` (the default) keeps it in the flow. |

The [page-breaking guide]($docs.page-breaking#floats) shows floats in
columns and says how the layout places them. In `PdfRichText`, `float` in
`styles.image` floats every image and figure of the content.

A plain view has column direction, no `height`, `minHeight`, `maxHeight` or
`flexGrow`, no `justifyContent` other than `'flex-start'`, and is not
`fixed`, absolute, a `PdfLink`, a table part or `wrap={false}`.

Each of these fails with `PDF_TREE_INVALID`:

- `float` on a primitive other than `PdfView`, `PdfImage`, `PdfSvg` and
  `PdfTable`. Put the content into a `PdfView` with `float`.
- A float inside a view that is not plain, inside another float, or on a
  `PdfPage` with `wrap={false}` or a `justifyContent` other than
  `'flex-start'`.
- A rich text image in a list item with `float` in `styles.image`: the item's
  content stands beside its marker, so the image cannot float out of it. The
  message names the image's content path. Remove `float` from `styles.image`,
  or move the image out of the list.
- A float with `break`, `keepWithNext` or `minPresenceAhead`, a float that is
  `fixed` or absolute, and a float with columns.

A float higher than the most room its area gets on a page, or than the
`height` of its column container, fails with `PDF_LAYOUT_ERROR`. Make it
lower, or remove `float` so it breaks with the flow. A column container with
a `height` whose content and floats need more than its columns hold fails as
without floats.

## Box model

The box model is valid on page-flow primitives. Percentages resolve through
the engine's PDF layout container, not a browser viewport.

| Property | Accepted value | Inherited | Behavior |
| -------- | -------------- | --------- | --------------------- |
| `margin`, `marginHorizontal`, `marginVertical`, `marginTop`, `marginRight`, `marginBottom`, `marginLeft` | `PdfLength \| PdfPercentage \| PdfEmLength \| 'auto'` | No | Sets space outside the box. |
| `padding`, `paddingHorizontal`, `paddingVertical`, `paddingTop`, `paddingRight`, `paddingBottom`, `paddingLeft` | `PdfLength \| PdfPercentage \| PdfEmLength` | No | Sets space inside the box. Padding does not accept `auto`. |

## Borders and paint

| Property | Accepted value | Inherited | Behavior |
| -------- | -------------- | --------- | --------------------------- |
| `backgroundColor` | color string | Only through nested `PdfText` runs | Paints the page-flow box background. On a nested `PdfText`, paints its glyph height (ascent to descent), not its line height, as in CSS. |
| `color` | color string | Yes | Sets text color on text-bearing primitives. |
| `opacity` | `number` | Yes | Sets node opacity. Limit: it applies to each box, not to a group as in CSS. Children inherit the value and each paints at it on its own, so a child text over its parent's background shows that background through it. A child's own `opacity` replaces the inherited value; it does not multiply it. |
| `borderWidth`, `borderTopWidth`, `borderRightWidth`, `borderBottomWidth`, `borderLeftWidth` | `PdfLength` | No | Sets all or individual border widths. |
| `borderColor`, `borderTopColor`, `borderRightColor`, `borderBottomColor`, `borderLeftColor` | color string | No | Sets all or individual border colors. The default is black, not the text color. |
| `borderStyle`, `borderTopStyle`, `borderRightStyle`, `borderBottomStyle`, `borderLeftStyle` | `'solid' \| 'dashed' \| 'dotted'` | No | Sets all or individual border styles. The default is `'solid'`: a border width alone paints a solid black border. |
| `borderRadius` | `PdfLength` | No | Page-flow primitives. Percent shorthand is not accepted because the engine requires a resolved number. |
| `borderTopLeftRadius`, `borderTopRightRadius`, `borderBottomRightRadius`, `borderBottomLeftRadius` | `PdfLength \| PdfPercentage` | No | Page-flow primitives; edge radii are resolved independently. |

A style object does not accept border strings such as `'1px solid red'`. Use
the explicit width, style, and color keys so invalid values remain
type-checkable. The `<style>` block accepts the `border` shorthands, and
`column-rule` for the column rule keys.

## Text

Text keys apply to `PdfText` and `PdfLink`. They may be set on ancestor
`PdfPage`/`PdfView` nodes when the table marks them inherited.

| Property | Accepted value | Inherited | Behavior |
| -------- | -------------- | --------- | --------------------- |
| `fontFamily` | `string` | Yes | Selects one registered family or a built-in engine family. |
| `fontSize` | `PdfLength` or `PdfPercentage` | Yes | Sets glyph size. A percentage is a share of the inherited font size (else 18 pt), as in CSS, and children inherit the points: `'70%'` in a text of 20 pt is 14 pt. A percentage on `PdfPage` or on SVG text fails with `PDF_TREE_INVALID`: a page inherits no font size, and SVG text resolves its own. |
| `fontStyle` | `'normal' \| 'italic' \| 'oblique'` | Yes | Selects the matching registered face. |
| `fontVariantNumeric` | `'normal' \| 'tabular-nums'` | Yes | `'tabular-nums'` gives every digit the same width, so amounts line up in a column. It turns on the font's `tnum` feature. A font without that feature keeps its digits, with no error. `'normal'` is the default. |
| `fontWeight` | `number` or `thin`, `hairline`, `ultralight`, `extralight`, `light`, `normal`, `medium`, `semibold`, `demibold`, `bold`, `ultrabold`, `extrabold`, `heavy`, `black` | Yes | Selects the face registered at that weight, or a variable face whose `wght` axis holds it. A weight without a face fails with `PDF_LAYOUT_ERROR`. |
| `hyphens` | `'auto' \| 'manual'` | Yes | `'auto'` splits a long word at the end of a line by the hyphenation patterns of the document `language`. `'manual'` (the default) splits a word only at its soft hyphens (`&shy;`). See [Hyphenate by document language]($docs.images-and-fonts#hyphenate-by-document-language). |
| `letterSpacing` | `PdfLength` | Yes | Adds space between glyphs and affects wrapping. |
| `lineHeight` | unitless multiplier, `PdfLength`, or `PdfPercentage` | Yes | A unitless value is a factor of each text's own font size, and children inherit the factor, as in CSS. A length is points where it is written. A percentage is points of the element's font size (its own, else the inherited one). Children inherit the points. The line height minus the font's glyph height (ascent to descent) goes half above and half below the glyphs, as in CSS. A line height below the glyph height lets the glyphs reach above their line. Applies also to a text with `PdfPageNumber` or `PdfPageCount`. |
| `maxLines` | `number` | No | Limits rendered lines to a whole number of 1 or more. Use `textOverflow: 'ellipsis'` for an ellipsis. |
| `textAlign` | `'left' \| 'right' \| 'center' \| 'justify'` | Yes | Aligns text inside its line box. |
| `textDecoration` | `'none' \| 'underline' \| 'line-through'` or both decoration names separated by a space | Yes | Applies one or both decorations. The decorations of a text and of its ancestors add up: `underline` on a text and `line-through` on a nested text give both. `'none'` adds nothing, so it cannot remove a decoration that an ancestor sets; remove it there. |
| `textDecorationColor` | color string | No | `PdfText` and `PdfLink`. |
| `textDecorationStyle` | `'solid' \| 'dashed' \| 'dotted'` | No | `PdfText` and `PdfLink`. |
| `textOverflow` | `'ellipsis'` | No | Adds an ellipsis when `maxLines` truncates text. |
| `textTransform` | `'none' \| 'capitalize' \| 'lowercase' \| 'uppercase'` | Yes | Transforms rendered text casing. `'upperfirst'` fails with `PDF_TREE_INVALID`: it is not CSS. `'capitalize'` raises the first letter of every word; to raise only the first letter of the text, write it in upper case. |
| `textWrap` | `'wrap' \| 'pretty'` | Yes | `'pretty'` breaks a paragraph's lines with more care. It avoids a last line shorter than a sixth of the line, a hyphen on the line before the last, and hyphens on two lines in a row. Lines may get slightly looser. Where no good set of lines avoids them, they stay. `'wrap'` is the default. The first text of a paragraph sets it for the paragraph. |
| `verticalAlign` | `'baseline' \| 'super' \| 'sub'` | No | Only on a `PdfText` or `PdfLink` inside another `PdfText`. `super` raises it by a third of the parent's font size, `sub` lowers it by a fifth. It keeps its font size, so set a smaller `fontSize` too, such as `'70%'`. The line grows only when the moved text no longer fits. |

`wordSpacing` is not supported. Use `letterSpacing` instead.

## Images and transforms

| Property | Accepted value | Inherited | Behavior |
| -------- | -------------- | --------- | --------------------------- |
| `objectFit` | `'contain' \| 'cover' \| 'fill' \| 'none' \| 'scale-down'` | No | Fits a `PdfImage` inside its resolved box: `fill` (the default) stretches it, `contain` letterboxes, `cover` crops, `none` keeps its own size, `scale-down` is the smaller of `none` and `contain`. |
| `objectPosition` | One or two parts, each a `PdfLength`, a `PdfPercentage`, or `'left'`, `'center'`, `'right'`, `'top'`, `'bottom'`, such as `'right 10pt'` | No | Places a `PdfImage` in its box when `objectFit` leaves free space, as in CSS: a length is an offset from the left or top, a percentage a share of the free space. The default is `'50% 50%'`. One part is the horizontal place (or the vertical one for `top` and `bottom`), and the other part is centred. Two keywords may come in either order. The CSS forms with offsets from an edge, such as `'right 10pt bottom 4pt'`, fail with `PDF_TREE_INVALID`. With `fill`, only a length moves the image. |
| `transform` | One to three space-separated `rotate()`, `scale()`, `scaleX()`, `scaleY()`, `translate()`, `translateX()`, `translateY()`, `skew()`, `skewX()` or `skewY()` operations | No | Applies to page-flow primitives. In the `<style>` block and in a typed style object, translation values are unitless points, and rotate and skew take `deg` or `rad`. A `:style` string also accepts `pt` or `px` in a translation, an angle without a unit, and any number of operations (see [Style object values](#style-object-values)). SVG transforms remain direct SVG props. |

## Style arrays

`PdfStyleValue` is either one `PdfStyle` or a recursively nested readonly array.
Arrays merge left-to-right. `false`, `null`, and `undefined` entries are ignored,
which makes Vue conditionals direct and type-safe:

```ts
import type { PdfStyle, PdfStyleValue } from '@lupinum/nuxt-pdf'

const base = { fontSize: 10 } satisfies PdfStyle
const total = { fontWeight: 700 } satisfies PdfStyle

const style = [base, [isTotal && total], null] satisfies PdfStyleValue
```

Numbers, strings, `true`, functions, and arbitrary objects are not valid array
entries.
