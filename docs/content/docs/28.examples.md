The playground under `playground/pdfs/` ships seven complete templates. Each is an
ordinary `.vue` single-file component discovered by the module, rendered through
the same registry in development and production, and covered by an end-to-end
rendering test. Selected visually load-bearing showcases additionally compare
reviewed raster baselines. Every template keeps its styles in a `<style>` block
with classes and a few `:root` variables; `:style` remains only for values that
come from data, such as chart geometry. Run `pnpm dev` and open `/_pdf` to
browse them, or read each source alongside the excerpts below.

::info{icon="lucide:info"}
`renderPdfSfc` compiles the same nested child-SFC graph as the production Nuxt
module. The packed-package gate exercises typed child props, a local image, and
multiple local font faces.
::

## At a glance

| Template | Source | Demonstrates |
| -------- | ------ | ------------ |

## Invoice with a repeated table header

The invoice lists its lines in a `PdfTable`. The columns are set once on the
table; the description column takes the free width. `PdfTableHeader` repeats at
the top of every page that the table reaches, and each `InvoiceLine` component
renders one `PdfTableRow`:

```vue [pdfs/invoice.vue (excerpt)]
<template>
  <PdfTable :columns="['28pt', 1, '52pt', '78pt', '86pt']">
    <PdfTableHeader class="line-header">
      <PdfTableCell>#</PdfTableCell>
      <PdfTableCell>Description</PdfTableCell>
      <PdfTableCell align="right">Qty</PdfTableCell>
      <PdfTableCell align="right">Rate</PdfTableCell>
      <PdfTableCell align="right">Amount</PdfTableCell>
    </PdfTableHeader>
    <InvoiceLine
      v-for="(line, index) in invoice.lines"
      :key="line.id"
      :currency="invoice.currency"
      :index="index"
      :line="line"
    />
  </PdfTable>
</template>
```

Both pages use `InvoicePage`, a local component that holds the page chrome
and a `<slot />` for the content: a top bar, a running head, a footer link and
the counter `Page <PdfPageNumber /> / <PdfPageCount />`. On the first page the
running head has `pages="continuation"`, so it starts on page 2. `pages`
counts the pages of one `PdfPage`, so the second page with the project brief
uses `pages="all"` to keep the head going. The `compact` scenario leaves that
page out.

The invoice is a Factur-X hybrid invoice. `toEInvoice` in
`pdfs/components/invoice/e-invoice.ts` turns the invoice into `EInvoice` data.
`PdfFacturX` writes the `EN 16931` XML from that data, and the pages print the
totals of `computeEInvoice`, so both show the same amounts. The
document is PDF/A-3b, so every page sets the registered `Fieldnote Sans`
family. See [E-invoices]($docs.e-invoices).

## E-book with chapter-aware running matter

*The Reed Line* is a digest novella. Its Contents page prints the start page of
each chapter with `PdfPageRef`, resolved after layout:

```vue [pdfs/ebook.vue (excerpt)]
<template>
  <PdfLink
    v-for="chapter in ebook.chapters"
    :key="chapter.id"
    :href="`#${chapter.id}`"
    class="toc-link"
  >
    <PdfView class="toc-row">
      <PdfText class="toc-title">{{ chapter.title }}</PdfText>
      <PdfText class="toc-page"><PdfPageRef :to="chapter.id" /></PdfText>
    </PdfView>
  </PdfLink>
</template>
```

Each chapter is a view with the chapter `id`. The running foot is a `fixed`
text inside that view, so it repeats on every page that the chapter spans and
names the **current** chapter:

```vue [pdfs/ebook.vue (excerpt)]
<template>
  <PdfView
    v-for="chapter in chapters"
    :id="chapter.id"
    :key="chapter.id"
    :break="!chapter.first"
    :bookmark="chapter.title"
    class="chapter"
  >
    <PdfText fixed class="running-foot">
      {{ chapter.title }}   ·   <PdfPageNumber />
    </PdfText>
    <PdfText v-for="(paragraph, index) in chapter.body" :key="index" class="paragraph">
      {{ paragraph }}
    </PdfText>
  </PdfView>
</template>
```

The [running foot recipe]($docs.recipes#running-foot-that-names-the-section)
shows the matching styles.

## Annual report with SVG charts and a ledger table

The Fieldnote Studio annual report draws a grouped bar chart, a line chart with a
gradient area tint, and a donut. It uses the [SVG primitives]($docs.svg-graphics),
with every figure computed from one canonical `YearFigures` source. The donut
segments come from a pure geometry model and render as a `v-for` of paths:

```vue [pdfs/annual-report.vue (excerpt)]
<PdfSvg :viewBox="`0 0 ${donut.size} ${donut.size}`" :alt="donut.alt" :style="{ height: donut.size, width: donut.size }">
  <PdfPath
    v-for="segment in donut.segments"
    :key="segment.id"
    :d="segment.d"
    :fill="segment.fill"
    :transform="segment.transform"
  />
</PdfSvg>
```

The donut size comes from the geometry model, so it stays in `:style`. The
statement of operations is a `PdfTable`. Each row carries a `kind`, and one
class per kind sets the right-aligned tabular numerals, the hairline rules
above totals and the parenthesised outflows. The quarter and sector breakdowns provably sum to the
yearly totals (asserted in the template's test).

The report is an accessible PDF that claims `['PDF/A-3a', 'PDF/UA-1']`. The
section titles and chart titles are headings, each section is a
`tag="section"` view, and the KPI tiles and the donut legend are lists. Each
chart has an `alt` text that the geometry model writes from the same data, so
the bar chart's text holds every plotted value. The axis and value labels
around the charts repeat that text, so they are `decorative`, and so are the
KPI triangles, whose delta text carries the sign. The ledger table needs no
props. See [Accessible PDF]($docs.accessible-pdf).

## Certificate with SVG ornaments

The certificate is a single A4 landscape page whose decoration is drawn entirely
from primitives: a double-rule engraver's border with corner diamonds, and a
concentric seal with two rules, a 32-dot beaded coin edge, a five-point star, and a
single bronze `RadialGradient` used once.

```vue [pdfs/components/certificate/CertificateSeal.vue]
<script setup lang="ts">
// Evenly spaced dots in the band between the two rules.
const beads = Array.from({ length: 32 }, (_, index) => {
  const angle = (index / 32) * Math.PI * 2 - Math.PI / 2
  return { cx: 50 + 45.2 * Math.cos(angle), cy: 50 + 45.2 * Math.sin(angle) }
})
</script>

<template>
  <PdfSvg view-box="0 0 100 100">
    <PdfDefs>
      <PdfRadialGradient id="seal-bronze" cx="0.5" cy="0.38" r="0.62">
        <PdfStop offset="0" stop-color="#E7CC86" />
        <PdfStop offset="0.55" stop-color="#C9A24B" />
        <PdfStop offset="1" stop-color="#8A6A2F" />
      </PdfRadialGradient>
    </PdfDefs>
    <PdfCircle
      v-for="(bead, index) in beads"
      :key="`bead-${index}`"
      :cx="bead.cx"
      :cy="bead.cy"
      :r="0.75"
    />
  </PdfSvg>
</template>
```

The decorative layers are absolutely positioned, so a long recipient name wraps
at spaces to two centered lines and the page can never spill to a second sheet.

## Menu with typography and diacritics

The Gasthaus Alpenrose card is two A5 pages of typography without borders or
boxes. German dish names carry their umlauts through rendering and extraction,
and a flex-`1` dotted leader ties each name to a right-aligned tabular price:

```vue [pdfs/menu.vue (excerpt)]
<template>
  <PdfView class="dish-row">
    <PdfText class="dish-name">
      {{ dish.name }}
    </PdfText>
    <DotLeader :baseline="2" :gap="7" :color="leader" :width="0.75" />
    <PdfText class="dish-price">
      {{ formatMenuPrice(dish.price) }}
    </PdfText>
  </PdfView>
</template>

<style>
:root {
  --ink: #23201c;
  --font-body: Inter;
}
.dish-row {
  flex-direction: row;
  align-items: flex-end;
}
.dish-name {
  font-family: var(--font-body);
  font-size: 10pt;
  font-weight: 600;
  color: var(--ink);
}
.dish-price {
  width: 32pt;
  font-family: var(--font-body);
  font-size: 10pt;
  text-align: right;
  color: var(--ink);
}
</style>
```

The leader color also feeds the `DotLeader` prop, so it is a script constant
next to the variables.

Prices use the locale format. For example, `9.5` becomes `9,50`. The whole card
is data-driven, so the `winter` scenario swaps every dish and pour without
touching the template.

## Registration form with fillable fields

The Fieldnote Studio workshop registration is a one-page A5 form. The
participant fills it in a PDF reader and sends it back. Each field gets its
size and border from a class; a `PdfText` above it is the visible label, and
`label` is the accessible name. See [Fillable forms]($docs.forms):

```vue [pdfs/registration.vue (excerpt)]
<template>
  <PdfText class="label">Full name</PdfText>
  <PdfTextField
    name="fullName"
    label="Full name"
    :value="registration.participant"
    :max-length="60"
    required
    class="field"
  />
  <PdfSelect
    name="session"
    label="Session"
    :options="registration.sessions"
    :value="registration.sessions[0]"
    class="field"
  />
</template>

<style>
.label {
  margin-top: 10pt;
  margin-bottom: 3pt;
  font-weight: 500;
}
.field {
  width: 100%;
  height: 20pt;
  border-width: 0.75pt;
  border-color: #9fb0b5;
}
</style>
```
