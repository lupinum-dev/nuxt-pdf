Module options live under the `pdf` key in `nuxt.config.ts`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ["@lupinum/nuxt-pdf"],
  pdf: {
    fonts: [/* … */],
    remote: {/* … */},
    limits: {/* … */},
  },
});
```

Every key is optional. With none set, the module renders with built-in fonts,
uses only local assets, performs zero network I/O, and bounds every render with
the default render limits below.

## pdf.fonts

An array of font-face declarations. Each face registers one weight/style of a
font found in `pdfs/fonts`:

```ts
export default defineNuxtConfig({
  pdf: {
    fonts: [
      { family: "Invoice Sans", src: "Regular.ttf", fontWeight: 400, fontStyle: "normal" },
      { family: "Invoice Sans", src: "Bold.ttf", fontWeight: 700, fontStyle: "normal" },
    ],
  },
})
```

| Field | Type | Required | Description |
| ----- | ---- | -------- | ----------- |
| `family` | `string` | yes | The family name referenced in `fontFamily` style values |
| `src` | `string` | yes | TTF/OTF filename relative to `pdfs/fonts` |
| `fontWeight` | `number \| PdfFontWeightName` | no | Numeric weight or a name (`"bold"`, `"medium"`, `"light"`, …) |
| `fontStyle` | `'normal' \| 'italic' \| 'oblique'` | no | The face style |

Register one entry per weight/style you use. Sources are signature- and
size-checked (5 MB cap) and embedded into the build. See
[Images & fonts]($docs/guides/images-and-fonts) for the validation boundary.

## pdf.remote

Opt-in remote fetching for images and fonts. **Absent by default**, which keeps
the module fully offline; when present, `allow` must list at least one
`https://` prefix.

```ts
export default defineNuxtConfig({
  pdf: {
    remote: {
      allow: [
        "https://cdn.example.com/brand/",
        "https://*.assets.example.com/logos/",
      ],
      maxImageBytes: 10_485_760,
      maxFontBytes: 5_242_880,
      timeoutMs: 10_000,
    },
  },
})
```

| Field | Type | Default | Description |
| ----- | ---- | ------- | ----------- |
| `allow` | `string[]` | — (required) | Allowlisted `https://` URL prefixes: a host (or a single leading `*.` subdomain wildcard on a registrable domain) plus a pathname prefix |
| `maxImageBytes` | `number` | `10_485_760` (10 MB) | Per-image byte cap |
| `maxFontBytes` | `number` | `5_242_880` (5 MB) | Per-font byte cap |
| `timeoutMs` | `number` | `10_000` | Per-hop fetch timeout |

Invalid entries fail fast at module setup: non-`https`, credentialed, or
query/fragment-bearing entries, bare wildcards, and wildcards on common public
suffixes are all rejected. The full security posture — per-hop redirect
re-checking, streamed byte caps, signature authority, and credential-free
fetches — is documented in [Images & fonts]($docs/guides/images-and-fonts).

## pdf.limits

Guardrails that bound every render so a hostile or buggy template cannot loop
forever or explode the page count. **Both defaults apply even when `pdf.limits`
is absent**, so every render is bounded out of the box. The defaults are
generous enough that no legitimate document reaches them.

```ts
export default defineNuxtConfig({
  pdf: {
    limits: {
      timeoutMs: 30_000,
      maxPages: 2_000,
    },
  },
})
```

| Field | Type | Default | Description |
| ----- | ---- | ------- | ----------- |
| `timeoutMs` | `number` | `30_000` | Time budget for the whole render (mount, layout, all passes, serialization) |
| `maxPages` | `number` | `2_000` | Maximum laid-out page count |

Both fields are optional positive integers; a non-positive, non-integer, or
non-numeric value fails fast at module setup. Omitting one field keeps its
default.

When a limit is exceeded the render fails with a `PDF_LIMIT_EXCEEDED`
`NuxtPdfError`:

- **`maxPages`** is checked right after layout (before serialization) on both the
  single-pass and multi-pass paths; the error names the page count, the cap, and
  the config key.
- **`timeoutMs`** bounds the entire render with a single deadline. Upstream
  layout is not abortable mid-step, so the budget is checked **between** engine
  stages and passes — it is a deadline, not hard cancellation, and a single
  engine stage can overshoot it by its own duration. The error names the elapsed
  budget.
