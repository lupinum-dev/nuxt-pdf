A fillable form is a PDF with fields. The user types into the fields in a PDF
reader, saves the PDF, and sends it back. Nuxt PDF writes three kinds of field:
`PdfTextField`, `PdfCheckbox` and `PdfSelect`.

## Add fields to a template

Give each field a `name` and a `width` and `height`. Put the visible label in a
`PdfText` next to the field:

```vue [pdfs/sign-up.vue]
<script setup lang="ts">
definePdf({ title: 'Volunteer sign-up', language: 'en' })
</script>

<template>
  <PdfDocument>
    <PdfPage size="A5" :style="{ padding: 40, fontSize: 10 }">
      <PdfText>Full name</PdfText>
      <PdfTextField name="fullName" label="Full name" required class="field" />

      <PdfText>Shift</PdfText>
      <PdfSelect name="shift" label="Shift" :options="['Morning', 'Afternoon']" value="Morning" class="field" />

      <PdfView :style="{ flexDirection: 'row', marginTop: 8 }">
        <PdfCheckbox name="newsletter" label="Send me the newsletter" class="box" />
        <PdfText :style="{ marginLeft: 6 }">Send me the newsletter</PdfText>
      </PdfView>
    </PdfPage>
  </PdfDocument>
</template>

<style>
.field {
  width: 100%;
  height: 20pt;
  margin-bottom: 8pt;
  padding: 4pt 5pt;
  border-width: 0.75pt;
  border-color: #9fb0b5;
}
.box {
  width: 10pt;
  height: 10pt;
  border-width: 0.75pt;
  border-color: #9fb0b5;
}
</style>
```

1. Open the PDF in a reader. Each field is a box the user can click and type
   into.
2. Fill the fields, save the PDF, and open it again. The values are kept.

Nuxt PDF draws each field itself: its border, background and value. The field
looks the same in every reader.

## Fields

All three fields take these props:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `name` | `string` | Required | The name a reader exports with the value. Unique in the document. No period. |
| `label` | `string` | None | The accessible name. A reader shows it as the tooltip of the field. |
| `readOnly` | `boolean` | `false` | The reader shows the value but does not let the user change it. |
| `required` | `boolean` | `false` | The reader asks for a value before it submits or exports the form. |
| `style` | `PdfStyleValue` | None | Must set `width` and `height`. See [Style a field](#style-a-field). |

`PdfTextField` also takes:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `value` | `string` | None | The text the field starts with. |
| `multiline` | `boolean` | `false` | Lets the user type several lines. `value` may then contain line breaks. |
| `maxLength` | `number` | None | The most characters the user can type. |

`PdfCheckbox` also takes:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `checked` | `boolean` | `false` | The box starts checked. A checked box shows a cross. |
| `exportValue` | `string` | `'Yes'` | The value a reader exports when the box is checked: letters, digits, `_` or `-`. |

`PdfSelect` is a drop-down list. It also takes:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `options` | `readonly string[]` | Required | The choices, in order. Each choice once. |
| `value` | `string` | None | The selected choice. It must be one of `options` unless `editable` is set. |
| `editable` | `boolean` | `false` | Lets the user type a value that is not in `options`. |

## Style a field

The field style takes the box styles that every element takes (`width`,
`height`, margins, `position`) and these styles for the look of the field:

| Style | Default | Description |
| ----- | ------- | ----------- |
| `fontSize` | `10pt` | The size of the value. |
| `color` | `black` | The colour of the value and of the checkbox cross. |
| `textAlign` | `left` | `left`, `center` or `right`. A `justify` from the parent is drawn as `left`. |
| `padding` | `2pt` | The space between the border and the value or cross. |
| `borderWidth`, `borderColor` | None | A square, solid border, drawn inside the box. Each side can have its own width and colour. |
| `backgroundColor` | None | Fills the box behind the value. |

`fontSize`, `color` and `textAlign` come from the parent when the field does
not set them, as they do for `PdfText`. In the example above, the fields take
`fontSize: 10` from the page.

A single-line value is centred vertically in the box. A `multiline` value
starts at the top and breaks at the box width and at its own line breaks. A
value that does not fit is cut off at the padding: Nuxt PDF does not make the
text smaller, and a long value is not an error.

## What the reader does

The value is drawn in Helvetica, a font that every PDF reader has, so the file
does not embed a font for the fields. When the user changes a value, the reader
draws the new value itself, in Helvetica at the field's `fontSize`.

- **Field text uses WinAnsi characters only.** Helvetica in a PDF reader has
  the Western European characters (Latin-1 and a few more, such as `€` and
  `–`). A `value` or an option with another character, such as `→` or `大`,
  fails with `PDF_TREE_INVALID`. The page text around the field can use any
  registered font.
- **The letter shapes come from the reader.** A reader that has no Helvetica
  uses a font with the same widths, such as Arial or Liberation Sans.

## Rules

A field is a box of fixed size that exists once:

- It needs `width` and `height` in its style.
- It never splits across pages. A field that does not fit moves to the next
  page whole.
- It cannot be inside `fixed` content (which repeats on every page), a node
  with `pages`, or `PdfSvg`.
- Two fields cannot have the same `name`.

Each rule fails with `PDF_TREE_INVALID` and a message that names the field.

## Limits

- **No PDF/A.** PDF/A needs every font embedded, also in the fields, and Nuxt
  PDF draws fields in the standard font Helvetica. A document with a PDF/A
  level or `PdfFacturX` and a field fails with `PDF_TREE_INVALID`.
- **No tagged PDF.** PDF/UA-1 and PDF/A-3a need a structure element for every
  field, which Nuxt PDF does not write yet. Such a document with a field fails
  with `PDF_TREE_INVALID`.
- **No radio groups, list boxes, buttons or field groups yet.**
- **Square, solid borders only.** A field with `borderRadius`, a `borderStyle`
  other than `solid`, or its own `textAlign: justify` fails with
  `PDF_TREE_INVALID`.
- **No form scripts or submit actions.** A field does not format or check what
  the user types, other than `maxLength`.

With [password protection]($docs.protection), `allow.fillingForms` and
`allow.annotating` decide whether a user who opened the PDF with the open
password may fill the fields.

## Test a form

Read the fields with pdf.js in a test. `getAnnotations()` returns each field
with its `fieldName`, `fieldValue` and flags:

```ts [test/sign-up.test.ts]
import { expect, it } from 'vitest'
import { getDocument } from 'pdfjs-dist/legacy/build/pdf.mjs'
import { renderPdfSfc } from '@lupinum/nuxt-pdf/test'

it('writes the sign-up fields', async () => {
  const { bytes } = await renderPdfSfc('./pdfs/sign-up.vue', {})
  const document = await getDocument({ data: bytes }).promise
  const annotations = await (await document.getPage(1)).getAnnotations()
  const fields = annotations.filter(annotation => annotation.subtype === 'Widget')

  expect(fields.map(field => field.fieldName)).toEqual(['fullName', 'shift', 'newsletter'])
})
```
