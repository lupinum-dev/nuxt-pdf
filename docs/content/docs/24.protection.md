A protected PDF is encrypted. A reader needs the open password to show it.
Nuxt PDF encrypts with AES-256, the strongest form the PDF standard defines
(ISO 32000-2, revision 6). It writes no other form.

## Require a password to open the PDF

Set `protection` on `PdfDocument` and give the password as a template prop:

```vue [pdfs/statement.vue]
<script setup lang="ts">
interface Props {
  holder: string
  password: string
}

definePdf<Props>({ title: 'Account statement', language: 'en' })

const props = defineProps<Props>()
</script>

<template>
  <PdfDocument :protection="{ openPassword: props.password, allow: { copying: false } }">
    <PdfPage size="A4" :style="{ padding: 48 }">
      <PdfText>Statement for {{ holder }}</PdfText>
    </PdfPage>
  </PdfDocument>
</template>
```

```ts [server/api/statement.post.ts]
import { pdf } from '#pdf'

export default defineEventHandler(async (event) => {
  const { holder, password } = await readBody<{ holder: string, password: string }>(event)
  const result = await pdf.statement.render({ holder, password })
  return result.response()
})
```

1. Send the password to the recipient on another channel than the PDF.
2. Open the PDF in a reader. It asks for the password before it shows a page.

Do not put a real password into `sampleData`. It is part of the repository.

## Passwords

| Field | Effect |
| ----- | ------ |
| `openPassword` | A reader needs it to open the PDF. The permissions in `allow` apply. |
| `ownerPassword` | Opens the PDF with every permission. A reader that opens the PDF with it ignores `allow`. |

Give at least one of the two. The render fails with `PDF_TREE_INVALID`
otherwise.

- **Only `openPassword`**: Nuxt PDF uses a random owner password of 32 bytes
  and does not keep it. Nobody can lift the permissions with a password.
- **Only `ownerPassword`**: anyone can open the PDF, and `allow` applies.
- **Both**: they must be different. With equal passwords, whoever opens the
  PDF gets every permission, so the render fails.

A password must not be empty, must be at most 127 bytes in UTF-8, and must
not contain control, format or private-use characters or spaces other than
the normal space. It must not change under Unicode NFKC normalization, so
write `fi` instead of the ligature `ﬁ`. These rules make every reader derive
the same key from the password. The error message names the field, never the
password.

## Permissions

`allow` sets what a reader permits to a user who opened the PDF with the open
password. Each permission is allowed unless you turn it off:

| Permission | Values | Default | Allows |
| ---------- | ------ | ------- | ------ |
| `printing` | `'none'`, `'low'`, `'high'` | `'high'` | Printing. `'low'` permits a degraded print only. |
| `copying` | `boolean` | `true` | Copying or extracting text and graphics. |
| `changing` | `boolean` | `true` | Changing the content, other than comments, forms and pages. |
| `annotating` | `boolean` | `true` | Adding or changing comments. It also allows filling forms. |
| `fillingForms` | `boolean` | `true` | Filling existing form fields. |
| `extractingForAccessibility` | `boolean` | `true` | Extracting text and graphics for assistive technology, such as a screen reader. |
| `assembling` | `boolean` | `true` | Inserting, rotating or deleting pages, and adding bookmarks. |

`fillingForms: false` needs `annotating: false` too, because the PDF annotate
permission also allows filling forms. The render fails otherwise.

## What protection does not do

- **Readers enforce permissions, the encryption does not.** A user with the
  open password can read every byte. A reader that ignores the permission
  flags can copy or print the content. Use the permissions to state your
  intent, not to keep content secret from someone who can open the PDF.
- **No PDF/A.** PDF/A forbids encryption. `protection` with a PDF/A level in
  `conformance`, or with `PdfFacturX` (which writes PDF/A-3), fails with
  `PDF_TREE_INVALID`. Send an e-invoice unprotected.
- **PDF/UA-1 needs accessibility extraction.** `protection` works with
  `conformance: 'PDF/UA-1'`, but `extractingForAccessibility` must stay
  `true`. ISO 32000-2 tells readers to ignore this flag; older readers still
  read it.
- **No equal bytes.** Every render uses a new random key, so the same document
  gives different bytes each time. Compare the text, not a hash of the file.
- **PDF 1.7 only.** `protection` writes PDF 1.7 with Adobe extension level 8.
  `pdfVersion` other than `'1.7'` fails with `PDF_TREE_INVALID`.
- **Old readers.** Revision 6 came with Acrobat X (2010); older readers
  cannot open it. Nuxt PDF tests the output with pdf.js, the reader of
  Firefox.

## Test a protected PDF

Pass the password to `renderPdfSfc`, `renderPdfTemplate` or `parsePdf`.
Without it, pdf.js fails with a `PasswordException`:

```ts [test/statement.test.ts]
import { expect, it } from 'vitest'
import { expectPdf, parsePdf, renderPdfSfc } from '@lupinum/nuxt-pdf/test'

it('opens the statement only with the password', async () => {
  const password = 'test-Willow-28'
  const { bytes, parsed } = await renderPdfSfc('./pdfs/statement.vue', { holder: 'Mira Okafor', password }, { password })

  expectPdf(parsed).toContainText('Statement for Mira Okafor')
  await expect(parsePdf(bytes)).rejects.toMatchObject({ name: 'PasswordException' })
})
```
