Nuxt PDF runs in a Vercel Function, which is a Node serverless function. You
do not need a headless browser, a Chromium layer, or a separate PDF service.
The engine, the templates, and the fonts travel inside the server bundle.

::warning{icon="lucide:triangle-alert"}
The repository verifies that the Vercel build output contains the engine and the
templates. It does not run the deployed function. Test your deployed route
before you send production traffic to it.
::

## Keep the Node runtime

Vercel detects Nuxt and builds with the Nitro `vercel` preset. This preset
creates Node functions. Keep it.

Do not select the `vercel-edge` preset or an edge runtime. The engine needs
Node APIs, and an edge build cannot render PDFs.

## Set the function duration

Give the function more time than the render needs. Set the render deadline in
`pdf.limits.timeoutMs` and the function limit in `nitro.vercel.functions`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lupinum/nuxt-pdf'],
  pdf: {
    limits: {
      timeoutMs: 20_000,
    },
  },
  nitro: {
    vercel: {
      functions: {
        maxDuration: 30,
      },
    },
  },
})
```

`maxDuration` is in seconds and `timeoutMs` in milliseconds. Keep `maxDuration`
higher than `timeoutMs`. Nuxt PDF then stops a slow render with a
`PDF_LIMIT_EXCEEDED` error that you can handle. Otherwise Vercel stops the
function first and returns a timeout error without details.

The allowed maximum depends on your Vercel plan. See
[Configuring maximum duration](https://vercel.com/docs/functions/configuring-functions/duration)
in the Vercel documentation.

## Keep the bundle small

The module embeds every font and image that your templates use into the server
bundle. A large bundle makes the first request after a deploy, the cold start,
slower.

- Remove unused files from `pdfs/fonts/` and `pdfs/assets/`.
- Register only the font weights that your templates use.
- Compress large images before you put them in `pdfs/assets/`.

## Deploy and check the route

Deploy as usual, with the Vercel Git integration or the Vercel CLI. Then
request a PDF route on the deployment and check the response headers:

```bash
curl -I https://your-app.vercel.app/api/invoices/INV-2048
```

A working route returns status `200` and `content-type: application/pdf`.
Open the same address in a browser to see the document.

To check the render time and size, log the diagnostics in the route. They
contain no document content:

```ts
const result = await pdf.invoice.render({ invoice })
console.info('invoice rendered', result.diagnostics)
```

The log line appears in the Vercel function logs. Compare `durationMs` with
your `timeoutMs`, and `byteLength` with the size that you expect.

## Cache PDFs that are the same for everyone

A PDF that does not depend on the user, such as a price list, can use the
Vercel CDN cache. Set `s-maxage` on the response. `loadPriceList` stands for
your own function in `server/utils/`:

```ts [server/api/price-list.get.ts]
import { pdf } from '#pdf'

export default defineEventHandler(async () => {
  const result = await pdf['price-list'].render({ items: await loadPriceList() })
  return result.response({
    headers: { 'cache-control': 'public, s-maxage=3600, stale-while-revalidate=86400' },
  })
})
```

The CDN then serves the same PDF for an hour without running the function.

Never cache an invoice or another private document this way. Use
`cache-control: private, no-store` for documents that belong to one user.

## Fix a failing deployed route

| Symptom | Cause | Fix |
| ------- | ----- | --- |
| Timeout error from Vercel, no Nuxt PDF error | `maxDuration` is lower than the render time | Raise `maxDuration`, or lower `timeoutMs` so Nuxt PDF stops first. |
| `PDF_LIMIT_EXCEEDED` in the logs | The document passed a configured limit | Read the named limit in the message. Reduce the input or raise that one limit. |
| The route works locally but fails on Vercel | The project builds for an edge runtime | Use the default `vercel` preset. |
| The first request after a deploy is slow | Cold start with a large bundle | Remove unused fonts and images. |

For memory, caching, and queues on every platform, see
[Deploy and operate]($docs.deployment).
