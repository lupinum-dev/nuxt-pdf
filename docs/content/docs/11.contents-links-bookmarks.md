Nuxt PDF builds a table of contents, internal links, and a bookmark outline from
ordinary components. `PdfContents` lists the bookmarks of the document with
their page numbers. For a list of your own, use `PdfLink` and `PdfPageRef`.
The engine resolves the page numbers in both cases.

## A table of contents from the bookmarks

Put `PdfContents` where the table of contents goes. It lists every node with a
`bookmark`, nested as the [outline](#bookmarks-the-outline) nests them, with
the page number of each:

```vue [pdfs/report.vue]
<script setup lang="ts">
interface Props {
  chapters: { title: string, sections: { title: string }[] }[]
}

definePdf<Props>({ filename: 'report.pdf' })

defineProps<Props>()
</script>

<template>
  <PdfDocument language="en">
    <PdfPage>
      <PdfText tag="h1" :bookmark="{ title: 'Contents', contents: false }">Contents</PdfText>
      <PdfContents />
      <PdfView v-for="chapter in chapters" :key="chapter.title" :bookmark="chapter.title" break>
        <PdfText tag="h1">{{ chapter.title }}</PdfText>
        <PdfText v-for="section in chapter.sections" :key="section.title" tag="h2" :bookmark="section.title">
          {{ section.title }}
        </PdfText>
      </PdfView>
    </PdfPage>
  </PdfDocument>
</template>
```

Each entry prints its title, a dotted leader, and the page number at the right
edge. The leader runs from the end of the title's last line, so a title that
wraps keeps its number on its last line. The entry is a link to its node. An entry never splits
across pages or columns. A long contents continues on the next page, and in a
column container it fills the columns.

- `levels` sets how many outline levels the contents lists: 1 to 6, default 3.
- `contents: false` in a bookmark keeps the node in the outline and out of the
  contents. The entries below it move up one level.
- `leader="none"` removes the dotted line and keeps the gap.
- `styles` changes the parts of the entries. See
  [PdfContents]($docs.primitives#pdfcontents) for the parts and defaults.

A `PdfContents` in a document without a `bookmark` fails with
`PDF_TREE_INVALID`. When every chapter is optional, put the same `v-if` on
the contents.

## Named destinations and internal links

Give any primitive an `id` to make it a named destination, then link to it with
`<PdfLink href="#id">`:

```vue
<PdfText id="terms">Terms &amp; conditions</PdfText>

<PdfLink href="#terms">Jump to terms</PdfLink>
```

Internal `#id` links resolve **by name in a single pass**. They do not trigger
the multi-pass loop and add no cost. A `#id` that does not match any destination
in the mounted document fails the render with `PDF_TREE_INVALID`.

## External links

An external link takes an absolute `http:`, `https:`, `mailto:` or `tel:`
URL:

```vue
<PdfLink href="https://example.org/terms">Read the terms online</PdfLink>
<PdfLink href="tel:+4930123456">+49 30 123456</PdfLink>
```

Keep the link text on the line of its tags, as in
`<PdfLink href="...">text</PdfLink>`. A line break after the opening tag or
before the closing tag becomes a space, and the page shows two spaces next to
the link. ESLint's `vue/singleline-html-element-content-newline` and
`vue/multiline-html-element-content-newline` add such line breaks; turn them off
for `pdfs/**/*.vue`.

Any other `href` fails the render with `PDF_TREE_INVALID`, and the message
names the value: a relative path, and a `javascript:`, `file:`, `data:` or
other URL. A link target often comes from data, such as a customer's website,
so check it in your form or route first.

::info{icon="lucide:info"}
When an `id` sits on a node that spans a page boundary, both the printed page
number and the jump target resolve to the section's **first** page. This is a
deliberate divergence from React PDF, whose last-writer-wins table points at the
last page.
::

## Printing page numbers: PdfPageRef

To print the page a destination lands on, put `<PdfPageRef :to="id" />` inside
a `PdfText`. It prints the 1-based number of the first page that shows the
element with that `id`. `PdfContents` prints its numbers in this way. For a
list of your own, combine it with `PdfLink` and a
[`PdfLeader`]($docs.primitives#pdfleader), which puts the number at the right
edge:

```vue
<template>
  <PdfLink
    v-for="entry in entries"
    :key="entry.id"
    :href="`#${entry.id}`"
  >
    <PdfText>
      <PdfText class="toc-title">{{ entry.title }}</PdfText>
      <PdfLeader />
      <PdfPageRef :to="entry.id" />
    </PdfText>
  </PdfLink>
</template>

<style>
.toc-title {
  font-weight: bold;
}
</style>
```

A `PdfPageRef` turns on multi-pass layout. The engine lays out the document
once per pass. Each pass feeds its destination page map into the next pass
until the map stops changing. The template renders once; only the layout runs
again.

A `PdfPageRef` whose `to` matches no `id` in the document fails the render with
`PDF_TREE_INVALID`. Check the spelling of the `id` on the destination.

For the current page and the total, use `PdfPageNumber` and `PdfPageCount`; see
[page tokens]($docs.primitives#page-tokens).

## Convergence and maxPasses

The loop is a fixed point. An ordinary table of contents converges in **two
passes**: pass one fills the numbers in, pass two lays out with them and the map
no longer changes. A `fixed` node with `pages` needs no extra pass, nor does a
view that must move its repeated header to the next page. Any other document
stops after one pass.

A document does not converge if its layout depends on the page numbers that it prints.
For example, a TOC entry can change height when its page number changes. After `maxPasses`
(a validated positive integer on `definePdf`, default 5) the render fails with a
`PDF_LIMIT_EXCEEDED` `NuxtPdfError`, attributed to the template:

```ts
definePdf<Props>({
  // Raise the cap only if a genuinely convergent document needs more passes.
  maxPasses: 8,
})
```

Non-convergence fails closed; the loop does not force a wrong answer. Raise
`maxPasses` only when you know the document actually settles.

## Bookmarks (the outline)

Add a `bookmark` to any of `PdfPage`, `PdfView`, `PdfText`, or `PdfImage` to
build the PDF outline. The value is a title string, or an object with
`title`, `expanded` (the entry starts open) and `contents: false` (no entry in
a `PdfContents`):

```vue
<PdfView :id="section.id" :bookmark="{ title: section.title, expanded: true }">
  <PdfText :id="sub.id" :bookmark="sub.title">{{ sub.title }}</PdfText>
</PdfView>
```

Nesting follows the component tree, so a child's bookmark nests under its
ancestor's. A node that splits across pages has one outline entry, on the page
where its content starts. The outline carries title text, its initially
expanded state, and parent/child nesting. Nuxt PDF does not expose reader
page-mode preferences or bookmark destination geometry
(`top`/`left`/`zoom`/`fit`).

## A full example

`playground/pdfs/report.vue` in the repository demonstrates the whole feature: a
contents page linking to each section, `PdfPageRef` page numbers, per-section
bookmarks, and a fixed footer with `PdfPageNumber` and `PdfPageCount`.
