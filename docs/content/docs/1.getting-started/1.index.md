Nuxt PDF authors server-rendered PDFs as ordinary Vue components. You write a
Single File Component in `pdfs/`, and a Nuxt module renders it to a PDF on the
server. Vue does the authoring; React PDF's framework-neutral layout, font, and
serialization packages do the rendering. React itself is never a production
dependency.

This is an external alpha (`0.1.0`) with a deliberately narrow contract: one
Nuxt module, one document tree, one Node server renderer, and a small set of
tested PDF primitives.

## Why it exists

Generating a data-driven document — an invoice, a report, a certificate, a
ticket — usually means one of two bad options: hand-assembling bytes with a
low-level PDF library, or rendering an HTML page in headless Chromium and hoping
the print stylesheet holds. Nuxt PDF takes a third path: the same component
model you already use for the app, rendered through a real PDF layout engine, on
the server, with typed props.

## When to use it

Reach for Nuxt PDF when the document is **structured and data-driven** and you
control the layout:

- invoices, quotes, and receipts,
- reports and statements with a table of contents,
- certificates, tickets, and labels.

## When not to use it

Nuxt PDF is honest about its boundaries. Pick a different tool when:

- **You want to print an existing web page.** Use headless Chromium (Playwright
  or Puppeteer). Nuxt PDF does not compile browser CSS or print HTML.
- **You want to display a PDF in the browser.** Use [PDF.js](https://mozilla.github.io/pdf.js/).
  Nuxt PDF renders on the server; it is not a viewer.
- **You want to edit, merge, fill, or sign an existing PDF.** Use
  [pdf-lib](https://pdf-lib.js.org/) or a signing service. Nuxt PDF produces new
  documents; it does not manipulate existing ones.

## What is deliberately not included

`0.1.0` has no CSS compiler, no HTML printing, no table engine, no charts, no
forms, no signing, no tagged/PDF-UA output, no browser or edge renderer, and no
guarantee of byte-identical output across machines. These are not oversights;
they are scope. The [Conformance & philosophy]($docs/conformance) section
explains the reasoning, and [CONFORMANCE.md](https://github.com/Mat4m0/nuxt-pdf/blob/main/CONFORMANCE.md)
records the exact tested boundary.
