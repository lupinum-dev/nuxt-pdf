Nuxt PDF now builds one plain-data document tree and lays it out in a worker
thread. A prop cannot hold a function any more, and some checks are stricter.
This page lists each change and its replacement.

Run `nuxt build` or `nuxt dev` first. The build names every removed prop with
its file, line, and column, and the message says what to use:

```text
Unsupported prop "render" on <PdfText>. Use <PdfPageNumber /> and <PdfPageCount /> inside the text. Use pages="first" or pages="continuation" on a fixed text to show it on some pages only.
```

## Replace the `render` prop

The `render` prop of `PdfText` is removed. Page numbers are components.

Before:

```text
<PdfText fixed :render="({ pageNumber, totalPages }) => `Page ${pageNumber} of ${totalPages}`" />
```

After:

```vue
<PdfText fixed>Page <PdfPageNumber /> of <PdfPageCount /></PdfText>
```

- A `PdfText` inside a `fixed` `PdfView`, such as a footer row, needs no
  `fixed` of its own.
- Where the callback built the whole line in JavaScript, keep the computed
  part in `{{ }}` and put the token after it:
  `{{ parts.join(' · ') }} · Page <PdfPageNumber />`.
- A token in a link goes into a text inside the link:
  `<PdfLink><PdfText>Page <PdfPageNumber /></PdfText></PdfLink>`.

A callback that hid content on some pages becomes `pages` on the `fixed` text.

Before:

```text
<PdfText fixed :render="({ pageNumber }) => pageNumber > 1 ? `${title} · ${pageNumber}` : ''" />
```

After:

```vue
<PdfText fixed pages="continuation">{{ title }} · <PdfPageNumber /></PdfText>
```

See [Fixed content and pages]($docs.primitives#fixed-content-and-pages).

## Replace `usePdfPageNumbers()`

`usePdfPageNumbers()` is removed. Print the page of a destination with
`PdfPageRef` inside a `PdfText`. The number is resolved after layout.

```vue
<PdfText>Results <PdfPageRef to="results" /></PdfText>
```

See [Contents, links, and bookmarks]($docs.contents-links-bookmarks).

## Replace `hyphenationCallback`

`hyphenationCallback` is removed. Use `:hyphenate="false"` to keep words
whole. Custom split rules are not supported.

```vue
<PdfText :hyphenate="false">Donaudampfschifffahrtsgesellschaft</PdfText>
```

## Pass plain values

A `ref` or another value that is not plain data inside a style or prop fails
with `PDF_TREE_INVALID`. Pass the value, not the `ref`: a style object built
in `<script setup>` uses `{ color: color.value }`.

The render also checks every `:style` and `v-bind()` value. A value that the
engine cannot read correctly, and that rendered wrong before, now fails with
`PDF_TREE_INVALID`: an unsupported unit such as `em`, a misspelled color or
keyword, a keyword in upper case such as `'Center'`, a border color with alpha
or a border color that the engine paints black (`'transparent'`, a color name
in upper case), or `false` in a style object. The message names the key, the
value, and the expected form. A value that rendered correctly still passes,
also when the `<style>` block rejects it. See
[Style object values]($docs.styles#style-object-values).

## Update `pdf.limits`

`pdf.limits` has seven options: `timeoutMs`, `maxPages`, `maxNodes`,
`maxTotalImageBytes`, `maxTotalImagePixels`, `maxRemoteRequests`, and
`maxTotalAttachmentBytes`. Each removed key fails module setup with a message
that says what to set.

| Removed key | Change |
| ----------- | ------ |
| `maxImageBytes`, `maxImagePixels` | Remove them. `maxTotalImageBytes` and `maxTotalImagePixels` are the budget for all images of one render. |
| `maxTreeDepth`, `maxTextCharacters`, `maxImages`, `maxOutputBytes` | Remove them. |
| `maxRemoteConcurrency` | Remove it. Remote requests run at most four at a time. |

See [Errors and limits]($docs.errors-and-limits).

## Remove content from leaf primitives

Text or an element inside `PdfImage`, an SVG shape, `PdfStop`, or a page token
now fails with `PDF_TREE_INVALID`, for example
`<PdfImage> cannot contain text.` Before, the content was dropped without a
message. Remove the content, or put it next to the element.

## Correct unknown tags

An unknown `<Pdf…>` tag now fails the build with its position and the nearest
known name. Before, it failed only when that tag rendered. Correct the name,
or import the component.

## Check page breaks near fixed content

- A view whose first page would hold only its `fixed` children, such as a
  repeated header alone at the page bottom, starts on the next page. Check the
  page breaks of views with `fixed` children.
- Fixed content that is as high as the page content area fails at once with
  `PDF_LAYOUT_ERROR`. Before, the render ran until the timeout.

## Update code that matches error text

- The error for page numbers that do not settle within `maxPasses` starts
  with "Page numbers did not stabilize".
- Compile error positions are file positions. Template compile errors moved
  from the line inside the `<template>` block to the line in the file.

## Install the standalone build peers

A project that calls `buildPdfRegistry()` from `@lupinum/nuxt-pdf/build` must
install `typescript` and `vue-tsc`:

```bash
pnpm add -D typescript vue-tsc
```

A Nuxt project that only uses the module needs nothing new.
