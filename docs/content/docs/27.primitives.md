Every primitive is an auto-registered global component. The tables below are
drawn from the shipped prop types. `style` values use Nuxt PDF's framework-owned
`PdfStyle` contract (see
[Styling and layout]($docs.styling-and-layout)). A primitive with a `style` prop
also takes `class` and `:class` with the classes of the file's `<style>` block
(see [Styles]($docs.styles)).

The same surface is enforced after Vue mounts the tree. Each primitive has a
closed runtime prop allowlist; unknown props, DOM/event attributes, and props
used on the wrong primitive fail with `PDF_TREE_INVALID` rather than passing
through or silently doing nothing.

Leaf primitives hold no content: `PdfImage`, the SVG shapes (`PdfPath`,
`PdfRect`, `PdfCircle`, `PdfEllipse`, `PdfLine`, `PdfPolyline`, `PdfPolygon`),
`PdfStop`, the page tokens (`PdfPageNumber`, `PdfPageCount`, `PdfPageRef`,
`PdfRunningText`), `PdfLeader`, `PdfAttachment`, `PdfFacturX`, `PdfContents`,
and the form fields. Text or an element inside one of them fails
with `PDF_TREE_INVALID`, for example `<PdfImage> cannot contain text.` Remove
the content, or put it next to the element. Whitespace and comments are not
content.

## Shared base props

`PdfPage`, `PdfView`, page-flow `PdfText`, `PdfImage`, `PdfLink`, and `PdfNote`
share these:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `id` | `string` | None | Makes the node a named destination for `#id` links and `PdfPageRef`. It cannot start with `__nuxtPdfFootnote-` or `__nuxtPdfContents-`: the notes of footnotes and the entries of a `PdfContents` use these ids. |
| `fixed` | `boolean` | `false` | Repeats the node on every page of its parent. See [Fixed content and pages]($docs.page-breaking#fixed-content-and-pages). |
| `break` | `boolean \| 'column'` | `false` | Forces a page break before the node, at every depth; `'column'` starts the next column. See [Page breaks]($docs.page-breaking#page-breaks) for where it is ignored or not allowed. |
| `keepWithNext` | `boolean` | `false` | Starts the node on the page where the next node in its container starts. See [Keep with the next node]($docs.page-breaking#keep-with-the-next-node). |
| `minPresenceAhead` | `number` | `0` | Minimum space in points that must follow, or the node moves to the next page. The space starts below the node's bottom margin and reaches at most to the end of the last flow node after it in the same container, and stops before a node with `break`: near the end of a container, or before a break, it asks for less. Use [`keepWithNext`]($docs.page-breaking#keep-with-the-next-node) to keep a node with the node after it. |
| `debug` | `boolean` | `false` | Draws the node's layout box for debugging. |
| `style` | `PdfStyleValue` | None | A style object or nested array. `false`, `null`, and `undefined` entries are ignored. |
| `decorative` | `boolean` | `false` | In a tagged document (`'PDF/UA-1'` or `'PDF/A-3a'`): the node and everything inside it are an artifact that assistive technology skips. No effect otherwise. See [Accessible PDF]($docs.accessible-pdf). |

`PdfPage`, `PdfView`, `PdfText`, and `PdfImage` additionally accept `bookmark`
(`string`, or `{ title, expanded?, contents? }`) to build the outline.
`contents: false` leaves the node out of a [`PdfContents`](#pdfcontents).

## PdfDocument

The root. Carries document metadata; takes no base props. Its children are
`PdfPage`, `PdfAttachment`, and `PdfFacturX`.

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `title`, `author`, `subject`, `keywords` | `string` | None | Info-dictionary metadata. `'PDF/UA-1'` requires `title`. |
| `creator`, `producer` | `string` | `'nuxt-pdf'` | Info-dictionary producer metadata. |
| `language` | `string` | None | Document language tag, such as `'en'` or `'de-AT'`. Picks the hyphenation patterns that the style key `hyphens: 'auto'` uses. See [Hyphenate by document language]($docs.images-and-fonts#hyphenate-by-document-language). `'PDF/UA-1'` and `'PDF/A-3a'` require it. |
| `creationDate` | `Date` | Current render date | Info-dictionary creation date. The same document with the same `creationDate` gives the same bytes on every render in one environment, so a hash can detect a changed document. |
| `pdfVersion` | `'1.3'` through `'1.7'` or `'1.7ext3'` | `'1.3'` | PDF version in the file header, such as `%PDF-1.3`. `'1.7ext3'` is written as `1.7`. With `conformance` or `protection`, only `'1.7'` is accepted. |
| `conformance` | `PdfConformance \| readonly PdfConformance[]` | None | The standard the PDF claims and meets: `'PDF/A-3b'`, `'PDF/A-3a'`, or `'PDF/UA-1'`, or a list of them with at most one PDF/A level. See [PDF/A and Factur-X]($docs.pdf-a-and-factur-x) and [Accessible PDF]($docs.accessible-pdf). |
| `protection` | `PdfProtection` | None | Encrypts the PDF with AES-256: `openPassword`, `ownerPassword` (at least one), and `allow` with the permissions. Conflicts with PDF/A and `PdfFacturX`. See [Password protection]($docs.protection). |
| `pageLayout` | `'singlePage' \| 'oneColumn' \| 'twoColumnLeft' \| 'twoColumnRight' \| 'twoPageLeft' \| 'twoPageRight'` | None | Reader page layout. |
| `footnotes` | `'document' \| 'page'` | `'document'` | How [footnotes](#pdffootnote) are numbered: through the whole document in reading order, or from 1 on each page. |
| `footnoteStyles` | `PdfFootnoteStyles` | See [footnote styles](#pdffootnote) | `{ mark?, note?, area?, rule? }`: the styles of every footnote, each merged over its default. |

`pageMode`, `modificationDate`, `userPassword` and `permissions` are not props.
To encrypt, use `protection`.

Set `title` and `language` here or in
[`definePdf`]($docs.define-pdf#metadata-resolution), never in both: a value in
both places fails with `PDF_TREE_INVALID`. The checks of `'PDF/UA-1'` and
`'PDF/A-3a'` see the `definePdf` values.

## PdfPage

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `size` | `PdfPageSizeName \| [w, h] \| { width, height }` | `'A4'` | Uppercase named size or explicit dimensions. See [Page sizes]($docs.page-sizes). |
| `orientation` | `'portrait' \| 'landscape'` | `'portrait'` | Page orientation. |
| `dpi` | `number` | `72` | DPI used for `px` lengths on the page. Other units, and the page size in points, do not change with it. |
| `wrap` | `boolean` | `true` | Paginates content. `false` grows the page to fit. |

Plus the base and bookmark props.

A page with `columnCount` or `columnWidth` lays its flow out in
[columns]($docs.styles#columns).

## PdfView

The flexbox container. Base and bookmark props, plus:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `wrap` | `boolean` | `true` | Allows the view to split across a page boundary. |
| `pages` | `PdfFixedPages` | `'all'` | With `fixed`: the pages of its parent on which the view appears. See [Fixed content and pages]($docs.page-breaking#fixed-content-and-pages). |
| `tag` | `PdfViewTag` | None | In a tagged document: `'section'`, `'list'`, `'list-item'`, `'quote'`, `'caption'`, or `'figure'`. Without `tag` the view is a plain group. No effect without a tagged level. See [Group content]($docs.accessible-pdf#group-content). |
| `alt` | `string` | None | With `tag="figure"`: what the figure shows, for assistive technology. A tagged document requires `alt` or `decorative` on a figure view. Fails on a view without `tag="figure"`. See [Figures with a caption]($docs.accessible-pdf#figures-with-a-caption). |

A view with a `height` or `maxHeight` that fits the page content area does
not split across pages: when it crosses the page end, it moves whole to the
next page. A higher view splits at the page ends, and its parts share its
height. Its content keeps to its height: a text in it keeps only the lines
that fit, the last one with an ellipsis, and the render gives the layout
warning `PDF_CONTENT_HIDDEN` with the number of lines that are not drawn.
Give the view more height, or remove the height.

## PdfText

The only container for text has two context-specific prop branches.

In normal page flow it accepts the base and bookmark props, plus:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `wrap` | `boolean` | `true` | Allows text to split across pages. |
| `widows` | `number` | `2` | Minimum lines kept together at a page top. |
| `orphans` | `number` | `2` | Minimum lines kept together at a page bottom. |
| `pages` | `PdfFixedPages` | `'all'` | With `fixed`: the pages of its parent on which the text appears. See [Fixed content and pages]($docs.page-breaking#fixed-content-and-pages). |
| `tag` | `PdfTextTag` | `'p'` | In a tagged document: `'h1'` through `'h6'` for a heading, `'p'` for a paragraph. Not allowed on a nested `PdfText`. No effect without a tagged level. See [Headings]($docs.accessible-pdf#headings). |
| `running` | `PdfRunning` | None | Sets a running value that `PdfRunningText` prints: a name such as `'chapter'`, with the plain text of this text as the value, or `{ name, text }` with a value of its own. See [Running headers]($docs.document-tree#running-headers). |

A text with a `height` or `maxHeight` follows the same rules as such a view:
when it fits the content area, it moves whole when it crosses the page end,
and the lines past its height are not drawn, with the warning
`PDF_CONTENT_HIDDEN`.

Inside `PdfSvg`, it instead accepts:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `x`, `y` | `PdfSvgLength` | Required | SVG text coordinates. |
| `fill` | `string` | None | Direct SVG text paint color. |
| `style` | `PdfStyleValue` | None | Text metrics such as font family and size. `color` is not SVG paint. |

SVG text rejects page-flow-only props such as `id`, `bookmark`, `fixed`,
`break`, `wrap`, `widows`, `orphans`, `pages`, `tag`, and
`decorative`.

A `PdfText` holds text, nested `PdfText`, `PdfImage`, `PdfLink`, `PdfTspan`,
`PdfFootnote`, `PdfLeader`, and the page tokens below, `PdfRunningText`
included.

## Page tokens

`PdfPageNumber`, `PdfPageCount`, and `PdfPageRef` print page numbers inside a
page-flow `PdfText`, and `PdfRunningText` prints a running value. They are
resolved after layout.

| Component | Props | Prints |
| --------- | ----- | ------ |
| `PdfPageNumber` | None | The number of the page the surrounding text is painted on. |
| `PdfPageCount` | None | The total number of pages in the document. |
| `PdfPageRef` | `to` (`string`, required) | The number of the first page that shows the element with the id `to`. |
| `PdfRunningText` | `name` (`string`, required); `at` (`'top'`, `'before'` or `'end'`, default `'top'`) | The running value `name` of the page the surrounding text is painted on. Only in a `fixed` node. Nothing before the first text that sets it. |

See [Page tokens]($docs.page-breaking#page-tokens) for where to put them, how they print and when they fail.

## PdfImage

Base and bookmark props, plus:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `src` | `PdfImageSource` | Required | Image source. |
| `alt` | `string` | None | What the image shows, for assistive technology. A tagged document requires `alt` or `decorative`, except for an image inside a `PdfSvg` or a `figure` view. |

`PdfImageSource` is a `pdfs/assets`-relative path, a `Uint8Array`/`ArrayBuffer`,
`{ data, format: 'png' \| 'jpg' }`, or `{ uri, format? }`.

The pixel size of an image never sets its size. Without `width` and `height`
in its style, an image is as wide as its parent gives it, in a column the
whole content width, so a small image scales up. Its height follows its aspect
ratio. With only `width` or only `height`, the other follows the aspect ratio.
An image is never higher than the page's content area less its own vertical
margins and 10 pt: a higher one is scaled down. Set `width` and `height`, with
`objectFit`, to give it a fixed box.

## PdfLink

Base props (no bookmark), plus:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `href` | `string` | Required | `#id` jumps to the element with that `id`. An absolute `http:`, `https:`, `mailto:` or `tel:` URL opens outside the PDF. Any other value, such as a relative path or a `javascript:` URL, fails with `PDF_TREE_INVALID`. |
| `wrap` | `boolean` | `true` | Allows the link to split across pages. |
| `hitSlop` | `{ top?, right?, bottom?, left? }` | None | Expands the clickable area. Each side is a number of 0 or more. |

A `PdfLink` is blue (`#0000FF`) and underlined by default. Its own style replaces
these defaults: `textDecoration: 'none'` removes the underline, and `color`
sets its color. Without its own `color`, a link does not take the color of the
text around it.

## PdfLeader

A leader fills the rest of a line between two parts of a text, such as a
title and its page number, or a dish and its price. It goes inside a
`PdfText` and holds no content:

```vue
<PdfText>
  <PdfText>Grilled trout</PdfText>
  <PdfLeader />
  <PdfText>24.50</PdfText>
</PdfText>
```

The leader draws a line on the baseline from the end of the text before it
to the start of the text after it. That text ends at the right edge of the
text box. When the title wraps, the leader starts at the end of its last line.

- A line never breaks at a leader. When the last word before the leader and
  the text after it do not fit, they move to the next line with the leader.
- Two leaders on one line share the room equally.
- A line with a leader is not justified or aligned: the leader takes the
  room.
- A copied or extracted text reads a space in place of the leader. In a
  tagged document, the line is an artifact.

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `style` | `PdfLeaderStyle \| PdfLeaderStyleEntry[]` | See below | The line and the gaps at its ends. |

| Style | Default | Description |
| ----- | ------- | ----------- |
| `borderBottomStyle` | `'dotted'` | `'dotted'`, `'dashed'` or `'solid'`. |
| `borderBottomWidth` | `0.75` | The thickness of the line, in points. `0` draws no line and keeps the gaps. |
| `borderBottomColor` | `'#6e6e6e'` | The color of the line. |
| `marginLeft`, `marginRight` | `'0.3em'` | The gaps between the line and the text before and after it. A length; the em is the font size of the text around the leader. |

The dots and dashes start on a grid from the left edge of the page, so the
dots of leaders above each other line up.

These fail with `PDF_TREE_INVALID`:

- a `PdfLeader` outside a `PdfText`, or in SVG text;
- another style key, `marginBottom` included: the line is on the baseline;
- a percentage or `auto` margin.

## PdfFootnote

A footnote. It goes inside a page-flow `PdfText`, at the place it refers to.
There the text prints a mark: the number of the note, raised. The content of
the footnote is the note, which prints at the bottom of the page that holds
the mark.

```vue
<PdfText>
  Peat stores twice as much carbon as all forests<PdfFootnote>Source: <PdfLink href="https://example.org/peat">the peatland report</PdfLink>, page 12.</PdfFootnote>.
</PdfText>
```

`PdfFootnote` takes no props. The note holds text, nested `PdfText`,
`PdfLink` and `PdfPageRef`. The marks are numbered through the document, or
from 1 on each page with `footnotes="page"` on `PdfDocument`. A per-page
number is known only once the pages are laid out, so each mark keeps room for
its number through the document: a mark that prints a shorter number leaves a
little extra space in its line. Each mark is a link to its note, and the
number in front of the note is a link back to the mark.

When the notes of one page cannot all fit on it (for example a block with
`wrap={false}` that holds many marks), the notes that do not fit print first
in the note area of the next page, in order, and the render reports the layout
warning `PDF_FOOTNOTES_MOVED`. A note that moves keeps the number of its mark.

Style all footnotes in one place, with `footnoteStyles` on `PdfDocument`. Each
style merges over its default:

| Part | Styles | Default |
| ---- | ------ | ------- |
| `mark` | The number in the text, and the number at the start of the note | `verticalAlign: 'super'`, `fontSize: '70%'` |
| `note` | Each note | None |
| `area` | The box at the bottom of a page that holds its rule and notes | `marginTop: 8`, `fontSize: '85%'` |
| `rule` | The line at the top of the area, or `false` for none | `width: '33%'`, `borderTopWidth: 0.5`, `marginBottom: 4` |

The area is a box like a `PdfView` that spans the content width: `marginTop`
is the least space between the text and the area, and `gap` the space
between notes. The notes inherit its text styles, such as `fontSize` and
`color`. The rule is a box at the top of the area: its top border is the
line, `width` its length (a percentage is of the area's width), and
`marginBottom` the space above the notes. For a
line over the full width, set `rule: { width: '100%' }`.

On a page with [columns]($docs.styles#columns), the area also spans the
content width, below all columns. The notes of marks in all columns come in
reading order, column by column. A column container that ends on the page is
balanced above the area. When the notes leave too little room for it, it
continues on the next page and is balanced there. Its columns on the page with
the notes all stop at one height, so the page is as full as one height allows:
three columns can hold 7, 7 and 7 lines where 8, 8 and 7 would fit.

A raised mark can make its line taller than the text's `lineHeight`. With
the default mark style, this happens when `lineHeight` is below about 1.16
with Helvetica, 1.18 with Times and 1.19 with Courier. The limit does not
depend on the font size. So with `lineHeight: 1.2` or more, lines with marks have the
same spacing as the other lines. For a custom font the limit is
0.33 + 0.7 × the font's ascent + its descent, both in em.

```vue
<PdfDocument language="en" :footnote-styles="{ mark: { color: '#2f6b3a' }, area: { gap: 2 }, rule: { borderTopColor: '#9aa59c' } }">
  <PdfPage>
    <PdfText>Peat<PdfFootnote>Source: the peatland report.</PdfFootnote></PdfText>
  </PdfPage>
</PdfDocument>
```

A key that places a box fails: `position` and the offsets in every part, and
in `mark`, `note` and `area` also sizes such as `width` or `maxHeight` and
flex keys such as `flexGrow`. The layout sets the margins of the area, so
only its `marginTop` is taken. Only the `mark` can be raised or lowered.

These fail with `PDF_TREE_INVALID`, each with a message that says what to do:

- a footnote outside a `PdfText`;
- a footnote in a `fixed` node, such as a header, a footer or a
  `PdfTableHeader`: the node repeats on every page, and so would its note;
- a footnote in a `PdfLink`: its mark is a link to the note;
- a footnote in the note of another footnote;
- a footnote without a note;
- a `PdfPageNumber` or `PdfPageCount` in a note: the notes are laid out
  before the pages are known;
- `fixed`, `break`, `wrap`, `minPresenceAhead` or `bookmark` on a text in a
  note: the note is laid out once, at the bottom of its page;
- a `style` or `class` on `PdfFootnote`: use `footnoteStyles.note` and
  `footnoteStyles.mark`;
- an `id` that starts with `__nuxtPdfFootnote-`: the notes and their marks
  use these ids;
- in a document that claims PDF/UA-1 or PDF/A-3a, a footnote in a
  `decorative` node or inside a figure: the note must be in the reading
  order.

In a tagged document, the mark and the note have their own structure; see
[What is tagged without props]($docs.accessible-pdf#what-is-tagged-without-props).

A footnote in a table cell keeps the cell a text cell. For footnotes from a
CMS, see [Rich text]($docs.rich-text#footnotes).

## PdfContents

A table of contents. It lists the nodes with a `bookmark`, nested as the
outline nests them, with the page number of each. It goes in the page flow and
holds no content.

```vue
<PdfContents :levels="2" />
```

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `levels` | `number` | `3` | The outline levels it lists: a whole number from 1 to 6. |
| `leader` | `'dots' \| 'none'` | `'dots'` | `'dots'` prints a dotted [leader](#pdfleader) between title and page number. `'none'` prints no line and keeps the gaps. |
| `styles` | `PdfContentsStyles` | See below | `{ entry?, title?, leader?, page?, level1? … level6? }`: the styles of the parts of the entries. |

The title of an entry is the title of its bookmark. A bookmark with
`contents: false` has no entry, and the entries below it move up one level.
Each entry is a link to its node. A node without an `id` gets one that starts
with `__nuxtPdfContents-`. An entry never splits across pages or columns. The
page numbers work as [`PdfPageRef`](#page-tokens) does, so a document with a
contents takes a second layout pass. A document can hold more than one
contents.

Each entry is one text: the title, a [`PdfLeader`](#pdfleader) and the page
number. The leader runs from the end of the title's last line, and the page
number ends at the right edge. A title that wraps runs to the right edge on
its other lines. Each style in `styles` merges over its default. The lengths
in em follow the text size at the place of the contents:

| Part | Styles | Default |
| ---- | ------ | ------- |
| `entry` | Each entry: a link around its text | `marginTop: '0.25em'`; the text color at the place of the contents, without underline |
| `title` | The title: text styles only, such as `color`, `fontSize` and `fontWeight` | None |
| `leader` | The leader: the styles of [`PdfLeader`](#pdfleader) | The defaults of `PdfLeader` |
| `page` | The page number: text styles only, such as `color`, `fontSize` and `fontWeight` | None |
| `level1` | The entries of the first level | `marginTop: '0.6em'`, `fontWeight: 'bold'` |
| `level2` to `level6` | The entries of that level | `marginLeft`: 1.5em for each level below the first |

```vue
<PdfContents :styles="{ level1: { fontWeight: 'normal', textTransform: 'uppercase' }, page: { color: '#2f6b3a' } }" />
```

These fail with `PDF_TREE_INVALID`, each with a message that says what to do:

- a contents in a document without a `bookmark`;
- a contents in a `fixed` node: the node repeats on every page, and so would
  the contents;
- a contents in a `PdfLink`, in a `PdfText` or in a `PdfTableCell`;
- `levels` that is not a whole number from 1 to 6, another `leader`, a part
  of `styles` that does not exist, or a style that is not valid;
- a box style such as `width`, `textAlign` or `flexShrink` in `styles.title`
  or `styles.page`, which are text inside the entry's line, and a style in
  `styles.leader` that `PdfLeader` does not take;
- a `style` or `class` on `PdfContents`: use `styles`, or put the contents in
  a `PdfView` with the style;
- a bookmark with a `contents` value other than `false`;
- an `id` that starts with `__nuxtPdfContents-`.

In a tagged document, the contents has its own structure; see
[What is tagged without props]($docs.accessible-pdf#what-is-tagged-without-props).

## PdfNote

A sticky-note annotation. Base props only; its text comes from its content.
A document that claims PDF/A or a tagged level rejects `PdfNote`; print the
note as `PdfText` instead.

## PdfTextField, PdfCheckbox, PdfRadio, PdfSelect

Form fields: a text field, a checkbox, an option of a radio group and a
drop-down list that a reader fills in. Each is a leaf with a fixed box; its
style must set `width` and `height`. They take `name` (required, unique;
radios with one name form one group), `label`, `readOnly`, `required` and
`style`, and no base props.

| Primitive | Props |
| --------- | ----- |
| `PdfTextField` | `value?: string`, `multiline?: boolean`, `maxLength?: number` |
| `PdfCheckbox` | `checked?: boolean`, `exportValue?: string` (default `'Yes'`) |
| `PdfRadio` | `value: string`, `checked?: boolean` (at most one option of a group) |
| `PdfSelect` | `options: readonly string[]`, `value?: string`, `editable?: boolean` |

Nuxt PDF draws each field in Helvetica (in a document with `conformance`: in the
field's registered font, embedded whole): the style sets `fontSize` (default `10pt`), `color`,
`textAlign`, `padding` (default `2pt`), the border and the background. Field
values and options use WinAnsi characters only. A `PdfFacturX` invoice
rejects form fields. In a tagged document (`'PDF/UA-1'` or `'PDF/A-3a'`), every
field needs a `label`, and a field cannot be in a `decorative` node or a figure.
See
[Fillable forms]($docs.forms).

## PdfAttachment

Embeds a file in the PDF. It is a direct child of `PdfDocument`, next to the
pages. It paints nothing and has no children.

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `name` | `string` | Required | File name that PDF viewers show. At most 255 characters, no `/`, `\`, or control characters, unique within the document. |
| `data` | `string \| Uint8Array` | Required | File content. A string is embedded as UTF-8. It is the content, never a path or URL. |
| `type` | `string` | None | MIME type such as `text/xml`. |
| `description` | `string` | None | Description that PDF viewers show. |
| `relationship` | `PdfAttachmentRelationship` | `'Unspecified'` | `'Alternative'`, `'Data'`, `'Source'`, `'Supplement'`, or `'Unspecified'`. Written as the PDF `AFRelationship` key. |

```vue
<PdfDocument language="en">
  <PdfAttachment name="invoice.xml" :data="invoiceXml" type="text/xml" relationship="Data" />
  <PdfPage size="A4">
    <PdfText>Invoice {{ invoice.number }}</PdfText>
  </PdfPage>
</PdfDocument>
```

An invalid prop, a duplicate `name`, or a child fails with `PDF_TREE_INVALID`.
The bytes of all attachments of one render count against
[`pdf.limits.maxTotalAttachmentBytes`]($docs.errors-and-limits). The
attachment date is the document's creation date, so a fixed `creationDate`
gives the same bytes on every render. An attachment does not make the PDF
conform to PDF/A-3 or an e-invoice profile; use `conformance` and `PdfFacturX`
for that. In a document with `PdfFacturX`, an attachment cannot use the file name of the
invoice XML: `factur-x.xml`, or `xrechnung.xml` for the `XRECHNUNG` profile.

## PdfFacturX

Embeds the XML invoice of a Factur-X (ZUGFeRD 2) hybrid invoice. It is a direct
child of `PdfDocument`, at most once per document. It paints nothing, has no
children. Its `PdfDocument` must claim `conformance="PDF/A-3b"` (or
`"PDF/A-3a"`); without a PDF/A-3 level, the render fails.

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `invoice` | `EInvoice` | None | The invoice data. The render writes the CII XML for `profile` from it. Give `invoice` or `xml`, not both. See [E-invoices]($docs.e-invoices). |
| `xml` | `string \| Uint8Array` | None | The finished CII XML content. A string is embedded as UTF-8. It is the content, never a path or URL. Give `invoice` or `xml`, not both. |
| `profile` | `PdfFacturXProfile` | Required | `'MINIMUM'`, `'BASIC WL'`, `'BASIC'`, `'EN 16931'`, `'EXTENDED'`, or `'XRECHNUNG'`. With `xml`, it must match the profile that the XML names. With `invoice`, `'EXTENDED'` is not available. |
| `relationship` | `PdfFacturXRelationship` | `'Data'` for `MINIMUM` and `BASIC WL`, else `'Alternative'` | `'Data'`, `'Alternative'`, or `'Source'`. Written as the PDF `AFRelationship` key. |

```vue
<PdfDocument title="Invoice 2026-014" language="en" conformance="PDF/A-3b">
  <PdfFacturX :invoice="invoice" profile="EN 16931" />
  <PdfPage size="A4" :style="{ fontFamily: 'Invoice Sans' }">
    <PdfText>Invoice 2026-014</PdfText>
  </PdfPage>
</PdfDocument>
```

The XML is embedded as `factur-x.xml` (`xrechnung.xml` for `XRECHNUNG`), with
the MIME type `text/xml`. Its bytes count against
[`pdf.limits.maxTotalAttachmentBytes`]($docs.errors-and-limits). The
[PDF/A and Factur-X guide]($docs.pdf-a-and-factur-x) explains the font
requirement and every failure.

`PdfTable`, `PdfTableHeader`, `PdfTableRow`, and `PdfTableCell` are global
components built from `PdfView` and `PdfText`. Their props, column widths,
spans, and cell rules are on their own page: [Tables]($docs.tables).

## PdfRichText

`PdfRichText` is a global component that prints editor HTML (`html`), a rich
text model (`content`) or a parsed comark document (`comark`) with `PdfView`, `PdfText` and `PdfLink`. Like the table
components, it is not a primitive. See [Rich text]($docs.rich-text).

```vue
<PdfRichText :html="article.body" class="body" bookmarks />
```

| Prop | Type | Meaning |
| ---- | ---- | ------- |
| `html` | `string` | Editor HTML. Exactly one of `html`, `content` and `comark`. |
| `content` | `readonly PdfRichBlock[]` | A rich text model, for example from `parseRichTextMarkdown`. Exactly one of `html`, `content` and `comark`. |
| `comark` | `unknown` | A document that comark parsed (the object with `nodes`) or its node list. Exactly one of `html`, `content` and `comark`. |
| `components` | `Record<string, Component>` | Vue components by comark component name. See [Components]($docs.rich-text#components). |
| `bookmarks` | `boolean` | Each heading becomes an outline entry. Default `false`. |
| `brokenImages` | `'placeholder' \| 'error'` | What an image does when the asset rules refuse its source. `'error'` (default) fails the render with the asset error; `'placeholder'` prints its `alt` text in a box and adds an entry to `diagnostics.imageWarnings`. |
| `styles` | `PdfRichTextStyles` | A style per element (`p`, `h1` to `h6`, `list`, `listItem`, `marker`, `quote`, `code`, `codeBlock`, `link`, `strong`, `em`, `sup`, `sub`, `rule`, `image`, `caption`, `imagePlaceholder`, `table`, `tableHeader`, `tableRow`, `tableCell`, `tableHeaderCell`), merged over the defaults. |

`class`, `style` and `id` apply to the view around the text. Its `fontSize`
sets the scale of headings and spacing.

## SVG primitives

SVG primitives render inside a `PdfSvg`. Paint, geometry, clipping, and
transforms are direct props. `PdfG` and the shape primitives have no generic
`style` prop, so there is no style-precedence path; kebab-case Vue attributes
are normalized to the equivalent camelCase key. See
[SVG graphics]($docs.svg-graphics).

`PdfSvgNumber` is a finite number or numeric string. `PdfSvgLength` additionally
accepts a numeric percentage string where the individual prop permits it.
`strokeWidth` is never a percentage. Non-negative geometry and unit-interval
opacity/stop ranges are checked at runtime.

### Shared SVG presentation props

Available on `PdfG`, `PdfPath`, `PdfRect`, `PdfCircle`, `PdfEllipse`, `PdfLine`,
`PdfPolyline`, and `PdfPolygon`:

| Prop | Type |
| ---- | ---- |
| `fill`, `stroke` | `string` |
| `fillOpacity`, `strokeOpacity` | `PdfSvgLength` (0 to 1 or 0% to 100%) |
| `strokeWidth` | `PdfSvgNumber` (non-negative) |
| `strokeLinecap` | `'butt' \| 'round' \| 'square'` |
| `strokeLinejoin` | `'miter' \| 'round' \| 'bevel'` |
| `transform` | `PdfSvgTransform`. One to three unitless `translate(...)` or `rotate(...)` operations. |
| `clipPath` | `string` with the value `url(#id)` |

### Geometry props

| Component | Own props |
| --------- | --------- |
| `PdfSvg` | `viewBox`, `width`, `height`, plus page-flow `style` (not SVG presentation), and `alt` and `decorative` as on `PdfImage` |
| `PdfG` | *(presentation props only)* |
| `PdfPath` | `d` **(required)** |
| `PdfRect` | `x`, `y`, `width` **(required)**, `height` **(required)**, `rx`, `ry` |
| `PdfCircle` | `cx`, `cy`, `r` **(required)** |
| `PdfEllipse` | `cx`, `cy`, `rx` **(required)**, `ry` **(required)** |
| `PdfLine` | `x1`, `y1`, `x2`, `y2` **(all required)** |
| `PdfPolyline` / `PdfPolygon` | `points` **(required)** |
| `PdfDefs` | None. It holds definitions that other elements can reference. |
| `PdfClipPath` | `id` **(required)** |
| `PdfLinearGradient` | `id` **(required)**, `x1`, `y1`, `x2`, `y2` |
| `PdfRadialGradient` | `id` **(required)**, `cx`, `cy`, `r`, `fx`, `fy` |
| `PdfStop` | `offset` **(required)**, `stopColor` **(required)**, `stopOpacity` |
| `PdfTspan` | `x`, `y`, `fill` only |

Alternate gradient coordinate systems, transforms, inheritance, and SVG
`preserveAspectRatio` modes are not public props. See
[Supported behavior and limitations]($docs.supported-behavior).

Each `PdfSvg` accepts at most one direct `PdfDefs` child. Definition ids are
safe, unique, and scoped to that one SVG. `fill="url(#id)"` must resolve to a
linear or radial gradient; `clipPath="url(#id)"` must resolve to a
`PdfClipPath`. Missing, malformed, or incompatible references fail with
`PDF_TREE_INVALID`.

Explicit zero has SVG semantics: zero fill opacity is transparent, zero stroke
width removes the stroke instead of requesting a PDF hairline, and supported
gradient coordinates remain zero.
