`PdfTable`, `PdfTableHeader`, `PdfTableRow`, and `PdfTableCell` are global
components built from `PdfView` and `PdfText`. They are not primitives: the
mounted tree contains only views and texts. In a tagged document they become a
table with header cells, data cells, and column and row spans, without extra props. See
[Accessible PDF]($docs.accessible-pdf#what-is-tagged-without-props).

```vue
<PdfTable :columns="['28pt', 1, '78pt']" class="lines">
  <PdfTableHeader class="head">
    <PdfTableCell>#</PdfTableCell>
    <PdfTableCell>Description</PdfTableCell>
    <PdfTableCell align="right">Amount</PdfTableCell>
  </PdfTableHeader>
  <PdfTableRow v-for="(line, index) in invoice.lines" :key="line.id" class="row">
    <PdfTableCell>{{ index + 1 }}</PdfTableCell>
    <PdfTableCell>{{ line.title }}</PdfTableCell>
    <PdfTableCell align="right">{{ money(line.total) }}</PdfTableCell>
  </PdfTableRow>
</PdfTable>
```

| Component | Renders | Props |
| --------- | ------- | ----- |
| `PdfTable` | `PdfView` | `columns` (required, `readonly PdfTableColumn[]`): one entry per column, in cell order. Other `PdfView` props, `class`, and `style` pass to the view. |
| `PdfTableHeader` | `fixed` `PdfView` in row direction | `PdfView` props pass to the view: `:fixed="false"` prints the header once, `pages` limits it. |
| `PdfTableRow` | `PdfView` with `wrap: false` in row direction | `PdfView` props pass to the view: `:wrap="true"` lets a tall row split across pages. `running` (`{ name, text }`) sets a running value, such as a carried subtotal (see [Carried subtotals]($docs.recipes#carried-subtotals)). |
| `PdfTableCell` | `PdfView` | `align`: `'left'`, `'center'`, or `'right'` (default: the `align` of its column, else `'left'`); `colspan`: a whole number from 1 (default `1`); `rowspan`: a whole number from 1 (default `1`), see "Spanning rows" below; `header` (`boolean`, default `false`): in a tagged document, a cell in a `PdfTableRow` is the header of its row; `class` and `style`. |

A column entry is a share, a width, or `'auto'`:

- A number is a share of the free width, like `flex-grow`. `[2, 1]` gives the
  first column two thirds of the width.
- A string is a fixed width: a length with a unit or a percentage, such as
  `'80pt'` or `'30%'`.
- `'auto'` makes the column as wide as its widest cell on one line. See
  "Automatic column widths" below.

An entry can also be a `PdfTableColumnOptions` object,
`{ width, align, style }`. `width` is required and takes one of the forms
above. `align` and `style` apply to each cell that starts in the column, header cells included; a spanning cell takes
those of its first column. The cell's own `align`, class, and style win.
`style` is a style object, checked as a cell's style is, and the same rules
for widths and margins apply to it. Any other key fails with
`PDF_TREE_INVALID`; a column takes no `class`, so put a class on the cell.

A text style in a column's `style` also beats what a cell inherits from its
row: with `{ width: 'auto', style: { fontWeight: 400 } }`, the header cell of
that column is not bold even in a bold header row. Set the style on the header
cell to change it.

```vue
<PdfTable :columns="['auto', 1, { width: 'auto', align: 'right', style: { fontWeight: 700 } }]">
  <PdfTableRow v-for="line in invoice.lines" :key="line.id">
    <PdfTableCell>{{ line.quantity }}</PdfTableCell>
    <PdfTableCell>{{ line.description }}</PdfTableCell>
    <PdfTableCell>{{ money(line.total) }}</PdfTableCell>
  </PdfTableRow>
</PdfTable>
```

The header repeats at the top of every page that the table reaches. A row does
not split across pages unless it sets `wrap`. `keepWithNext` on a row keeps
it with the next row. A row that splits keeps every
cell in its column on both pages, and a row with nothing to show above the page
end moves to the next page whole. An image cell that crosses the page end moves
to the next page; one higher than the page stays on its page. The orphan rule in
[Fixed content and pages]($docs.page-breaking#fixed-content-and-pages) applies: the table does
not end a page with only its header.

A cell gets its width from its column, also when a local component renders
the cell, and whatever its padding. A horizontal margin of `'auto'` on a cell
fails with `PDF_TREE_INVALID`: use `textAlign` to place its text, `align` on
the cell or its column to place its content, or a `PdfView` inside the cell to
place a box. A cell's own `width`, `minWidth`, or `maxWidth` fails with
`PDF_TREE_INVALID` unless every column it covers is `'auto'`: set the width in
`columns`. A horizontal margin on a cell sits inside its columns: it narrows
the cell, and the later cells of the row stay in their columns. It is a
length: a margin in percent on a cell fails with `PDF_TREE_INVALID`. So do
`flex`, `flexBasis`, `flexGrow`, and `flexShrink` on a cell, which would size
it in its row, and `position: 'absolute'`, which would take it out of its row;
put an absolute `PdfView` inside the cell instead.
A cell renders a `PdfView`, which passes text styles on to the texts inside
it. Its `align` sets both `textAlign` and `alignItems`, whatever the content.
A cell with only text puts it in one `PdfText` as wide as the cell, which
takes the `maxLines`, `textOverflow`, `textDecorationColor` and
`textDecorationStyle` of the cell's style. In a cell with other content, put
text inside `PdfText`. Because a cell is a view, `justifyContent` places its
content vertically: `:style="{ justifyContent: 'center' }"` centers it in a
row that a higher cell makes taller. A cell can hold page tokens and footnotes with text, such as `Page <PdfPageNumber />`. A row
can have fewer cells than columns; the columns after its last cell stay empty
at their width. A local component can render several cells; each takes its
own column.

## Automatic column widths

```vue
<PdfTable :columns="['auto', 1, 'auto']">
  <PdfTableRow v-for="line in invoice.lines" :key="line.id">
    <PdfTableCell>{{ line.position }}</PdfTableCell>
    <PdfTableCell>{{ line.title }}</PdfTableCell>
    <PdfTableCell align="right">{{ money(line.total) }}</PdfTableCell>
  </PdfTableRow>
</PdfTable>
```

An `'auto'` column is as wide as its widest cell on one line. The share
columns get the width that is left, and width columns keep their width. When
the table has less room, the `'auto'` columns get narrower together, each in
proportion to how much it can give, until each reaches its longest word. In a
table with `'auto'` columns, a share column is never narrower than its own
longest word.

The widths come from all rows and the header together, before the table is
split into pages, so every page shows the same columns. The padding, border,
and margin of a cell count. In a share column, a percentage width or edge
does not count for its least width.

- A cell that spans an `'auto'` column does not make it wider. It gets the
  width of the columns it covers, and its text wraps inside them. Only its
  own padding, border, and margin count: the columns it covers are together
  at least that wide.
- A cell fills its columns. On a cell over `'auto'` columns only, its own
  `width`, `minWidth` and `maxWidth` count for the width of the column, but
  the cell is always as wide as its columns. A cell keeps its own horizontal padding and border: in a table
  narrower than its longest words, a cell with more padding than the other
  cells of its column pushes the later cells of its row to the right, and
  the render reports it with `PDF_TABLE_COLUMNS_TOO_NARROW`.
- `PdfPageNumber` and `PdfPageCount` count as four of the widest digit.
  `PdfPageRef` counts as the page number it prints.
- An image, an SVG, a form field, or a view in row direction in an `'auto'`
  column needs a width of its own, such as `:style="{ width: '80pt' }"`. An
  element with its own width counts as that width. A numeric `maxWidth` or
  `minWidth` limits what an element counts as.
- In an `'auto'` column, a width, `minWidth` or `maxWidth` in percent, a
  horizontal padding or border in percent or `'auto'`, and a horizontal
  margin in percent fail with `PDF_TREE_INVALID`: the column measures its
  content in points before layout. Use a length, such as `'4pt'`. A
  margin of `'auto'` on an element inside a cell counts as 0, as it
  only takes free space, so
  `marginLeft: 'auto'` on an element with its own width moves it to the
  right of the cell.
- A cell cannot span a percentage column and an `'auto'` or share column.
- When the table is narrower than the longest words, the `'auto'` columns
  still get narrower, and their words break as words that are wider than
  their line do elsewhere. A column whose cells are one word each has no
  room to give and keeps that width. When the columns do not fit even then,
  the table is wider than its box, as an HTML table is. In both cases the
  render gives the layout warning `PDF_TABLE_COLUMNS_TOO_NARROW` (see
  [diagnostics]($docs.registry)).

## Spanning columns

`colspan` lets a cell cover several columns, also in `PdfTableHeader`:

```vue
<PdfTable :columns="['28pt', 1, '78pt']">
  <PdfTableRow v-for="line in invoice.lines" :key="line.id">
    <PdfTableCell>{{ line.position }}</PdfTableCell>
    <PdfTableCell>{{ line.title }}</PdfTableCell>
    <PdfTableCell align="right">{{ money(line.total) }}</PdfTableCell>
  </PdfTableRow>
  <PdfTableRow>
    <PdfTableCell :colspan="2" align="right">Total</PdfTableCell>
    <PdfTableCell align="right">{{ money(invoice.total) }}</PdfTableCell>
  </PdfTableRow>
</PdfTable>
```

A spanning cell is as wide as the columns it covers together: the shares add
up, and the fixed widths add up. Lengths add up only in the same unit or
between `pt`, `in`, `mm`, and `cm`. A span over `px`, `rem`, `vw`, or `vh`
columns and columns of another unit fails. A row counts each cell as the
number of columns it covers. A cell that spans percentage and length columns
together cannot take a right margin (`margin`, `marginHorizontal`, or
`marginRight`); use `paddingRight` for space inside it.

## Spanning rows

`rowspan` lets a body cell cover the rows below its own row:

```vue
<PdfTable :columns="['auto', 1, '78pt']">
  <PdfTableRow v-for="line in invoice.lines" :key="line.id">
    <PdfTableCell v-if="line.firstOfProject" :rowspan="line.projectLines" header>
      {{ line.project }}
    </PdfTableCell>
    <PdfTableCell>{{ line.title }}</PdfTableCell>
    <PdfTableCell align="right">{{ money(line.total) }}</PdfTableCell>
  </PdfTableRow>
</PdfTable>
```

Write the cells of the covered rows without the spanned column: each cell
takes the next column that no span from above takes.

- The cell is as high as the rows it covers. When its content needs more
  height, the last row it covers grows by the difference.
- The rows that a cell covers stay on one page. When they cross the page end,
  they move to the next page together. When they are higher than the page,
  or than the room below the header rows that repeat on the next page, they
  stay where they start and are cut at the page end, the same as a block with
  `wrap: false` that is higher than the page, and the render gives the layout
  warning `PDF_UNBREAKABLE_NODE_OVERFLOW` for them.
- The cell paints after the rows it covers, so the backgrounds of those rows
  do not hide it. The opacity of its row applies to it; a clip of its row
  (`overflow: 'hidden'`) does not, as the cell reaches below its row.
- The text of a cell over several rows starts at its top. To center it
  vertically, set `justifyContent`:
  `<PdfTableCell :rowspan="3" :style="{ justifyContent: 'center' }">{{ line.project }}</PdfTableCell>`.
- In an `'auto'` column, the content of the cell counts for the width of the
  column.
- In a tagged document, the cell is a `TD`, or a `TH` with `header`, with the
  `RowSpan` attribute.

A row that a span covers cannot set `wrap` or `break`. A header cell cannot
span rows, because the header repeats as one row.

Tables have no automatic borders between cells and no selector for the last
cell. Style each cell with a class. For a nested table, put a `PdfTable`
inside the cell.

Each of these fails with `PDF_TREE_INVALID`:

| Cause | Message |
| ----- | ------- |
| `columns` missing, empty, or with an entry that is not a positive number, a length with a unit, a percentage, `'auto'`, or an object | `<PdfTable> requires "columns": a non-empty list of shares (numbers), widths ('30%', '80pt'), 'auto', or { width, align, style }.` |
| A column object without a valid `width` | `<PdfTable> column 2 requires "width": a share (number), a width ('30%', '80pt') or 'auto'.` |
| A column object with an `align` other than `'left'`, `'center'` or `'right'` | `<PdfTable> column 2 requires "align" to be 'left', 'center' or 'right'.` |
| A column object with another key | `<PdfTable> column 2 has the key "class": a column takes width, align and style. Use style here, or class on the cell.` |
| More columns than the table declares, counting `colspan` and the columns that spans from above take | `<PdfTableRow> needs 4 columns (counting colspan), but its <PdfTable> declares 3.` |
| `colspan` that is not a whole number from 1 | `<PdfTableCell> requires "colspan" to be a whole number from 1.` |
| A static `colspan="2"`, which passes text and not a number | `<PdfTableCell> colspan="2" passes the text "2", not a number. Bind it: :colspan="2".` |
| A horizontal margin in percent on a cell | `<PdfTableCell> has a horizontal margin in percent (marginLeft "5%"): the margin sits inside the cell's columns, and a percentage cannot be taken off a column width. Use a length, such as '4pt'.` |
| A key in a column's `style` that is not a PDF style | `Unsupported PDF style "float" in the style of <PdfTable> column 2.` |
| A value in a column's `style` that the key does not take | `<PdfTable> column 2 style value -4 for "fontSize" is invalid: expected a value above 0.` |
| A `width`, `minWidth` or `maxWidth` on a cell over a column that is not `'auto'` | `<PdfTableCell> sets width 50: a cell is as wide as its columns. Set the width in columns, such as '80pt' or 'auto'.` |
| `flex`, `flexBasis`, `flexGrow` or `flexShrink` on a cell, or in a column's `style` | `<PdfTableCell> sets flexBasis 200: a cell is as wide as its columns. Set the width in columns, such as '80pt' or 'auto'.` |
| `position: 'absolute'` on a cell, or in a column's `style` | `<PdfTableCell> sets position "absolute": a cell stays in its row. Put an absolute <PdfView> inside the cell.` |
| A right margin on a span over percentage and length columns | `<PdfTableCell> spans percentage and length columns, so it cannot take a right margin (margin, marginHorizontal or marginRight). Use paddingRight for space inside the cell, or give the spanned columns one kind of width.` |
| `header` that is not `true` or `false` | `<PdfTableCell> requires "header" to be true or false.` |
| `rowspan` that is not a whole number from 1 | `<PdfTableCell> requires "rowspan" to be a whole number from 1.` |
| A static `rowspan="2"`, which passes text and not a number | `<PdfTableCell> rowspan="2" passes the text "2", not a number. Bind it: :rowspan="2".` |
| A `rowspan` past the last row of the table | `<PdfTableCell> spans 3 rows, but its <PdfTable> has only 2 rows from its row to the end.` |
| A `rowspan` in `PdfTableHeader` | `<PdfTableCell> in <PdfTableHeader> cannot span rows: a header repeats as one row.` |
| `wrap` or `break` on a row that a span covers | `<PdfTableRow> sets wrap, but a rowspan covers it: the rows of a span stay together on one page. Remove wrap.` |
| A cell over a column that a span from above takes | `<PdfTableCell> spans 2 columns up to column 2, but a rowspan from a row above takes column 2.` |
| A covered row inside another element, such as a `PdfView` | `<PdfTableRow> is covered by a rowspan, so it must be a row of its <PdfTable> itself, not inside another element.` |
| A span over widths in units that do not add up | `<PdfTableCell> spans columns in "px" and "pt"; their widths cannot be added. Use one unit for the columns it spans.` |
| An image, an SVG, a form field, or a view in row direction without a width in an `'auto'` column | `<PdfImage> in an 'auto' table column needs a width of its own, such as style width: '80pt': the column is as wide as its content, and text is the only content it measures.` |
| A percentage width, `minWidth` or `maxWidth` in an `'auto'` column | `<PdfText> with width "50%" in an 'auto' table column needs a width of its own in points, such as style width: '80pt': the column is as wide as its content, and a percentage of it is not known before layout.` |
| A horizontal padding or border in percent or `'auto'`, or a horizontal margin in percent, in an `'auto'` column | `<PdfTableCell> in an 'auto' table column has padding "5%": the column is as wide as its content in points, and a percentage or 'auto' padding or border, or a percentage margin, has no width before layout. Use a length, such as '4pt'.` |
| A span over a percentage column and an `'auto'` or share column, in a table with `'auto'` columns | `<PdfTableCell> spans a percentage column and an 'auto' or share column of a table with 'auto' columns: a percentage and a measured width cannot be added before layout. Give the percentage column a length, or do not span it.` |
| Text or a primitive directly in a row or header | `<PdfTableRow> holds <PdfTableCell> elements only.` |
| A row or header outside a table, or directly in a cell | `<PdfTableRow> must be inside <PdfTable>.` |
| A cell outside a row or header, or directly in a cell | `<PdfTableCell> must be inside <PdfTableRow> or <PdfTableHeader>.` |

The table components check what the template shows. Only the layout sees a
tree that sets the internal column props by hand, and it fails with
`PDF_LAYOUT_ERROR` and the same message for content it cannot measure, or with
`<PdfView> takes column 3 of a table with 2 columns.` for a cell over a column
the table does not have.
