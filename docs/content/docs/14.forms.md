A fillable form is a PDF with fields. The user types into the fields in a PDF
reader, saves the PDF, and sends it back. Nuxt PDF writes four kinds of field:
`PdfTextField`, `PdfCheckbox`, `PdfRadio` and `PdfSelect`.

## Add fields to a template

Give each field a `name` and a `width` and `height`. Put the visible label in a
`PdfText` next to the field:

```vue [pdfs/sign-up.vue]
<script setup lang="ts">
definePdf({ title: 'Volunteer sign-up', language: 'en' })
</script>

<template>
  <PdfDocument>
    <PdfPage size="A5" :style="{ padding: 40, fontSize: 10 }">
      <PdfText>Full name</PdfText>
      <PdfTextField name="fullName" label="Full name" required class="field" />

      <PdfText>Shift</PdfText>
      <PdfSelect name="shift" label="Shift" :options="['Morning', 'Afternoon']" value="Morning" class="field" />

      <PdfView :style="{ flexDirection: 'row', marginTop: 8 }">
        <PdfCheckbox name="newsletter" label="Send me the newsletter" class="box" />
        <PdfText :style="{ marginLeft: 6 }">Send me the newsletter</PdfText>
      </PdfView>
    </PdfPage>
  </PdfDocument>
</template>

<style>
.field {
  width: 100%;
  height: 20pt;
  margin-bottom: 8pt;
  padding: 4pt 5pt;
  border-width: 0.75pt;
  border-color: #9fb0b5;
}
.box {
  width: 10pt;
  height: 10pt;
  border-width: 0.75pt;
  border-color: #9fb0b5;
}
</style>
```

1. Open the PDF in a reader. Each field is a box the user can click and type
   into.
2. Fill the fields, save the PDF, and open it again. The values are kept.

Nuxt PDF draws each field itself: its border, background and value. The field
looks the same in every reader.

## Fields

All four fields take these props:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `name` | `string` | Required | The name a reader exports with the value. Unique in the document, except for the options of one radio group. No period. |
| `label` | `string` | None | The accessible name. Written as the field's description (`/TU`). Readers such as Acrobat show it as a tooltip; assistive technology reads it as the name in a tagged document. |
| `readOnly` | `boolean` | `false` | The reader shows the value but does not let the user change it. |
| `required` | `boolean` | `false` | Sets the Required flag. A reader can mark the field as required. Nuxt PDF writes no submit action. |
| `style` | `PdfStyleValue` | None | Must set `width` and `height`. See [Style a field](#style-a-field). |

`PdfTextField` also takes:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `value` | `string` | None | The text the field starts with. |
| `multiline` | `boolean` | `false` | Lets the user type several lines. `value` may then contain line breaks. |
| `maxLength` | `number` | None | The most characters the user can type: a positive whole number. A `value` longer than `maxLength` fails with `PDF_TREE_INVALID`. |

`PdfCheckbox` also takes:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `checked` | `boolean` | `false` | The box starts checked. A checked box shows a cross. |
| `exportValue` | `string` | `'Yes'` | The value a reader exports when the box is checked: letters, digits, `_` or `-`, and not `Off`. |

`PdfRadio` is one option of a radio group. It also takes:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `value` | `string` | Required | The value a reader exports when this option is on: letters, digits, `_` or `-`, and not `Off`. |
| `checked` | `boolean` | `false` | This option starts on. |

`PdfSelect` is a drop-down list. It also takes:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `options` | `readonly string[]` | Required | The choices, in order: a non-empty list of non-empty strings. Each choice once. |
| `value` | `string` | None | The selected choice. It must be one of `options` unless `editable` is set. |
| `editable` | `boolean` | `false` | Lets the user type a value that is not in `options`. |

## Make a radio group

Radios with the same `name` are one field, a radio group. The user can turn on
one option of the group; the reader exports the `value` of that option. Put
each option where it belongs in the layout, with its visible label next to it:

```vue [pdfs/sign-up.vue (excerpt)]
<PdfText>Shirt size</PdfText>
<PdfView :style="{ flexDirection: 'row' }">
  <PdfView v-for="size in ['S', 'M', 'L']" :key="size" :style="{ flexDirection: 'row', marginRight: 12 }">
    <PdfRadio name="shirt" :value="size" :label="`Shirt size ${size}`" :checked="size === 'M'" :style="{ width: 10, height: 10, borderWidth: 0.75, borderColor: '#9fb0b5' }" />
    <PdfText :style="{ marginLeft: 4 }">{{ size }}</PdfText>
  </PdfView>
</PdfView>
```

- `value` is unique in the group, and at most one option is `checked`.
  Without a `checked` option, no option is on and the group's value is `Off`.
- `readOnly` and `required` belong to the group: set them on every option or
  on none.
- `label` is per option. Give each option a label that a screen reader can
  read alone, such as "Shirt size M".
- The options of a group can be on different pages.
- Once the user turns an option on, the reader keeps one option on. Clicking
  the option that is on does not turn it off.

## Style a field

The field style takes the box styles that every element takes (`width`,
`height`, margins, `position`) and these styles for the look of the field:

| Style | Default | Description |
| ----- | ------- | ----------- |
| `fontSize` | `10pt` | The size of the value. |
| `color` | `black` | The color of the value, of the checkbox cross and of the radio dot. |
| `textAlign` | `left` | `left`, `center` or `right`. A `justify` from the parent is drawn as `left`. |
| `padding` | `2pt` | The space between the border and the value, cross or dot. |
| `borderWidth`, `borderColor` | None | A square, solid border, drawn inside the box. Each side can have its own width and color. |
| `backgroundColor` | None | Fills the box behind the value. |

A radio is round: its background is a disc and its border a ring, as large as
the smaller side of the box, with the width and color of the top border. The
dot fills the space inside the border and padding.

`fontSize`, `color` and `textAlign` come from the parent when the field does
not set them, as they do for `PdfText`. In the example above, the fields take
`fontSize: 10` from the page.

A single-line value is centered vertically in the box. A `multiline` value
starts at the top and breaks at the box width and at its own line breaks. A
value that does not fit is cut off at the padding: Nuxt PDF does not make the
text smaller, and a long value is not an error.

## What the reader does

The value is drawn in Helvetica, a font that every PDF reader has, so the file
does not embed a font for the fields. When the user changes a value, the reader
draws the new value itself, in Helvetica at the field's `fontSize`.

- **Field text uses WinAnsi characters only.** Helvetica in a PDF reader has
  the Western European characters (Latin-1 and a few more, such as `€` and
  `–`). A `value` or an option with another character, such as `→` or `大`,
  fails with `PDF_TREE_INVALID`. The page text around the field can use any
  registered font.
- **The letter shapes come from the reader.** A reader that has no Helvetica
  uses a font with the same widths, such as Arial or Liberation Sans.

In a PDF/A or PDF/UA-1 document, a field draws its value in its own font
instead: the registered font of its `fontFamily` (or of its page), embedded
whole, so that the reader also draws a typed value in that font. See
[Embed the field font](#embed-the-field-font).

## Embed the field font

A document with `conformance="PDF/A-3b"` can have fields of every kind. PDF/A
needs every font embedded, also the font a reader uses when the user types a
new value. PDF/UA-1 needs the same, so these steps apply to every
`conformance` level:

1. Register a TrueType font (a `.ttf` file, or a WOFF2 file with TrueType
   outlines) in `pdf.fonts`.
2. Set `fontFamily` on the page, as for the text of a PDF/A document. A field
   takes the font of its page or parent view, or its own `fontFamily`.

Nuxt PDF embeds the whole font file once for the fields, not only the letters
of the values, so that the reader has every letter the user can type. A font
file of 170 KB makes the PDF about 90 KB larger, because Nuxt PDF compresses the
stream. The exact size depends on the font.

Each of these fails with `PDF_TREE_INVALID` and names the field:

- a field without a registered font (in Helvetica);
- a font with PostScript (CFF) outlines, such as most `.otf` files;
- a `value` or choice with a character that the font does not have.

Field text is still WinAnsi only. Checkboxes and radios draw no text and need
no font. A `PdfFacturX` invoice cannot have fields: the printed invoice must
match its XML.

## Accessible forms

In a tagged document (`conformance="PDF/UA-1"` or `"PDF/A-3a"`), each field is
a form element (`Form`) in the document structure. Assistive technology reads
the field's `label` as its name, and the Tab key moves from field to field in
template order:

- **Give every field a `label`.** A field without one fails with
  `PDF_TREE_INVALID`. Write what the visible text next to the field says, such
  as `label="Full name"`.
- **Give each radio option its own label**, which names the question and the
  option, such as `label="Plan: Basic"`. A radio group has no label of its
  own, so the label of each option carries the question.
- **Keep the visible label as a `PdfText`.** It is read as a paragraph before
  the field.
- **Register a font** for text fields and drop-down lists, as in
  [Embed the field font](#embed-the-field-font).

Each form element stands where its field is in the template, also when the
layout draws the field somewhere else, such as in a row with
`flexDirection: 'row-reverse'`. A field cannot be inside a `decorative` node or
a `PdfView tag="figure"`. See [Accessible PDF]($docs.accessible-pdf).

## Rules

A field is a box of fixed size that exists once:

- It needs `width` and `height` in its style.
- It never splits across pages. A field that does not fit moves to the next
  page whole.
- It cannot be inside `fixed` content (which repeats on every page), a node
  with `pages`, or `PdfSvg`.
- Two fields cannot have the same `name`. Only the radios of one group share
  a name; a radio and another field with the same name fail.

Each rule fails with `PDF_TREE_INVALID`. The message names the field or the
element that holds it.

## Limits

- **No fields in an e-invoice.** A document with `PdfFacturX` and a field
  fails with `PDF_TREE_INVALID`.
- **No list boxes, buttons or field groups yet.**
- **Square, solid borders only.** A field with `borderRadius`, a `borderStyle`
  other than `solid`, or its own `textAlign: justify` fails with
  `PDF_TREE_INVALID`. A radio is always round and ignores `borderRadius`.
- **No form scripts or submit actions.** A field does not format or check what
  the user types, other than `maxLength`.
- **No automatic font size.** A long value is clipped at the field box, never
  made smaller.
- **Western European text only.** Field values and choices use WinAnsi
  characters, also in PDF/A.
- **Helvetica without a conformance level.** The font is not embedded, and the
  reader uses its own Helvetica-compatible font. With a conformance level the
  field uses your registered font (see [Embed the field font](#embed-the-field-font)).
- **No name for a whole radio group.** Each option has its own `label`.
- **Tested with pdf.js.** pdf.js is the only reader that fills a field in the
  tests. Acrobat, PDFium and Preview are not checked.

With [password protection]($docs.protection), `allow.fillingForms` and
`allow.annotating` decide whether a user who opened the PDF with the open
password may fill the fields.

## Test a form

Read the fields with pdf.js in a test. `getAnnotations()` returns each field
with its `fieldName`, `fieldValue` and flags:

```ts [test/sign-up.test.ts]
import { expect, it } from 'vitest'
import { getDocument } from 'pdfjs-dist/legacy/build/pdf.mjs'
import { renderPdfSfc } from '@lupinum/nuxt-pdf/test'

it('writes the sign-up fields', async () => {
  const { bytes } = await renderPdfSfc('./pdfs/sign-up.vue', {})
  const document = await getDocument({ data: bytes.slice() }).promise
  const annotations = await (await document.getPage(1)).getAnnotations()
  const fields = annotations.filter(annotation => annotation.subtype === 'Widget')

  expect(fields.map(field => field.fieldName)).toEqual(['fullName', 'shift', 'newsletter'])
})
```

`getDocument` takes over the buffer it gets and leaves `bytes` empty. Pass `bytes.slice()`
when the test uses `bytes` again, for example for `rasterizePdf` or a search in the raw file.
