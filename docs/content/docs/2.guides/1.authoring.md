A PDF template is an ordinary Vue Single File Component under `pdfs/`. You get
typed props, interpolation, `v-if`, keyed `v-for`, slots, and local components.
What differs from a page component is the element set and the styling model.

## The directory

Templates live in `pdfs/**/*.vue`. Three sibling directories are reserved and
are **not** registered as documents:

| Directory | Purpose |
| --------- | ------- |
| `pdfs/components` | Local `.vue` components used by templates |
| `pdfs/assets` | Local PNG/JPEG images (see [Images & fonts]($docs/guides/images-and-fonts)) |
| `pdfs/fonts` | Local TTF/OTF fonts |

Discovery is deterministic. Nested paths become dotted registry keys, and a
project template overrides a same-keyed template from an extended layer.

## The primitives

The document primitives are thin, auto-registered global components:

| Component | Role |
| --------- | ---- |
| `PdfDocument` | Root; carries document metadata and outline mode |
| `PdfPage` | A page with a size, orientation, and padding |
| `PdfView` | A flexbox container (the layout workhorse) |
| `PdfText` | A text run; the only place text may live |
| `PdfImage` | A raster image from a local or embedded source |
| `PdfLink` | An external URL or internal `#id` link annotation |
| `PdfNote` | A sticky-note annotation |

There is also a [full SVG primitive set]($docs/guides/svg-graphics) for vector
drawing. Every primitive's props are tabulated in the
[reference]($docs/reference/primitives).

::callout{icon="lucide:info"}
Text must live inside a `PdfText`. Loose text placed directly under a `PdfView`
or `PdfPage` is excluded from the document tree rather than silently rendered.
::

## Styles are React PDF objects, not CSS

The `:style` prop takes a **React PDF style object**, not browser CSS. It is a
familiar subset — flexbox, box model, colours, transforms — but it is its own
system:

```vue
<PdfView
  :style="{
    flexDirection: 'row',
    justifyContent: 'space-between',
    alignItems: 'center',
    padding: 12,
    backgroundColor: '#f4f6f4',
    borderRadius: 4,
  }"
>
  <PdfText>Invoice total</PdfText>
</PdfView>
```

Key differences from CSS:

- Properties are camelCase (`backgroundColor`, `marginTop`), never kebab-case.
- The default flex direction is `column`, as in React Native — not `row`.
- Values are unitless points by default; percentages are strings (`'50%'`).
- There is no cascade from a global stylesheet. Inheritance flows through the
  component tree for the properties the engine inherits (font family, size,
  colour), and you set everything else explicitly.

`:style` also accepts an array; falsy entries (`false`, `null`, `undefined`) are
filtered and the rest are merged left-to-right:

```vue
<PdfText :style="[base, isTotal && { fontWeight: 700 }]">
  {{ amount }}
</PdfText>
```

## Composition is ordinary Vue

Break a document into components exactly as you would a page. Put shared pieces
in `pdfs/components`:

```vue [pdfs/components/InvoiceLine.vue]
<script setup lang="ts">
defineProps<{ label: string; amount: string }>()
</script>

<template>
  <PdfView :style="{ flexDirection: 'row', justifyContent: 'space-between', marginBottom: 4 }">
    <PdfText>{{ label }}</PdfText>
    <PdfText>{{ amount }}</PdfText>
  </PdfView>
</template>
```

```vue [pdfs/invoice.vue]
<PdfView>
  <InvoiceLine
    v-for="line in invoice.lines"
    :key="line.id"
    :label="line.label"
    :amount="line.amount"
  />
</PdfView>
```

`v-if`, keyed `v-for`, and slots all work. Invalid primitive nesting (for
example a `PdfPage` inside a `PdfText`) and DOM-only attributes (`class`,
`data-*`, `aria-*`) fail early with a targeted diagnostic naming the template.

## Dynamic text

Some content is only known during pagination — most commonly the page number. A
`PdfText` with a `render` function receives per-page context and returns a
string or number:

```vue
<PdfText
  fixed
  :render="({ pageNumber, totalPages }) => `Page ${pageNumber} of ${totalPages}`"
/>
```

`render` callbacks are **synchronous** and must return a scalar. They run during
layout, once per page the node appears on. Pair `render` with `fixed` to repeat
the node on every page.

::callout{icon="lucide:triangle-alert"}
Dynamic text renders with the font's default line spacing; an inherited or
explicit `lineHeight` multiplier is intentionally not applied to it. Apply
`lineHeight` directly to static `PdfText` nodes. This is a deliberate divergence
from upstream React PDF — see [Conformance]($docs/conformance).
::

## definePdf

Each template calls `definePdf` once to declare metadata and preview data:

```ts
definePdf<Props>({
  title: props => `Report ${props.id}`,
  filename: props => `report-${props.id}.pdf`,
  language: 'en-GB',
  sampleData: { id: 'sample' },
  scenarios: {
    long: { id: 'long-report' },
  },
})
```

`title` and `filename` are a static string or a function of props. `sampleData`
drives the default preview; each entry in `scenarios` becomes a preview tab and
a `?scenario=` query. Full option semantics are in the
[definePdf reference]($docs/reference/define-pdf).
