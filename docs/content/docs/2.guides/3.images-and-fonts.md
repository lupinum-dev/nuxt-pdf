Images and fonts are resolved and embedded during the Nuxt build from explicit
local roots. Remote fetching is off by default and, when enabled, is gated by an
operator-owned allowlist. This is a fail-closed resource boundary, not a general
filesystem or network sandbox.

## Local images

Put PNG or JPEG files in `pdfs/assets` and reference the path **relative to that
directory**:

```vue
<PdfImage
  src="brand/logo.png"
  :style="{ height: 40, objectFit: 'contain', width: 120 }"
/>
```

## Local fonts

Put TTF or OTF files in `pdfs/fonts` and register each face in `nuxt.config.ts`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ["@lupinum/nuxt-pdf"],
  pdf: {
    fonts: [{
      family: "Invoice Sans",
      src: "InvoiceSans-Regular.ttf",
      fontWeight: 400,
      fontStyle: "normal",
    }],
  },
});
```

Then use the family in a style object. Font inheritance flows through the tree,
so setting it on the page covers the document:

```vue
<PdfPage :style="{ fontFamily: 'Invoice Sans' }">
  <PdfText>Invoice</PdfText>
</PdfPage>
```

Register one entry per weight/style you use; `fontWeight` accepts a number or a
named weight (`"bold"`, `"medium"`, …). See the
[module options reference]($docs/reference/module-options) for the full font
declaration.

## The validation boundary

Every configured resource is checked at build time. Resources are:

- **extension- and signature-checked** — PNG/JPEG for images, TTF/OTF for fonts;
  a wrong signature is rejected regardless of file extension;
- **size-checked** — 10 MB for images, 5 MB for fonts;
- **realpath-contained** — resolved paths must stay inside the declared root; and
- **embedded into the server build** — the bytes travel in the build, so there is
  no runtime filesystem read.

Absolute paths, `..` traversal, symlink escapes, missing files, ambiguous
sources, and unsupported URL schemes are all rejected. There is no runtime
filesystem fallback.

## Opt-in remote resources

Remote images and fonts are **unsupported until you configure an allowlist**.
With `pdf.remote` absent the module performs zero network I/O and every URL
source fails closed.

When an operator sets `pdf.remote.allow`, the module itself — never React PDF's
engine — fetches allowlisted resources and converts them to the same embedded
form as local assets before layout or the font store ever sees a URL:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ["@lupinum/nuxt-pdf"],
  pdf: {
    remote: {
      allow: [
        "https://cdn.example.com/brand/",
        "https://*.assets.example.com/logos/",
      ],
      // Optional overrides (defaults shown):
      // maxImageBytes: 10_485_760,
      // maxFontBytes: 5_242_880,
      // timeoutMs: 10_000,
    },
  },
});
```

### The security posture

The allowlist is the operator's trust decision, and the fetch path is
deliberately narrow:

- **`https://` only.** `http://`, embedded credentials, and non-matching hosts,
  ports, or path prefixes are blocked.
- **Explicit entries.** Each entry is a host (or a single leading `*.` subdomain
  wildcard on a registrable domain) plus a pathname prefix. Prefixes match only
  on path-segment boundaries, so `/logos` admits `/logos/x.png` but never
  `/logos-private/x.png`. Wildcards on common public suffixes (`*.github.io`,
  `*.vercel.app`, …) are rejected at setup.
- **Redirects re-checked per hop.** Redirects are followed manually (bounded to
  five) and the allowlist is re-checked on every hop, so an allowlisted host
  cannot redirect out of the allowlist.
- **Byte caps enforced while streaming.** Caps reuse the local 10 MB image / 5 MB
  font limits, enforced from `Content-Length` and while reading the body; the
  stream aborts the moment a cap is exceeded.
- **Signature is authoritative.** A deceptive `Content-Type` cannot make
  non-image or non-font bytes validate.
- **No credentials, no headers.** Fetches are `GET` only, send no request
  headers, and carry no cookies or credentials, under a per-hop timeout.

Remote images resolve at render time (deduplicated per render, no cross-render
cache); remote fonts resolve at build time and embed as the same
`data:font/...` URL as local fonts, keeping the render path zero-network.

::callout{icon="lucide:shield-alert"}
Not claimed: authenticated fetches, request headers or bodies, proxies, and
private-IP or DNS-rebinding protection beyond the allowlist. The allowlist
scopes *which hosts and paths* may be fetched — it is not an SSRF sandbox.
::
